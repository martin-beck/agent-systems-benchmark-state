# AR-1674 — Project-Persisted Channel Resolution for Every ASB Command

Extend the versioned ASB project configuration so `asb project init` always
writes `channel = "dev"` for a new project. A channel-less compatible legacy
project resolves to `dev` and is migrated or rewritten only through the
project-config compatibility path. A malformed, unknown, or unavailable
configured channel is a typed diagnostic; it must never silently become `dev`.

Implement one shared project-channel resolver and provide its resolved value to
every executable public ASB command and subcommand, including project/config,
catalog and discovery, provider/agent/model, tool/workload, plan/run/sweep,
report/compare, record/replay, easy, control/serve, and TUI lifecycle and
launch commands. An explicit `--channel` is an invocation-only override unless
the user explicitly changes project configuration. Commands which currently do
not use channel behavior must still accept the resolved context so later
features cannot bypass the contract. Help, version, and shell completion must
remain usable without a project and must not create or rewrite configuration.

Human-default and explicit `--json` output must expose the resolved channel
where it informs an operation or diagnostic. Acceptance requires focused unit,
subprocess, and command-surface coverage for fresh init, legacy compatibility,
every command-family handoff, explicit override, persistence across a fresh
process, and unavailable channels. Development-only authentication, signature,
and key-management warnings remain non-blocking for `dev`.
