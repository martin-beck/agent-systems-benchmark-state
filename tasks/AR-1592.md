The released asb-tui bootstrap requests typed BenchmarkCatalog and
MeasurementCatalog responses. The current ASB backend has neither call, so a
real inherited-fd launch exits after Capabilities. This AR owns the ASB-side
protocol/schema/backend implementation; it must not replace the cross-project
qualification owned by AR-1590.

Development mode may use generated local catalog data and must remain usable
without provider authentication, signatures, or key management. Stable and
production paths retain their existing fail-closed validation.

Acceptance requires version negotiation/downgrade behavior, typed validation,
deterministic catalog identity/revision evidence, backend responses, negative
compatibility tests, an exact signed/DCO PR, independent review, and all
required hosted checks.
