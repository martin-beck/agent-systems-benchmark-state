## AR-1521

Implement the separately reviewed successor chosen by AR-1529 for the terminal
AR-1308 full-exhaustive capacity failure. This is an implementation repair for
the 1307/1308 path, not permission to reinterpret a diagnostic run as formal
qualification.

- Preserve AR-1307's reviewed 3G memory, 3G swap, two-worker, two-core, 8G
  address-space and 7200-second contract. Any larger disposable capacity must
  be a distinct named profile with explicit claims.
- Bind the exact AR-1307 source, runner, TLC/JDK, model/config and profile
  digests. Development may use generated unsigned seeds, but formal evidence
  must continue to use the existing signed/profile gates.
- Repair the concrete failure selected by AR-1529 (capacity implementation or
  deterministic model reduction) with no weakening of admission, isolation,
  timeout, cancellation, cleanup, privacy or attestation validation.
- Add positive and negative tests for OOM, timeout, disk exhaustion, stale or
  mismatched inputs, concurrent admission, cleanup failure and profile/claim
  confusion. Unknown profiles and missing terminal evidence fail closed.
- Run focused and full gates, exact-head hosted CI and independent review. Do
  not claim AR-1307 qualification until AR-1522 produces terminal evidence.

The reduced development profile from AR-1519/1520 remains available for local
development and is explicitly non-qualifying.
