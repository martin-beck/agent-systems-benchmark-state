# AR-1338: Guided ASB command wrapper

## Outcome

Provide a user-friendly, fail-closed `asb easy` wrapper that discovers the
authoritative supported agent/provider/model catalog, lets the user choose only
advertised compatible values, computes catalog and credential-reference digests,
generates bounded private selection/experiment files, and dispatches the normal
ASB commands without requiring users to copy hashes or long arguments.

The wrapper must expose setup, plan, run, sweep, report, compare, record and
replay journeys while preserving the underlying ASB command contracts. It must
never invent an agent, provider, model, workload, path or credential source.

## Dependencies and ownership

Dependencies: AR-1442 (ASB CLI setup), AR-1443 (guided capture/replay/
comparison), and AR-1446 (first-customer local qualification). Optional live
provider capture and the separate asb-tui integration are not prerequisites.
Repository: `martin-beck/agent-systems-benchmark`.
Owned paths: the wrapper entry point, generated private working files, wrapper
tests, and user-facing command documentation. Do not duplicate provider or
credential policy; call the authoritative ASB commands and schemas.

## Requirements

1. Discover supported values from `asb provider-catalog` and reject unknown,
   unavailable, duplicate, or cross-provider selections before side effects.
2. Offer an interactive and noninteractive mode with clear prompts, `--help`,
   `--yes`/dry-run confirmation, bounded absolute output roots, and deterministic
   private temporary/configuration files.
3. Compute catalog, selection, provider-profile, workload and credential-reference
   digests by invoking ASB or its versioned libraries; users must not copy them.
4. Reuse persisted setup/configuration where available and resolve secrets only
   through the enrolled credential boundary; never place secret bytes in argv,
   generated files, logs or reports.
5. Support one shared provider selection for several agents while making clear
   that ordinary experiment runs are one agent per manifest; use the campaign
   command for a multi-agent workload matrix.
6. Add offline tests and hostile validation for invalid choices, stale catalogs,
   path traversal/symlinks, secret leakage, partial files, cancellation and
   command failures. Do not contact a live provider in CI.

## Acceptance criteria

From a clean install, a user can select only catalog-advertised agents,
providers and models and complete the deterministic local-mock setup-to-report
workflow with generated arguments/files, while every underlying ASB validation
and evidence boundary remains authoritative. The wrapper's docs and tests make
external live network/provider contact optional, explicitly gated, and
non-gating; no external reachability or free-model access is required for
completion.

## Current development and CI qualification boundary

The mandatory development and CI qualification path for this AR is a deterministic
local provider/LLM mock (LiteLLM-compatible where practical), including hostile
negative tests and offline replay where applicable. External/live OpenRouter or
other provider reachability is optional supplementary evidence only; it is never a
completion, dependency-readiness, or CI gate. Production egress policy, credential
non-disclosure, runtime-owned authority, namespace/relay attestation, cancellation
and teardown, and fail-closed denial of unapproved external traffic remain required
contracts. Existing live-provider dependency edges describe production integration
ordering only and must not be used to block local qualification or to claim external
reachability.
