# AR-0004: Generate the visual AR status document

## Outcome

Generate a checked-in `STATUS.md` from all task front matter so users can quickly understand the
entire AR portfolio, current status, ownership, next actions, and dependency structure. Present a
visually clear Mermaid dependency graph plus an adjacent accessible textual representation; the
document must remain useful without client-side JavaScript or external assets.

## Dependencies and ownership

Dependencies: AR-0002.
Owned state-repository paths: `STATUS.md`, the status renderer and its tests, focused
`handoffctl` integration, state verification workflow changes, and README links/documentation.
Branch: `feature/ar-status-document`. State worktree:
`agent-systems-benchmark-state-ar-status-document` under `/srv/data/projects`.
One worker owns this task. Changes to task schema, lock/transaction code, generated views, or CI
must be reviewed for compatibility with concurrent coordination mutations.

## Work sequence

1. Define a deterministic view model derived only from validated task front matter.
2. Render status counts, a status-grouped AR inventory, a legend, and a directed Mermaid graph in
   which each dependency edge points from prerequisite to dependent.
3. Regenerate `STATUS.md` automatically inside the same locked transaction used for material AR
   mutations, including claim, update, release/finish, task creation or promotion, and reconcile.
   Heartbeats and recorded commands may avoid document churn when no rendered field changes.
4. Add an explicit render/check command and CI stale-output gate, then exercise real mutation,
   rollback, race, and malformed-graph failure paths.
5. Publish a focused state-repository PR only after exact-tree tests, coverage, signature/DCO,
   privacy, Gitleaks, scope, and documentation review pass.

## Acceptance criteria

- Every non-private AR appears exactly once in the inventory and once as a graph node, with a
  working task link, status, priority, owner or unclaimed marker, summary, and next action.
- Every declared dependency appears exactly once as a correctly directed graph edge. Missing
  nodes, duplicate IDs/edges, self-dependencies, and cycles fail closed with useful diagnostics.
- Statuses have a consistent accessible legend, human-readable labels, and distinct Mermaid
  styling; summary counts and grouped tables agree mechanically with task front matter.
- Markdown and Mermaid labels are safely escaped. Long text, unusual punctuation, and hostile
  fixture strings cannot corrupt the document or inject directives/links.
- Output is byte-deterministic, has no wall-clock churn, embeds no secrets/private paths/raw
  coordination history, and requires no network access, JavaScript, or external visual service.
- `handoffctl` claim, update, release/finish, and reconcile paths atomically refresh the document
  before their signed state commit. Injected write/commit/push failures never leave task files,
  `CURRENT.md`, and `STATUS.md` mutually inconsistent.
- Unit, integration, concurrent mutation, negative, snapshot, and stale-generated-file tests cover
  the renderer and automatic hooks with at least 95 percent branch-aware coverage for changed
  coordination modules.

## Evidence and completion

Record exact commands, immutable state commit/PR head, CI runs, coverage, independent review, and
post-merge live doctor/state validation. Completion requires a clean synchronized state repository,
automatic regeneration demonstrated for a real claim and finish transition, and an honest browser
rendering review of the checked-in Markdown/Mermaid document. The generated page is a coordination
view, not evidence that an ARs product acceptance criteria passed.
