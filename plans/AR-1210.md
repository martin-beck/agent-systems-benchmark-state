# AR-1210: Tutorial contract and syntax validator

## Outcome

Define a machine-readable tutorial-step contract and an offline validator for ASB tutorials.
Tutorial steps must be checked against the current CLI command grammar, option names, required
ordering, file/configuration references, and expected output shapes without executing ASB, starting a
provider, contacting an LLM, or using credentials.

## Ownership and boundaries

Own the ASB tutorial schema, parser, validator, canonical fixtures, and CI entrypoint. Keep
workflow prose in the tutorial ARs. The validator must be reusable by the standalone asb-tui
repository through a versioned contract or equivalent checked-in fixture; it must not import
private paths or require a live ASB installation.

## Acceptance

- malformed, stale, unknown, reordered, incomplete, secret-bearing, and network-bearing steps fail
  closed;
- valid steps are checked against generated/current ASB command metadata;
- CI proves syntax and references only and never runs tutorial commands;
- diagnostics identify tutorial and step IDs without printing credentials or raw prompts.

## Evidence

Record the schema version, validator tests, negative fixtures, CI job, and exact command metadata
identity. Add a mutation test proving removal or renaming of a CLI option fails CI.
