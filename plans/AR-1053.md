# AR-1053: Harden the standalone asb-tui delivery roadmap

## Outcome

Turn the audited standalone TUI feature set into a dependency-executable, non-overlapping roadmap
that objectively covers landing, configuration, measurement search and selection, recent reports
and comparison, professional responsive visuals, contextual hotkeys, navigation and complete action
help.

## Scope and ownership

Repository: `martin-beck/agent-systems-benchmark-state` only. Owned paths are the task and plan
records for AR-1010, AR-1011, AR-1014, AR-1025 and AR-1031 through AR-1035, plus generated state
views and this AR's own records. No path in `martin-beck/agent-systems-benchmark` or
`martin-beck/asb-tui` may change. No feature AR may be claimed, promoted, completed or otherwise
moved to a terminal status by this documentation-only task.

Branch: `docs/asb-tui-roadmap-hardening`. Worktree:
`agent-systems-benchmark-state-asb-tui-roadmap-hardening`.

## Work sequence

1. Correct AR-1010's stale publication action and make the active AR-1052 trusted-main recovery an
   explicit dependency without introducing a reverse edge or cycle.
2. Narrow AR-1025 to the functional standalone shell, authenticated control client, authoritative
   state projection, routing, terminal lifecycle and extension seams. Reserve final screen,
   contextual-help and professional visual implementation for their focused downstream ARs.
3. Expand AR-1014 into a complete measurement-selection specification with exact catalog bounds,
   group and filtered-toggle semantics, mandatory evidence separation, stale-digest behavior and
   canonical AR-1037 plan round trips.
4. Add objective route, recency, visual-conformance, configuration-search, report-ordering,
   comparison-cardinality and cross-screen focus/navigation acceptance to AR-1031 through AR-1035
   and AR-1011.
5. Regenerate all derived views, validate the complete dependency graph, reconcile live state and
   inspect the exact diff for private identifiers, host details, credentials, raw logs and any
   accidental product ownership.

## Dependency and ownership invariants

The intended feature order after AR-1010 and ASB AR-1037 complete is AR-1025, then AR-1033, then
AR-1014/AR-1031/AR-1035 in parallel, then AR-1034, AR-1032 and finally AR-1011. AR-1052 may gate
AR-1010, but no recovery task may depend on AR-1010 in a way that creates a cycle. Legacy ASB TUI
ARs are read-only behavior inputs only. Every application screen, widget, renderer, interaction,
preference store and terminal UI test remains exclusively owned by `martin-beck/asb-tui`.

## Acceptance and evidence

- Every referenced task and plan exists, has consistent dependencies and ownership, and retains its
  pre-existing nonterminal status.
- The dependency graph is acyclic and the documented topological sequence agrees with the task
  metadata.
- AR-1025 can complete without implementing downstream professional visuals or final feature
  screens; downstream ARs can consume its stable shell without reopening it.
- Each requested UX capability has exact acceptance and deterministic test obligations, including
  bounded malformed, stale, reordered, resize, keyboard-only, accessibility and privacy cases.
- `handoffctl render-status --check`, reconciliation and `handoffctl doctor --live` pass from a clean
  state tree.
- The final diff changes state documentation and generated views only, is privacy-safe, and is
  independently reviewable before this AR is released done.
