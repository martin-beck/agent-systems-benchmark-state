# AR-1010: Adopt Ratatui/Crossterm TUI foundation

## Outcome

Make the existing standalone `martin-beck/asb-tui` repository a real, maintainable terminal
application using pinned Ratatui and Crossterm while keeping ASB control, runner, protocol, and
benchmark state outside the renderer.

## Dependencies and ownership

Dependencies: AR-0803, AR-0804, AR-0805, AR-0806, AR-1030, AR-1052, AR-1054, AR-1056, AR-1058 and AR-1060. AR-1030 owns the explicit
supply-chain decision required before Ratatui can enter the standalone repository. AR-1052 owns the
narrow tmux peer-authority change already merged after the foundation; AR-1054 owns the subsequent
AF_UNIX connection-completion recovery proven necessary by exact-main Trusted main run 34562090773;
AR-1056 proved server acquisition succeeds; AR-1058 localized the remaining failures to concurrent
live tmux fixture execution; AR-1060 owns that scheduling-isolation recovery.
None of the recovery tasks has a reverse dependency on AR-1010, so the graph remains acyclic.
Repository: `martin-beck/asb-tui` only. Owned paths: its Cargo manifests, terminal lifecycle, event
loop, renderer shell, application state, and TUI unit/snapshot fixtures. The old
`agent-systems-benchmark/crates/asb-tui` candidate is read-only migration input and is not an owned
implementation path.
Branch: feature/ratatui-crossterm-foundation. Worktree: agent-systems-benchmark-asb-tui-ratatui-foundation.

## Work sequence

1. Pin the Ratatui release and matching Crossterm version approved for the standalone `asb-tui`
   crate; inspect licenses and lockfile changes and resolve the recorded dependency-policy blocker
   without weakening policy.
2. Build a single-writer application shell with Action messages, deterministic AppState updates, and a pure state-to-frame renderer.
3. Implement safe raw-mode/alternate-screen setup and restoration, panic/error cleanup, resize handling, Ctrl-C, SSH/tmux/screen fallbacks, and NO_COLOR behavior.
4. Define the typed single-writer injection seam and deterministic projection for already-
   negotiated ASB control events without modifying the ASB repository or moving runner ownership or
   benchmark work into the UI process. AR-1025 exclusively owns the live control-wire client,
   negotiation, asynchronous polling and responsive integration; this foundation must not duplicate
   them.
5. Add TestBackend frame tests, terminal lifecycle tests, and plain-text rendering equivalents before adding visual polish.

## Acceptance criteria

The standalone TUI launches into a real Ratatui screen, deterministically projects injected typed
control actions, restores the terminal on every tested exit path, renders a useful compact/plain
fallback, and cannot alter benchmark results or bypass explicit confirmation. AR-1025 must prove
responsiveness while real control operations run. No second incompatible Crossterm version is
introduced.

## Evidence

Record exact dependency versions, lockfile/license audit, immutable commit, unit and snapshot results,
terminal restoration probes, native supported-Linux and available local tmux/GNU screen checks,
deterministic SSH-channel policy tests, independent review, exact-head CI and post-merge verification.
Actual cross-host SSH, supported-platform matrices and any future Windows support belong to AR-0807
and AR-1012; the current release contract is Linux-only and this AR must not imply otherwise.
The foundation is not complete until AR-1052 preserves authenticated cleanup authority and both
exact-main Repository quality and Trusted main verification pass.
