# AR-1289: Repair formal lock gate

## Outcome

Restore the exact hosted formal-model gate by updating the pinned `formal/Cargo.lock` and any
required provenance/quality fixture so `cargo test --locked --manifest-path formal/Cargo.toml`
passes on a clean protected-main checkout and all PR merge refs.

## Scope

ASB formal workspace and its lock/provenance evidence only; no asb-tui or certificate feature
changes. Preserve offline-after-install, pinned dependencies, signed+DCO history, and native
formal policy. Diagnose whether the stale lock is caused by the current manifest/toolchain, then
make the smallest reproducible repair with positive and negative lock-consistency tests.

## Acceptance

- Exact protected-main and PR merge refs pass the hosted formal command with `--locked`.
- Lockfile, manifest, provenance, and generated documentation are consistent; no floating or
  runtime download is introduced.
- Focused formal tests, full applicable local gates, independent review, signed PR CI, protected
  merge, and exact-main post-merge formal verification are green.
- If the runner/toolchain itself is the cause, record exact evidence and create a narrower
  infrastructure successor rather than weakening the formal gate.
