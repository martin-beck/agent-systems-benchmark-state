## Outcome

After existing TUI workflow evidence and CLI stabilize, add discoverable TUI selection, preflight, progress, labels and diagnostics only for proven profiles.

## Dependencies and ownership

Depends on AR-0893, AR-0870 and AR-0873. Own new TUI view-model/state/navigation/tests and TUI docs/captures. Reuse shared provider/run contracts; do not fork CLI behavior or modify engines. Branch `feat/tui-local-llm-parity`; worktree `agent-systems-benchmark-tui-local-llm-parity`.

## Work sequence

1. Re-read shipped TUI navigation and AR-0870/0873 evidence; add no control without shared action/state and accessibility semantics.
2. Show only negotiated profiles/capabilities and evidence labels before launch/review; never show research candidates.
3. Reuse shared preflight for identity, model, network, resources, credentials and unsupported routes with privacy-safe errors.
4. Test keyboard focus/order, resize, cancellation, slow startup, stream progress, recovery, reopen, screen-reader text, double-launch and stale selection.
5. Execute deterministic TUI scenarios in CI and send real captures/text equivalents through AR-0873; no staged mock screens.

## Acceptance criteria

Actions map to tested contracts; only supported profiles appear; labels/provenance are visible; accessibility/lifecycle tests pass; no fallback/secrets; CLI/TUI produce equivalent run intents; and evidence is executed TUI output.

## Evidence and completion

Record state transitions, shared-intent parity, accessibility/resize/cancellation, real CI captures/text, privacy scan, full gates, immutable review, exact-head CI and post-merge verification.
