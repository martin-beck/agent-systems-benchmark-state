# AR-1345: Runtime live-provider coverage repair

## Outcome

Raise the workspace line-coverage result for the runtime live-provider
implementation to the mandatory 90% floor without exclusions, altered quality
policy, or fabricated live capabilities. Cover the real sandbox admission and
ownership transitions, relay timeout/error matrix, and provider-egress address
and authorization branches introduced by AR-1339 through AR-1344.

## Dependencies and ownership

Dependencies: AR-1339, AR-1340, and AR-1342. This is a coordinator-owned
coverage repair for the AR-1344 candidate and must not overlap its active
worktree. The worker owns runtime test fixtures and coverage-only test code;
it must not weaken `NetworkPolicy::Deny`, exclude files, change coverage floors,
or construct fake delegated capabilities that could overstate live execution.

## Required work

1. Generate an exact LLVM coverage report and classify misses in added or
   modified runtime code as reachable, capability-gated, or pre-existing.
2. Add bounded positive and negative tests for reachable sandbox admission,
   ownership/teardown, relay timeout/error, and provider-egress branches.
3. Keep capability-gated observations explicit and separate from successful
   live-provider evidence; do not turn ignored tests into proof of execution.
4. Run focused runtime tests, full workspace coverage, formatting, lint, and
   all applicable quality gates; publish only a clean signed+DCO exact head.

## Acceptance criteria

The hosted policy coverage gate reports at least 90% workspace lines with the
existing floor unchanged; all new tests are meaningful and privacy-safe; the
complete required CI matrix is green; and the AR-1344 candidate can be merged
without weakening native, formal, or live-provider boundaries.

## Current development and CI qualification boundary

The mandatory development and CI qualification path for this AR is a deterministic
local provider/LLM mock (LiteLLM-compatible where practical), including hostile
negative tests and offline replay where applicable. External/live OpenRouter or
other provider reachability is optional supplementary evidence only; it is never a
completion, dependency-readiness, or CI gate. Production egress policy, credential
non-disclosure, runtime-owned authority, namespace/relay attestation, cancellation
and teardown, and fail-closed denial of unapproved external traffic remain required
contracts. Existing live-provider dependency edges describe production integration
ordering only and must not be used to block local qualification or to claim external
reachability.
