# AR-0874: Automate workflow documentation refresh

## Outcome

Detect essential user-visible changes and deterministically regenerate or fail closed on stale workflow documentation, examples, and screenshots.

## Dependencies and ownership

Dependencies: AR-0873.
Owned paths: workflow dependency manifest, regeneration tool, drift checker, trusted update workflow, generated provenance, and automation tests.
Branch: `docs/automatic-workflow-refresh`. Worktree: `agent-systems-benchmark-automatic-workflow-refresh`.

## Work sequence

1. Define essential inputs: CLI/TUI help and navigation, schemas, catalogs, defaults, provider/agent/workload support, recording/replay contracts, output fields, installation, and release identity.
2. Map every generated page, command block, expected output, screenshot, alt text, and provenance record to its exact inputs and generating scenario.
3. On pull requests, rerun affected synthetic workflows and fail with a focused diff whenever checked-in documentation or captures are stale.
4. On trusted main, release, scheduled, and manual events, regenerate affected assets and open a reviewable update pull request; never push generated changes directly to protected main.
5. Pin tools/actions, minimize permissions, prevent fork secrets, deduplicate concurrent updates, sign or attest outputs, and test deleted/renamed inputs, partial failures, and no-op changes.

## Acceptance criteria

An essential behavior change cannot merge with stale affected workflows; successful trusted regeneration produces one reviewable, provenance-linked update; unrelated changes do not churn assets; failed or skipped runs never overwrite good evidence; and automation exposes no secrets or private data.

## Evidence and completion

Record dependency-graph fixtures, intentional drift failures, deterministic reruns, updater PR evidence, action/tool digests, permissions audit, immutable review, exact-head CI, and post-merge verification.
