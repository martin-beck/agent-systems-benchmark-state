# AR-1060: Add authenticated control endpoint handoff

## Outcome

Freeze and implement the non-UI framing boundary used to hand authenticated ASB control connections
to the separately launched frontend without exposing a raw Unix-socket path. AR-1060 returns a typed
authenticated generation and defines a private `SOCK_SEQPACKET` request/reply broker. AR-1024 owns
the long-lived router, safe child-stdin transfer and public launch command; AR-1025 owns descriptor
adoption, control negotiation, runner continuity and cursor resume.

## Dependencies and repository ownership

Dependencies: AR-1022 and AR-1023. AR-1022 supplies the standalone lifecycle/exec boundary and
AR-1023 supplies the authoritative versioned control service and peer-authentication contract.
AR-1024 and AR-1025 depend on this AR; this AR must not depend on either of them.

This coordinating AR has two strictly separated product halves:

- `martin-beck/agent-systems-benchmark`: private control/provisioning endpoint lease authority,
  bounded nonblocking role probe, service-created anonymous stream provisioning,
  `AuthenticatedGeneration` construction, closed broker framing and ASB-side hostile tests. AR-1024
  alone integrates the router side into the long-lived launch lifecycle. This repository
  owns no frontend, renderer, Ratatui, Crossterm, terminal event-loop, navigation, screen or widget.
- `martin-beck/asb-tui`: `SOCK_SEQPACKET` request/reply and descriptor adoption, strict ancillary
  validation, independent service-peer authentication and the injected post-adoption validator.
  AR-1025 exclusively owns control framing/decoding, `{1.0,1.2,1.3}` negotiation, runner-version
  continuity, authoritative cursor resume and all application behavior. Rendering and navigation
  remain owned by the standalone UI ARs.

Use isolated repository worktrees and separate signed+DCO commits, immutable reviews, pull requests
and protected-main evidence. Never combine both repositories into one Cargo workspace or add a path
dependency in either direction. Implement one repository half at a time when coordinator ownership
cannot safely represent both worktrees.

## ASB authenticated-generation contract

1. The ASB control service exclusively owns an owner-private control endpoint and a distinct
   owner-private `SOCK_SEQPACKET` provisioning endpoint under one retained lease. Only the AR-1024
   router resolves those paths. Neither endpoint, directory, inode nor encoded form crosses the
   router/frontend broker, environment, argv or public diagnostic boundary. Discovery and
   replacement acquisition remain serialized for the frontend lifetime.
2. The router opens a separate nonblocking control probe and keeps it open through anonymous-stream
   receipt and validation. One monotonic deadline bounds connect,
   readiness polling, `SO_ERROR`, kernel credentials, framing, negotiation and close. The probe must
   offer exactly `{1.0,1.2,1.3}`, require highest-exact selection, and establish a validated
   `runner_instance_id`. Current main must select 1.3; 1.2/1.0 are defined compatibility fallbacks;
   1.1, future, unoffered or shape-mismatched selection fails closed. Timeout, trickle, refusal,
   malformed response or ambiguous readiness also fails closed.
3. The router connects to the separate provisioning endpoint and requires its UID, positive PID and
   bounded `/proc/<pid>/stat` start time to match the successful control probe. Both ends authenticate
   `SO_PEERCRED`; the exact fixed request/reply protocol is accepted only over `SOCK_SEQPACKET`.
   These process values are short-lived comparison evidence only and are never used for later
   authority, liveness, lookup or signaling.
4. For each valid request the control service creates an anonymous `UnixStream::pair`, arms service-
   side cleanup, and registers one end with the normal bounded control-session worker before sending
   the other end to the router through exactly one `SCM_RIGHTS`. If registration or send fails, both
   ends close and the worker is bounded and joined. A router-created pair/proxy is forbidden because
   its peer credentials authenticate the router rather than the control service.
5. Before accepting that service-created end, the router requires `AF_UNIX`, `SOCK_STREAM`, not a
   listener, zero `SO_ERROR`, a bounded nonblocking peek, and both local and peer addresses to be
   unnamed. It independently requires service-creator credentials to match the probe/provisioning
   generation. A pathname-connected stream is never forwarded: on Linux its peer address reveals
   the raw server endpoint.
   After those checks the still-open probe executes one terminal non-mutating capabilities call,
   revalidates credentials/start time and runner identity under the original diminishing deadline,
   then closes. Failure closes the anonymous stream before broker publication.
6. The result is exactly `AuthenticatedGeneration { stream, broker_generation, kernel_peer,
   expected_runner_identity }` plus an injected post-adoption validator seam. The expected identity
   is SHA-256 over ASCII domain `asb-control-runner-instance-v1`, one zero byte, the exact validated
   UTF-8 byte length as `u16` big-endian, then the exact `runner_instance_id` UTF-8 bytes with no
   terminator or normalization. Length must fit the protocol identity bound before hashing. Golden
   input `runner-handoff-test` hashes to
   `9035cbae7ce01f88036f2b24b524268b91e2e2d3833e1607b29ce37a9e0cc872`. Credential fields have
   private construction and bounded read-only comparison access. AR-1025 negotiates the anonymous
   stream and must match the same independently computed digest before state advances. Validation
   failure closes the stream.
7. All owned descriptors are CLOEXEC from creation. AR-1060 never clears CLOEXEC, uses
   `/proc/self/fd` to reopen a socket, or maps an arbitrary fixed descriptor. AR-1024 passes the
   `SOCK_SEQPACKET` frontend broker as the exact child stdin with safe `Stdio::from(OwnedFd)` while
   lifecycle JSON remains on its own pipes and `asb-tui` opens validated `/dev/tty` for terminal I/O.
   An audited fd-mapping dependency requires a separate reviewed architecture decision.
8. Short connect, poll, credential, probe, provisioning request, pair creation, service-worker
   registration, broker send, spawn, exec,
   response, timeout and frontend-exit paths close all owned duplicates and reap only router-owned
   processes. Self-tests, downloaders, signature verifiers, shells and unrelated descendants never
   inherit the broker or service stream. The benchmark runner remains separately authoritative.

## Closed broker state machine

Use one private close-on-exec `SOCK_SEQPACKET` pair. Possession of the safely inherited child-stdin
endpoint is broker authority; socketpair `SO_PEERCRED` reports the creator and must not be presented
as child identity. Packets have fixed magic, exact protocol version, operation, flags, broker epoch
and sequence with a small compile-time maximum. The epoch is fresh per router/frontend lifetime;
sequence starts at one, increments only after one complete reply plus descriptor is sent, never
wraps, and is ordered lexicographically as `(epoch, sequence)` only within the same live broker.

The frontend sends exactly one `initial` request with no prior generation, then at most one
`replacement` request naming its last accepted generation after a closed service disconnect. The
router sends one seqpacket reply containing either a closed status without ancillary data or success
with exactly one `SCM_RIGHTS` descriptor. Duplicate initial, wrong epoch, stale/future/out-of-order
sequence, concurrent outstanding requests, unsolicited replies, retry storms and exhaustion fail
closed. One monotonic deadline and fixed attempt/rate ceilings bound every request, connect/probe and
reply; failed replies do not increment generation.

### Frozen v1 bytes

All integers are unsigned big-endian and every reserved byte must be zero. Broker request/reply
packets are exactly 72 bytes: magic `[u8;8] = "ASBHND01"`, version `u16 = 1`, operation `u8`
(`initial = 1`, `replacement = 2`), status `u8` (`request = 0`, `success = 1`,
`unavailable = 2`, `rejected = 3`, `exhausted = 4`), flags `u32 = 0`, epoch `[u8;16]`, sequence
`u64`, and expected-runner-identity SHA-256 `[u8;32]`. A request has status zero and an all-zero
identity digest. Initial request uses zero epoch/sequence; successful initial response establishes a
nonzero kernel-random epoch and sequence one. Replacement request repeats the last accepted tuple;
successful reply repeats the epoch and uses exactly sequence plus one. Failure replies carry the
current tuple, zero digest and no descriptor. One frontend lifetime permits one initial request and
at most eight replacements, with at least 100 ms between replacements and one 2,000 ms diminishing
deadline per acquisition. Packet excess, sequence overflow or limit exhaustion is terminal.

The private service provisioning packet is exactly 64 bytes: magic `[u8;8] = "ASBPRV01"`, version
`u16 = 1`, operation `u8` (`acquire = 1`), status `u8` (`request = 0`, `success = 1`,
`unavailable = 2`, `rejected = 3`), flags `u32 = 0`, request nonce `[u8;16]`, and
runner-identity SHA-256 `[u8;32]`. Request digest is zero; response repeats the nonzero random nonce,
contains the control-service runner digest and includes exactly one anonymous stream descriptor only
on success. A provisioning connection serves one request/reply and closes.

Check identical binary fixtures into both repositories and bind their SHA-256 values. Canonical
fixtures are: 72-byte zero initial request `e1dc9317afbc4bce748f0ce65424ad185c8a29e5ab40eb3e724d8930e77f216a`;
72-byte success with epoch bytes `00..0f`, sequence one and digest bytes `a0..bf`
`0936d182cde09230bcb3fd3f40c9f0aaa886e23fdb42ac68cfb1e098b8cf98f5`; 64-byte acquire request
with nonce `00..0f` `b3d2dc48c3c4afffbf2be9081974d72be4ed4ec3f737c51ad07af4aeab68ef4d`;
and its success with digest bytes `a0..bf`
`72c2bd598a591bf033db321e9e2acccea451a69ccabfc27498a9d8cdb2c032e5`.

The receiver uses `MSG_CMSG_CLOEXEC`, rejects payload or control truncation, unknown version/op/flag,
zero/multiple/extra messages or descriptors, and closes every rejected descriptor. Before credentials
or protocol bytes it proves the received object is `AF_UNIX`, `SOCK_STREAM`, connected, not a
listener, has unnamed local and peer addresses and zero `SO_ERROR`, then performs a bounded
nonblocking peek. Any pathname or abstract namespace address is rejected before credentials.
It independently obtains `SO_PEERCRED`, applies the post-adoption validator and negotiates the exact
control protocol. The standalone half adds its own pinned safe `rustix` net feature and never links
to ASB source.

Both repositories use pinned safe rustix 1.1.4 ancillary APIs. Because `RecvAncillaryBuffer` does not
surface unknown control-message kinds, every broker/provisioning socket is freshly created and code
must never enable `SO_PASSCRED`, `SO_PASSSEC`, `SO_TIMESTAMP`, `SO_TIMESTAMPNS`, `SO_TIMESTAMPING`
or another ancillary-producing socket option. Construction tests read back every platform-exposed
option as disabled, and the socket is never lent to untrusted code before receive. On the supported
Linux configuration, other ancillary messages are rejected by the kernel or not delivered unless
their corresponding receive option is enabled. Receive control space holds at least two descriptors
plus one `SCM_CREDENTIALS`: reject `MSG_CTRUNC`, every exposed non-`SCM_RIGHTS` message,
more than one rights message, or a rights message containing other than exactly one descriptor.
Hostile tests enable each available option or send credentials/one/two/multiple rights where safe
APIs permit, proving either the construction invariant fails before receive or the packet is rejected
with every delivered descriptor closed. Adding any ancillary-producing option or accepting a new
rustix control-message variant requires a contract revision and new golden negatives.

A replacement with the same `runner_instance_id` and negotiated version may resume once from its
last authoritative cursor. A changed runner identity must atomically discard the old cursor,
projection, outstanding request IDs and idempotency context, then start from the new runners
negotiated bounds and initial revision; no old revision is sent to the new runner. Any negotiated
version change requires a fresh decoder/session or trusted relaunch and can never continue old typed
state. No mutation is replayed automatically. Frontend or broker death requires trusted relaunch.

## Privacy and public failures

Environment and argv contain no control endpoint, descriptor number, PID, UID, token or secret.
The broker is child stdin, not an environment or argument convention. `env_clear` remains in force. Public JSON,
terminal output, errors, logs, telemetry and crash text use closed reason enums such as unavailable,
unauthenticated, disconnected and reconnect-required. Never echo raw endpoint/socket paths, tmux or
SSH socket text, `/proc` paths, ancillary bytes, environment values or kernel credentials.

## Adversarial evidence

- Scan child argv, environment, public response, diagnostics and logs with unique endpoint and
  secret markers; neither raw nor encoded markers may appear.
- Enumerate inherited descriptors in the lifecycle candidate, frontend, self-test, downloader,
  verifier and hostile descendant. Only the broker is transferred as child stdin; service streams
  arrive later through exact `SCM_RIGHTS`, and every unrelated descriptor remains CLOEXEC/closed.
- Inject failure before and after nonblocking connect/poll/`SO_ERROR`, credential read, role probe,
  provisioning accept/request, anonymous pair creation, service-worker registration, generation
  comparison, spawn,
  exec, broker send/receive, ancillary parse, frontend adoption and cleanup. Prove bounded completion,
  no descriptor/process/thread leak, unchanged installation and no runner/unrelated-process signal.
- Reject pipe, file, TCP, datagram, listener, unconnected, half-closed, wrong-UID, wrong-role,
  mismatched probe/transfer PID or start time, fd-substitution and concurrent-close cases. Prove no
  PID is used for signaling or post-adoption authority.
- Put unique secret markers in both private endpoint pathnames and assert router/frontend
  `getsockname`, `getpeername`, argv, environment, responses and diagnostics contain neither raw nor
  encoded markers. Require unnamed addresses on the forwarded service-created stream. A
  router-created anonymous proxy and any pathname-connected forwarded stream are negative fixtures.
- Reject zero/multiple/extra `SCM_RIGHTS` descriptors, unknown flags/version, credentials mixed with
  the wrong descriptor, truncation, oversized/trickle frames, replay, stale/reordered generations
  and reconnect storms. Close every rejected descriptor and retain a usable previous authoritative
  projection only when the protocol permits it.
- Mutate every frozen byte field, width, byte order, magic/version/op/status/flag value and reserved
  byte; cross-repository golden vectors and digests must match exactly. Exercise the fixed 2,000 ms,
  eight-replacement, 100 ms spacing and no-wrap limits without timing sleeps.
- Mutate the runner-identity domain, separator, length width/order, UTF-8 bytes, terminator and
  normalization; verify the exact golden digest above independently in both repositories. Exercise
  disabled ancillary socket options, exposed non-rights messages, split/multiple rights messages,
  one/two/many descriptors and `MSG_CTRUNC`, proving rejected descriptors close.
- Exercise ASB service restart, frontend detach/crash/upgrade, broker death and relaunch. Each accepted
  generation is independently authenticated, resumes once from the authoritative cursor and never
  duplicates launch/cancel. A runner PID/process-group sentinel must survive every frontend failure.
- Run repository-local unit/property/fault/coverage/privacy/supply-chain gates, cross-repository
  schema and fixture drift checks, supported Linux PTY integration, ASB-without-frontend isolation,
  independent immutable review, exact-head CI and protected-main post-merge verification for each
  repository half.

## Acceptance criteria

- The reusable AR-1060 framing returns only a typed authenticated generation and post-adoption
  validator seam; AR-1024/AR-1026 retain command and end-to-end launch acceptance.
- Broker transfer through child stdin and service transfer through exact `SCM_RIGHTS` are
  default-CLOEXEC, bounded and leak-free; no arbitrary fixed-FD adoption or CLOEXEC race exists.
- ASB compares probe, provisioning peer and anonymous service-creator credentials without treating
  PID as lasting authority; `asb-tui` independently requires unnamed addresses and binds the stream
  to the negotiated runner identity digest.
- Exact frozen packet layouts, constants, fixtures and digests match independently in both
  repositories; the probe offers exactly 1.0/1.2/1.3 and preserves role evidence through transfer.
- The router is the sole reconnect broker owner. AR-1025 alone owns same-runner/version continuity,
  changed-runner handling, cursor resume and no-mutation-replay behavior.
- ASB gains provisioning and transport-boundary code only. No frontend UI, renderer, Ratatui,
  Crossterm, terminal event-loop, navigation, screen or widget implementation enters ASB.
- AR-1024 and AR-1025 name this dependency but retain their current status/owner until their entire
  prerequisite sets are done.
