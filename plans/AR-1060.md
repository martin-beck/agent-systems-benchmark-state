# AR-1060: Add authenticated control endpoint handoff

## Outcome

Connect the optional standalone frontend to the authoritative ASB control service without exposing
or rediscovering a raw Unix-socket path. ASB provisions an authenticated connection or a narrowly
equivalent descriptor channel; `asb-tui` independently authenticates every connection it consumes.
The boundary survives service restart without giving the frontend endpoint-discovery authority and
never moves UI or benchmark-runner ownership across repositories.

## Dependencies and repository ownership

Dependencies: AR-1022 and AR-1023. AR-1022 supplies the standalone lifecycle/exec boundary and
AR-1023 supplies the authoritative versioned control service and peer-authentication contract.
AR-1024 and AR-1025 depend on this AR; this AR must not depend on either of them.

This coordinating AR has two strictly separated product halves:

- `martin-beck/agent-systems-benchmark`: endpoint discovery under ASB authority, Unix connection
  establishment, peer authentication, descriptor/broker provisioning, child-transfer ownership,
  restart/reconnect brokering and ASB-side conformance tests. This repository owns no frontend,
  renderer, Ratatui, Crossterm, terminal event-loop, navigation, screen or widget code.
- `martin-beck/asb-tui`: fixed transport acquisition, connection-shape validation, independent
  `SO_PEERCRED`/generation re-authentication, bounded framing, reconnect consumption and transport
  conformance tests. Application routes and visible behavior remain AR-1025-owned; rendering and
  navigation remain the standalone UI ARs' responsibility.

Use isolated repository worktrees and separate signed+DCO commits, immutable reviews, pull requests
and protected-main evidence. Never combine both repositories into one Cargo workspace or add a path
dependency in either direction. Implement one repository half at a time when coordinator ownership
cannot safely represent both worktrees.

## Closed transport contract

1. ASB resolves the configured control endpoint under its existing owner-safe authority, opens the
   Unix stream itself and authenticates the service before any frontend exec. Prefer transfer of an
   already-connected descriptor at one protocol-fixed child descriptor number when the architecture
   can prove an atomic, race-free CLOEXEC handoff. If that cannot be proved on the supported Linux
   baseline, select another descriptor-only authenticated mechanism and document the evidence; do
   not fall back to a raw endpoint path in argv or environment.
2. Every descriptor is close-on-exec by default. Clear CLOEXEC only for the exact intended transfer
   across the exact frontend exec, without exposing a multithreaded inheritance window; close or
   restore it immediately on every success, error and panic. Lifecycle self-tests, downloaders,
   signature verifiers, shell helpers and unrelated descendants must never inherit the channel.
3. Ownership is explicit at every transition: ASB owns the source connection until successful
   transfer; the frontend owns only its transferred duplicate; the broker owns only its private
   reconnect side. Short write, spawn, exec, response, timeout, malformed frame and frontend-exit
   paths close every owned duplicate and reap every owned process without signaling or mutating the
   separately authoritative benchmark runner.
4. `asb-tui` accepts only a connected `AF_UNIX` stream received through the fixed contract. Reject
   pipes, regular files, datagrams, TCP sockets, listeners, unconnected sockets, substituted or
   already-closed descriptors and unexpected ancillary descriptors before decoding control bytes.
5. Both sides obtain Linux `SO_PEERCRED`. Require the expected effective UID, a positive peer PID
   and the expected ASB service role. Bind PID identity to a connection-stable pidfd or checked
   `/proc/<pid>/stat` start time where later liveness/generation decisions use the PID. Fail closed
   on unreadable, ambiguous, exited or reused identity. Never publish UID, PID, descriptor number,
   process start time or endpoint text in user-facing diagnostics.
6. The frontend independently repeats connection-shape and peer checks for the initial service
   descriptor and every replacement. An ASB-side claim or previously accepted generation never
   substitutes for frontend authentication.

## Restart and reconnect

An inherited connected stream is single-generation and cannot safely rediscover the service after
a restart. Supply replacements through a private inherited Unix broker/socketpair owned by the ASB
router or service, using a versioned bounded message and exactly one `SCM_RIGHTS` descriptor per
accepted generation. The broker owns endpoint discovery and reconnection; `asb-tui` owns validation
and consumption. Reject missing, duplicate, extra, truncated, malformed, oversized, reordered or
stale-generation messages and close every received descriptor before returning a closed error.

The broker channel must itself use fixed descriptor transfer, default CLOEXEC, bounded reads/writes,
peer/ownership checks and frontend-lifetime cleanup. Frontend disconnect or upgrade closes the
channel. ASB service restart invalidates the old connection, yields at most one newly authenticated
generation and resumes from the runner's authoritative cursor without duplicate launch, cancel or
state mutation. If supported Linux cannot prove a private reconnect broker without an inheritance
race, fail closed on disconnect and require trusted relaunch rather than exposing a path; document
that narrower behavior and update AR-1025 acceptance before implementation review.

## Privacy and public failures

Environment and argv may contain only fixed protocol-presence/version sentinels whose literal values
cannot encode a caller path, endpoint, PID, UID, descriptor choice, token or secret. Prefer a
compiled fixed descriptor number with no variable at all. `env_clear` remains in force. Public JSON,
terminal output, errors, logs, telemetry and crash text use closed reason enums such as unavailable,
unauthenticated, disconnected and reconnect-required. Never echo raw endpoint/socket paths, tmux or
SSH socket text, `/proc` paths, ancillary bytes, environment values or kernel credentials.

## Adversarial evidence

- Scan child argv, environment, public response, diagnostics and logs with unique endpoint and
  secret markers; neither raw nor encoded markers may appear.
- Enumerate inherited descriptors in the lifecycle candidate, frontend, self-test, downloader,
  verifier and hostile descendant. Exactly the intended fixed channel is transferred, and only to
  the intended frontend exec; all other descriptors remain CLOEXEC/closed.
- Inject failure before and after connect, credential read, duplication, CLOEXEC transition, spawn,
  exec, broker send/receive, ancillary parse, frontend adoption and cleanup. Prove bounded completion,
  no descriptor/process/thread leak, unchanged installation and no runner/unrelated-process signal.
- Reject pipe, file, TCP, datagram, listener, unconnected, half-closed, wrong-UID, wrong-role,
  exited-PID, reused-PID/starttime, fd-substitution and concurrent-close cases. Use deterministic
  seams for PID-generation and descriptor-number reuse races.
- Reject zero/multiple/extra `SCM_RIGHTS` descriptors, unknown flags/version, credentials mixed with
  the wrong descriptor, truncation, oversized/trickle frames, replay, stale/reordered generations
  and reconnect storms. Close every rejected descriptor and retain a usable previous authoritative
  projection only when the protocol permits it.
- Exercise ASB service restart, frontend detach/crash/upgrade, broker death and relaunch. Each accepted
  generation is independently authenticated, resumes once from the authoritative cursor and never
  duplicates launch/cancel. A runner PID/process-group sentinel must survive every frontend failure.
- Run repository-local unit/property/fault/coverage/privacy/supply-chain gates, cross-repository
  schema and fixture drift checks, supported Linux PTY integration, ASB-without-frontend isolation,
  independent immutable review, exact-head CI and protected-main post-merge verification for each
  repository half.

## Acceptance criteria

- `asb tui launch` can provision a usable authenticated control channel without a socket path,
  endpoint or secret in frontend argv, environment or public diagnostics.
- Descriptor transfer is default-CLOEXEC, fixed, bounded and leak-free across every lifecycle and
  fault path; unrelated helpers and descendants cannot inherit it.
- ASB and `asb-tui` independently authenticate exact UID/PID/service generation, and PID reuse or
  substitution fails closed.
- Restart/reconnect has one explicit tested owner and preserves authoritative runner identity,
  cursor continuity and idempotency without frontend endpoint discovery.
- ASB gains provisioning and transport-boundary code only. No frontend UI, renderer, Ratatui,
  Crossterm, terminal event-loop, navigation, screen or widget implementation enters ASB.
- AR-1024 and AR-1025 name this dependency but retain their current status/owner until their entire
  prerequisite sets are done.
