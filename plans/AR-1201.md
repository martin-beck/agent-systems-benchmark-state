# AR-1201: Implement live provider capture (record) seam

## Outcome

Implement the runtime-owned capture path so `asb record` launches a real attempt against the pinned
provider, intercepts the provider-bound traffic, redacts and seals a cassette, and replay-verifies
it before any durable write.

## Dependencies and ownership

Dependencies: AR-0102 (process runtime), AR-0502/AR-0503 (cassette + strict replay), AR-0314
(source choice), AR-1200 (provider). Repository: `martin-beck/agent-systems-benchmark` only.
Owned paths are the concrete `ProviderCapture` in `crates/asb-runtime/src/provider_capture.rs`, a
capture sidecar (reverse of `loopback_sidecar.rs`: a provider-bound proxy that records responses
into `CassetteContents`), the `record`/`record-campaign` live mode in `crates/asb-cli`, redaction +
replay-verification before seal, and the cost/network acknowledgement path. Branch:
`feature/live-provider-capture`. Worktree: `agent-systems-benchmark-live-capture`.

## Work sequence

1. Define the capture sidecar contract: the child namespace sees a loopback endpoint bound to the
   provider route; the sidecar forwards to the real provider only after capture is acknowledged,
   and records request/response semantic fields (dialect, headers, body, SSE events, causal IDs)
   without transport chunks.
2. Implement `ProviderCapture::capture` for a real launch: run one attempt, collect the interaction
   stream, apply the redaction policy, seal the cassette, run it through `StrictReplayService` once
   (network denied) before returning the digest.
3. Wire `asb record` live mode: `asb record EXPERIMENT.toml` (or `--live` on the existing capture
   envelope path) runs the actual attempt, writes the cassette atomically, and emits
   `RecordingMetadata` only. Keep the existing envelope-seal path working.
4. Enforce acknowledgement: network consequence, cost estimate and recording persistence must be
   explicitly confirmed before the attempt starts; refusal is fail-closed.
5. Add the capture to `record-campaign` with per-tuple cost estimate and duplicate-paid-work
   fencing via `attempt_id`.

## Acceptance criteria

A live attempt against the pinned provider produces an immutable redacted cassette that passes
strict replay offline; no prompt/response/key appears in any artifact or error; a
cancelled/truncated/failed attempt produces no cassette or an explicit incomplete marker;
cost/network acknowledgement is mandatory; campaign duplicates are rejected before any paid call.

## Evidence

Loopback-only live-record journeys, redaction reports, replay-verified seals, negative fixtures
(interruption, size overrun, unknown fields), exact-head CI.
