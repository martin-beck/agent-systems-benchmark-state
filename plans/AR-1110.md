# AR-1110: Implement provider connections and model discovery

## Outcome

Add managed provider connections, compatible model discovery and user-defined provider profiles.

## Dependencies and ownership

Dependencies: AR-0315 and AR-1120; AR-0311 and AR-0312 are provider design inputs, while AR-1100 is transitive. Repository: `martin-beck/agent-systems-benchmark`. Owned paths: provider/connection/model registry, built-ins, custom OpenAI-compatible endpoints, discovery cache and tests.
Branch: `feature/ar-1110`. Worktree: `agent-systems-benchmark-ar-1110`.

## Work sequence

1. Separate provider family, named connection, API protocol, endpoint, authentication method, model and qualification identity.
2. Register qualified OpenAI, Gemini and Ollama profiles and bounded user-defined OpenAI-compatible connections.
3. After authentication, fetch bounded provider-specific model catalogs and bind freshness to the connection and credential reference.
4. Map exact agent compatibility to provider protocol and model settings; never infer support from a model-list response alone.
5. Attack redirects, unsafe endpoints, oversized or duplicate catalogs, aliases, stale caches and malformed models.

## Acceptance criteria

Users can add and manage provider connections and select only current models compatible with the selected agents; unavailable or unqualified combinations remain disabled with stable reasons.

## Evidence and completion

Record bounded public fixtures, exact schema and repository identities, focused/full gates, privacy scans, independent immutable-head review, exact-head CI and post-merge verification. Never publish credentials, prompts, responses, private paths, host identities or raw logs.
