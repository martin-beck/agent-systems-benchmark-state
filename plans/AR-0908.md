# AR-0908: Harden control-state lock test isolation

## Outcome

Make the embedded `asb-cli` control-state ownership/restart test deterministic under ordinary,
coverage, and parallel execution while preserving the production exclusive-lock and fail-closed
restart semantics unchanged.

## Dependencies and ownership

Dependencies: completed AR-0101, AR-0102, AR-0103, and AR-0875.

Owned product path:

- `crates/asb-cli/src/control.rs`, embedded `#[cfg(test)]` support and tests only

Do not alter production `open_backend`, lock acquisition, catalog reconciliation, public protocol,
schemas, Cargo manifests, or generated files without a separately reviewed scope amendment. This
repair unblocks investigation recorded by AR-0896 but does not depend on that blocked qualification
AR and must not change its MockAgents evidence.

## Investigation and implementation

1. Reproduce the exact post-drop reopen sequence under the same locked toolchain, Repository Quality
   coverage environment, and bounded parallel subprocess stress. Record whether the original
   failure is deterministic, filesystem-specific, collision-induced, or unreproduced.
2. Replace recursive reuse of a PID/sequence path with an atomically create-new unique private test
   root. Canonicalize and verify its external base, directory ownership and mode, and repository
   disjointness before any state file is created.
3. Bound collisions and fail closed. Never delete or reuse a stale, pre-existing, symlinked,
   non-directory, wrong-owner, public-mode, or repository-aliased root.
4. Preserve the behavioral sequence: first acquisition succeeds; a concurrent acquisition of the
   same state root is rejected; dropping every owning handle releases the lock; reopening succeeds;
   and a previously running catalog entry becomes `NeedsReconciliation`.
5. Keep cleanup scoped to the exact verified directory identity. A path substitution before cleanup
   must not delete an attacker-selected tree.

## Negative and stress evidence

- Reject fixed-name collisions, stale roots, leaf and ancestor symlinks, non-directory components,
  public permissions, wrong ownership, relative roots, and canonical overlap with the repository.
- Exercise multiple parallel subprocesses sharing one configured test base without root reuse or
  cross-process cleanup.
- Repeat the acquire/reject/drop/reopen lifecycle sufficiently to expose PID reuse and lock-release
  races, including the repository coverage command that originally failed.
- Inject a collision at creation and a path substitution before cleanup; prove failure is bounded,
  atomic, and leaves unrelated files unchanged.
- Keep diagnostics bounded and generic. Do not record temporary paths, account names, host identity,
  environment contents, catalog bodies, or private state.

## Gates and acceptance

Run focused `asb-cli` control tests serially and in parallel subprocesses; the exact Repository
Quality coverage command; full locked workspace format, Clippy, tests, rustdoc, and release build;
control protocol/contract and failure-path tests; mutation/fault/formal recovery checks where
applicable; repository policy, source headers, privacy, and Gitleaks; immutable scope,
SSH-signature, and DCO review; exact-head CI; and post-merge exact-main verification.

Acceptance requires deterministic proof that exclusive acquisition rejects a live competitor,
that all owners releasing permits reopen, and that uncertain restart still transitions to
`NeedsReconciliation`. Test roots are atomically unique, private, canonical, owner-bound,
repository-disjoint, collision-bounded, and symlink-safe under creation and cleanup. Production
locking is byte-for-byte unchanged unless a separately authorized product-defect repair is backed
by an independently reproduced failure.

## Evidence limits

A green synthetic lock lifecycle does not prove network-filesystem support, crash consistency on
every filesystem, distributed locking, or correctness after kernel failure. An unreproduced CI
failure must remain labelled as such; do not weaken exclusivity or claim a production fix merely to
stabilize the test harness.
