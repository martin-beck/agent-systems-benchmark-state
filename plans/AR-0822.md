# AR-0822: Add safe installation lifecycle management

## Outcome

Make update, downgrade policy, repair, rollback, migration, and uninstall as safe and understandable as first installation.

## Dependencies and ownership

Dependencies: AR-0104, AR-0820, AR-0821.
Owned paths: installed-version ledger, update/repair/uninstall commands, schema migrations, service transitions, rollback slots, retention policy, and lifecycle tests.
Branch: `feature/install-lifecycle`. Worktree: `agent-systems-benchmark-install-lifecycle`.

## Work sequence

1. Detect the exact installed channel/version/source and check signed update metadata without mutating on read-only checks.
2. Quiesce only control-plane components, never cancel active benchmark runs implicitly, validate protocol/schema migration, atomically switch verified versions, health-check, and roll back on failure.
3. Back up configuration and durable indexes with explicit versions and bounded retention; preserve recordings/results/trust by default and require a separate typed confirmation to purge data or credentials.
4. Implement repair for interrupted installation and service drift, explicit downgrade compatibility gates, channel changes, key rotation, and offline upgrades.
5. Uninstall binaries/service integration cleanly, show every retained path, and prove reinstall/reconnect can reuse compatible state without duplicating runs.

## Acceptance criteria

Upgrades and repairs are authenticated, atomic, and recoverable; active runs survive frontend/runner-control updates where promised; incompatible migrations fail before state change; rollback restores a usable prior version; uninstall is non-destructive by default; purge is explicit; and no secret or private result enters diagnostics.

## Evidence and completion

Record version/migration matrices, interrupted-step fault injection, active-run upgrade evidence, backups/rollbacks, immutable commits, reviews, exact-head CI, native platform sessions, and unsupported transitions.
