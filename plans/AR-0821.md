# AR-0821: Add guided one-line local installation

## Outcome

Let a new user run one documented command that downloads and verifies ASB, performs local setup, guides initial configuration, starts the independent local runner service, and opens `asb-tui`.

## Dependencies and ownership

Dependencies: AR-0803, AR-0804, AR-0805, AR-0820.
Owned paths: bootstrap script/binary, first-run orchestration, rootless installation, local service setup, configuration handoff, TUI launch, and installer tests.
Branch: `feature/one-line-local-install`. Worktree: `agent-systems-benchmark-one-line-install`.

## Work sequence

1. Publish a short copyable HTTPS one-liner that downloads a bounded bootstrap into a private temporary directory. The bootstrap displays channel/version/platform/source, obtains the signed AR-0820 manifest, and verifies every payload before execution. Document the HTTPS trust boundary and an equivalent stronger pinned/offline procedure; never claim a pipe-to-shell bootstrap is cryptographically self-authenticating.
2. Default to a rootless XDG installation and owner-local data/config/runtime paths. Never ask for `sudo` implicitly, edit shell startup files silently, overwrite an existing binary/config, or follow unsafe symlinks. Offer system-wide/package-manager modes only as explicit separate choices.
3. Install runner and TUI transactionally, run `asb doctor`, create an owner-only local service/socket using the detected service manager, and verify protocol/version/permissions. On systems without a supported service manager, offer a clearly labeled supervised local alternative rather than daemonizing ambiguously.
4. In an interactive TTY, enter the AR-0804 first-run wizard for agent/provider/replay/live/output choices, store only secret references with protected permissions or a supported credential store, then start `asb-tui` connected to the verified local service. Noninteractive use requires explicit flags and never invents provider choices.
5. Make reruns idempotent and resumable after network loss, Ctrl-C, full disk, verification failure, service-start failure, or terminal closure. Roll back partial binaries/service files while preserving pre-existing configuration and user data.

## Acceptance criteria

On every claimed fresh native platform, one pasted command reaches a verified local TUI with a healthy separate runner and guided configuration; no unverified payload runs; default setup needs no root; credentials/prompts never enter argv, logs, shell history, or artifacts; rerun cannot duplicate services or destroy settings; cancellation leaves a clean or explicitly recoverable state; and the exact installed version/source is visible before and after setup.

## Evidence and completion

Record disposable clean-home sessions, shell/TLS/proxy/TTY variants, installer transcript with synthetic public values only, manifest/artifact digests, service state, failure-injection cleanup, independent security/UX review, exact-head CI, and native distro/architecture results.
