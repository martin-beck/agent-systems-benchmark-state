# AR-1023: Add the ASB frontend capabilities command

## Outcome

Implement the product-side capability probe required before a standalone frontend can be selected,
installed or launched.

## Dependencies and ownership

Dependencies: AR-0803, AR-0840 through AR-0844, and AR-0904.
Repository: `martin-beck/agent-systems-benchmark`.
Owned paths: the narrow capability command in `crates/asb-cli`, its Rust types, generated schema and
fixtures, CLI help/completion, focused guide assertions and contract-consistency checks.
Branch: `feature/asb-tui-capabilities-command`.
Worktree: `agent-systems-benchmark-asb-tui-capabilities-command`.

Do not implement downloading, installation, rendering, lifecycle delegation, network access or
runner mutation. Do not expose socket paths, user IDs, environment values, provider configuration or
host identity.

## Work sequence

1. Reconcile the current `asb-control` method set with the public asb-tui capabilities schema.
2. Define a closed Rust response type containing protocol identity/version, ASB version and exact
   booleans for planning, launch, events, cancel, history, repeat, analysis and artifacts.
3. Add `asb capabilities --format json` with strict argument handling and stable exit codes.
4. Emit capabilities only when their authoritative control methods exist; unknown is unavailable.
5. Generate/check JSON Schema and public fixtures from the Rust model.
6. Import or digest-bind the matching public asb-tui fixture and prove its parser accepts the exact
   ASB output while rejecting drift, duplicate fields, unknown fields, wrong versions and bad types.
7. Update help, completion and documentation without claiming installation or interactive rendering.

## Acceptance criteria

- The command is deterministic, side-effect-free, bounded and valid in an empty/minimal environment.
- Output contains no private host or user data and matches the closed schema byte-for-semantics.
- Every `true` capability maps to a tested `asb-control` operation.
- Malformed invocations and unsupported formats fail with stable structured errors.
- The exact public asb-tui parser accepts the fixture generated from ASB.

## Evidence

Run focused CLI/schema/parser tests, the complete workspace fmt/Clippy/test/doc/release gates,
contract consistency, formal/fault suites applicable to the CLI boundary, dependency and workflow
audits, Gitleaks, clean-tree review, exact-head CI and post-merge verification. Record the exact ASB
and asb-tui revisions used for cross-contract evidence.
