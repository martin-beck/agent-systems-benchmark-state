# AR-0817: Build remote terminal frontend workflows

## Outcome

Integrate professional remote connection and durable-run management journeys into `asb-tui` without obscuring trust or runner location.

## Dependencies and ownership

Dependencies: AR-0804, AR-0805, AR-0806, AR-0815, AR-0816.
Owned paths: remote connection manager, runner selector, trust/enrollment UI, remote status/history, detach/reconnect UX, and TUI tests.
Branch: `feature/remote-tui-workflows`. Worktree: `agent-systems-benchmark-remote-tui-workflows`.

## Work sequence

1. Add explicit local/remote runner selection, IP/DNS entry, saved non-secret profiles, certificate/fingerprint display, latency/version/capability preflight, and clear active-runner identity in every view.
2. Guide enrollment and roles, then reuse existing settings/launch/status/history interfaces with runner-side capabilities and platform data.
3. Provide deliberate `detach` distinct from `cancel`, persistent reconnect shortcuts, offline/stale indicators, resync progress, conflict notices, and safe multi-runner switching.
4. Never display controller paths/platform as runner facts; keep sensitive remote artifacts behind explicit authorized retrieval and redaction.
5. Test wrong runner, address reuse, identity change, expired trust, network transitions, resize during reconnect, multiple controllers/runners, long-running sessions, and accessibility/plain-mode journeys.

## Acceptance criteria

Users always know which authenticated runner they control and whether data is live/stale; launching remotely is no more ambiguous than locally; closing the TUI defaults to detach and clearly states the run continues; reconnect/adopt is discoverable; cancel requires explicit run-scoped confirmation; cross-platform facts are labeled by source; and connection failures never damage runner state.

## Evidence and completion

Record synthetic UX fixtures, usability/accessibility review, remote fault journeys, immutable commits, exact-head CI, native cross-platform sessions, and unsupported terminal/network combinations.
