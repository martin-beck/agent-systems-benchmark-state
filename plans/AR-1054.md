## Exact failure and repair boundary

PR #19 exact-head Repository quality run `34561967135` passed. GitHub-verified squash
`7a398032246aa935b13b5d3139949c2375fa7309` has parent `de5c6c6289f306361e02cb97325db072775f2a29`,
the exact reviewed tree, and a valid raw multiline DCO trailer. Trusted-main run `34562090773`
failed five live tmux fixtures at the same closed pre-credential stage
`socket_connection_unavailable`; 23 of 28 terminal tests passed. This localizes the defect to
connecting to the exact authenticated socket, before any `SO_PEERCRED`, generation, pane, option or
signal decision.

Linux nonblocking AF_UNIX `connect(2)` may return `EAGAIN` rather than `EINPROGRESS`. Treat both as
incomplete and decide completion from bounded readiness followed by exact `SO_ERROR`, not by
rejecting `POLLHUP`/`POLLERR` alone. Require a valid descriptor, bounded readiness, reject
`POLLNVAL`/timeout/unavailable cases, and proceed only when exact `SO_ERROR` is zero. Measure the
encoded socket pathname against `sockaddr_un.sun_path` before connecting and retain the existing
content-free diagnostic. Never treat a nonzero socket error or unavailable/malformed credentials
as success.

## Tests and gates

Add an injected connection-completion classifier/fixture proving:

- immediate connect success and delayed readiness after either `EINPROGRESS` or AF_UNIX `EAGAIN`
  plus zero `SO_ERROR` succeed;
- `POLLHUP` or `POLLERR` combined with readiness and zero `SO_ERROR` does not override the kernel
  completion result;
- timeout, zero readiness, `POLLNVAL`, malformed readiness and every nonzero `SO_ERROR` fail closed;
- overlong/NUL socket paths and unproven completion never reach peer/process authority.

Retain the exact peer-credential, cross-process, unavailable-socket and all live tmux tests. Run
