# AR-1419: Literature framework boundaries

## Objective

Ensure every benchmark or evaluation family named in ASB's literature documentation
is represented exactly once in the machine registry and generated docs, while
frameworks and infrastructure are not accidentally exposed as executable workloads.

## Dependencies and scope

- Depends on AR-1417 and AR-1418.
- Product repository only; no `asb-tui` changes.
- Owned paths: documentation inventory, registry validation, generated catalog tests,
  selector labels, and hostile fixtures.

## Acceptance

1. Build a machine-checked inventory from `docs/WORKLOADS.md`, `docs/RELATED_WORK.md`,
   `docs/PLAN.md`, and the registry. Every named benchmark has one stable identity,
   source/revision/license record, role, evidence state, and selection policy.
2. Mark Harbor, Inspect AI, HAL, AgentOps, and HELM (and any newly found framework,
   harness, scorer, or observability tool) as non-workload methodology records unless
   an explicit task protocol plus independent grader exists. They must be visible for
   provenance but rejected before execution.
3. Add generated-doc parity and omission tests, duplicate/role-confusion hostile
   fixtures, and checks that built-in and literature selectors expose the same truthful
   evidence labels across CLI, replay, and report paths.
4. Preserve source links without copying copyrighted task data. No runtime network,
   credentials, telemetry, private paths, or unbounded evidence is introduced.
5. Run focused and full gates, exact-head CI, independent diff/privacy review, and
   all post-merge assurance workflows before release.

## Non-goals

No new benchmark execution, score normalization, live-provider test, or framework
dependency. Execution remains owned by the family-specific ARs.
