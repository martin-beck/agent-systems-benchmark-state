# AR-1233: Approved loopback-only sandbox transport

## Outcome

Extend the approved runtime sandbox with an authenticated loopback-only network policy for strict
replay services, without weakening `NetworkPolicy::Deny` or permitting provider egress.

## Dependencies and ownership

Dependency: AR-1231 and AR-1100. Repository: `martin-beck/agent-systems-benchmark`. Own the runtime transport
policy, route/listener identity binding, and focused native tests.

## Acceptance

- Add a typed, versioned loopback-only policy distinct from `Deny` and `Host`; reject all provider
  endpoints, ambient network, credentials, and unknown policy fields.
- Bind listener address and route digest to the authenticated launch record and owned service;
  reject stale, duplicate, mismatched, or externally supplied route identities.
- Prove a real strict-replay child reaches only the owned cassette service while a provider and
  descendants are denied, with bounded timeout/cancellation/reaping/restart cleanup tests.
- Preserve `NetworkPolicy::Deny` behavior and existing bytes/schema; add docs and negative tests.
- Run signed-DCO focused/full locked, policy, privacy, and native gates with exact-head review.

## Explicit non-goals

No provider discovery, credentials, live provider network, shell command execution, or TUI changes.
