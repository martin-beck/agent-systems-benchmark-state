# AR-0806: Add terminal history and analysis

## Outcome

Show recent durable runs, let users inspect and deliberately repeat their plans, and analyse only provenance-compatible results.

## Dependencies and ownership

Dependencies: AR-0104, AR-0203, AR-0805, AR-1001.
Owned paths: paginated history UI, repeat workflow, result summaries, comparisons, exports, and tests.
Branch: `feature/tui-history-analysis`. Worktree: `agent-systems-benchmark-tui-history-analysis`.

## Work sequence

1. Present paginated/filterable recent runs with status, time, agents, provider/replay source, workload, platform, result integrity, and concise outcome.
2. Show full redacted provenance, metrics, uncertainty, failures, artifacts, and unsupported/missing evidence on demand.
3. Repeat by cloning the immutable prior plan into a new draft, revalidating all pins/capabilities, highlighting drift, and requiring confirmation.
4. Compare only through AR-1001 compatibility results; visibly label confounders and refuse unqualified claims.
5. Test deleted/corrupt/legacy/incomplete runs, pagination races, changed providers/models, unavailable recordings, large result sets, export redaction, and concurrent retention.

## Acceptance criteria

Recent runs are useful without loading unbounded history; repeat never mutates or reuses a prior run ID and cannot bypass current validation; analysis reports uncertainty and provenance limits; confounded runs are unmistakable; sensitive artifacts require explicit access; and stale/deleted data fails clearly without crashing the runner or frontend.

## Evidence and completion

Record synthetic history fixtures, comparison and drift negatives, immutable commits, independent review, CI, performance limits, and post-merge tests.
