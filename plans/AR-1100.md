# AR-1100: Add the machine-readable provider registry foundation

## Outcome

Replace the hard-coded provider catalog with a machine-readable, versioned provider registry that is
embedded at compile time, strictly validated, and digest-pinned, while keeping every existing CLI
output contract byte-identical so no downstream selection fixture changes.

## Dependencies and ownership

Dependencies: AR-0310 (provider-profile contract). Repository:
`martin-beck/agent-systems-benchmark` only. Owned paths are the embedded registry file
`config/providers/providers-v1.toml`, the loader and validation module
`crates/asb-agents/src/registry.rs`, the registry-driven `provider_catalog_digest` and
`provider_catalog` in `crates/asb-cli/src/lib.rs`, the new read-only `asb registry` command, and
tests. It reuses AR-0310's `ProviderKind`, `EndpointClass`, `CredentialSource`, `ProviderSettings`
and `ProviderTransportLimits` so that one registry entry can construct a
`ProviderProfileV1` later. No live API, network, credential value or user interaction is required:
the default registry is embedded via `include_str!` and all tests use in-memory fixtures.
Branch: `feature/provider-registry`. Worktree: `agent-systems-benchmark-provider-registry`.

## Work sequence

1. Define `config/providers/providers-v1.toml` with a versioned table containing one entry per
   provider id. Each entry carries `id`, `kind` (openai, openai_compatible, anthropic, ollama),
   `model`, `credential_source` (none, environment, file_descriptor, helper), `selectable`, an
   optional `unavailable_reason`, and the exact public defaults needed to construct a
   `ProviderProfileV1` later (endpoint class, api base for public services, settings, transport).
   The default file reproduces exactly the current catalog: `openai` with model
   `gpt-5.2-2025-12-11` selectable, and `ollama` with model `qwen3-coder:30b` advertised but
   selectable false with the current unavailable reason. Extensibility is explicit: unknown
   providers may be added by editing this file, and a user overlay file path is reserved but not
   required.
2. Add `crates/asb-agents/src/registry.rs` with a strict parser (toml crate, deny unknown fields,
   bounded strings, bounded counts) that returns a deterministic `ProviderRegistry` ordered
   canonically by provider id. Every entry must be validated: non-empty ids, known kind, non-empty
   model, valid digest-shaped fields, and selectable=false requires an unavailable_reason.
3. Compute a canonical `registry_sha256` over the fully parsed and re-serialized registry so that
   formatting noise never changes the identity. Expose `registry_sha256()` and
   `provider(id)` lookup.
4. Switch `provider_catalog_digest` and `provider_catalog` in `crates/asb-cli/src/lib.rs` to derive
   their bytes from the registry. The digest input sequence must remain byte-identical to the
   current hard-coded sequence so the catalog digest value and `provider-catalog` JSON output do
   not change. Add an exact-head test asserting the digest and JSON output are unchanged.
5. Add the read-only `asb registry` command that prints the canonical parsed registry and its
   `registry_sha256` as a bounded JSON envelope following the existing `ProviderCatalogOutput`
   shape and `ErrorEnvelope` conventions.
6. Test strict rejection of malformed, unknown-field, oversized and inconsistent entries in
   unit tests; prove the embedded default registry parses and its digest is stable; prove
   `provider-catalog` output and digest remain byte-identical.

## Acceptance criteria

`provider-catalog` and `provider-plan` behave exactly as before (same digest, same JSON). The
default registry is embedded and validated, no network or credential is needed, and adding a new
provider or model is a data-only change. Malformed registries fail closed at parse time with a
bounded error and never fall back to a partial catalog.

## Evidence

Record the unchanged catalog digest, exact `asb registry` output, strict parser tests for
malformed/unknown/oversized entries, digest-stability tests, privacy scan and exact-head CI.
