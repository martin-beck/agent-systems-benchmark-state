# AR-1011: Deliver TUI UX quality features

## Outcome

Make common ASB workflows easy for beginners and efficient for experts without inventing capabilities the negotiated runner does not advertise.

## Dependencies and ownership

Dependencies: AR-1010, AR-0870, AR-0871, AR-1014, AR-1031, AR-1032, AR-1033, AR-1034
and AR-1035. The focused feature ARs establish the concrete user-facing screens; this AR performs
their integrated usability pass and closes defects without moving UI implementation into ASB.
AR-0870 and AR-0871 are read-only migration and reviewed-behavior inputs, not authorization to
modify or restore legacy ASB frontend code.
Repository: `martin-beck/asb-tui`. Focused ARs retain implementation ownership. This AR owns only
cross-screen navigation/action consistency, end-to-end journeys, usability defect follow-ups,
accessibility integration and interaction fixtures. No ASB product paths are owned.
Branch: feature/tui-ux-quality. Worktree: agent-systems-benchmark-asb-tui-ux-quality.

## Required features

1. Integrate and qualify AR-1032's global command/search palette, deterministic matching, focus,
   Escape/back behavior and shortcut presentation across every screen.
2. Integrate and qualify the focused selectors from AR-1014 and the agent/provider/workload/recording
   flows, including disabled reasons and preserved search state.
3. Connect the landing and configuration workspaces into a beginner journey with step indication,
   contextual help, safe negotiated defaults, back/reset/import/export, validation and explicit
   review before launch.
4. Qualify the existing run-control progress model with per-agent state, elapsed time, bounded
   resource/attempt counters, cancellation confirmation, reconnect state and clear outcomes.
5. Integrate AR-1035 history/report/compare navigation, warnings, numeric equivalents and exact
   reproducible CLI commands with the rest of the application.
6. Close cross-screen keyboard, focus, theme, NO_COLOR, plain-output, screen-reader order and error-
   language defects. Mouse remains optional and cannot be the sole access path.
7. Validate one typed focus/navigation graph for every enabled screen and modal: deterministic Tab,
   Shift-Tab and arrow order; explicit Escape, Back and Home hierarchy; prior-focus restoration on
   modal close; a valid retained or deterministic fallback target after resize, reconnect or
   capability loss; and no unreachable enabled action or shortcut-only action.

## Acceptance criteria

A new user can discover and complete setup without memorizing flags; an expert can reach any screen
through the palette and keyboard; search/filter state survives resize and backtracking; every
action is capability-gated and confirmation-protected; progress never claims runner truth before an
authoritative event; and all screens have bounded, privacy-safe text equivalents. Exhaustive graph
fixtures must prove every enabled action is keyboard reachable, focus cannot become hidden or
trapped, modal close restores the prior valid target, and resize/reconnect/capability transitions
select a documented valid fallback without dispatching an action.

## Evidence

Capture sanitized interaction fixtures, exhaustive focus/navigation graph fixtures, TestBackend
snapshots, keyboard-only and accessibility checks, resize/latency probes, beginner usability
walkthroughs, exact CLI parity checks, independent UX/security review, exact-head CI, and post-merge
verification.
