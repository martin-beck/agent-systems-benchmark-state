# AR-1106: Extend the TUI wizard with provider model selection

## Outcome

The asb-tui setup wizard gains model selection from the provider's offered models, the
default-vs-selected-agent scope choice, and a default provider/model applying to all agents, using
the product registry through a public read-only contract, without ever storing secrets or
mutating authoritative runner state.

## Dependencies and ownership

Dependencies: asb-tui AR-1025 (settings-wizard port), AR-1033 (visual system) and AR-1034
(configuration center), plus product AR-1102 (UserConfigV1) and AR-1103 (CLI setup wizard).
Repository: `martin-beck/asb-tui` only. Owned paths are the wizard model/selection extensions in
`src/app.rs` (model in `SharedProviderChoice`, model/scope/default in `MultiAgentSettings`), the
wizard screens, the `PreviewConfig`/`WriteConfig` control calls and tests. ASB remains the
authority for validation: the TUI renders registry providers/models supplied by a public read-only
contract and edits local preference and validated draft state only; secrets never enter the TUI.
This record is tracked here pending registration in the asb-tui coordinator (sqlite-backed on
another development machine). Branch: `feature/asb-tui-wizard-provider-model`. Worktree:
`agent-systems-benchmark-asb-tui-wizard-provider-model`.

## Work sequence

1. Extend `SharedProviderChoice` to carry the registry-offered model list for the selected
   provider and the `MultiAgentWizard` provider step with a bounded, searchable model selection
   step that preserves query/focus through resize and defines exact clear/Escape/Back behavior.
2. Extend `MultiAgentSettings` with `model`, `scope` (default or selected agents) and
   `set_default` state; the wizard preview and confirm steps show origin, effective value and
   validation consequence for every value.
3. Add `ControlCall::PreviewConfig` and `ControlCall::WriteConfig` that render the chosen
   settings as a UserConfigV1 draft (AR-1102 shape) for preview, and write it only after
   confirm, atomically, with the same bounds as AR-1103 and never storing secret-shaped input.
4. Capability-gate unavailable providers/models with reasons and never allow a live-discovered
   model to be selected into the draft; only registry-pinned models are selectable.
5. Test model search bounds, scope toggle, default application, preview/apply/cancel, unsaved
   confirmation, secret-shaped rejection, and parity with the AR-1103 non-interactive transcript.

## Acceptance criteria

A user can select provider, model and scope, set the default for all agents, and preview/write a
validated UserConfigV1 draft entirely from the TUI; cancellation loses no prior state; secrets and
unpinned models can never enter the draft; runner-owned values are never silently overridden.
