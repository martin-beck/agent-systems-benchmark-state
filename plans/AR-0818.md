# AR-0818: Audit remote benchmark control

## Outcome

Independently verify that remote control is secure, durable, interoperable, privacy-preserving, and operationally safe.

## Dependencies and ownership

Dependencies: AR-0813, AR-0814, AR-0815, AR-0816, AR-0817, AR-0819.
Owned paths: independent threat/fuzz/fault/interoperability audits, remediation evidence, and release gate.
Branch: `audit/remote-control`. Worktree: `agent-systems-benchmark-remote-control-audit`.

## Work sequence

1. Audit attack surface from unauthenticated network through TLS, parser, authorization, mutations, event streams, artifact access, logs, updates, and recovery.
2. Fuzz wire framing/schemas/state transitions; test denial of service, resource exhaustion, replay/downgrade, certificate/key compromise, privilege escalation, request duplication, and confused-deputy paths.
3. Prove disconnect/reconnect/upgrade/partition/crash invariants and verify runs continue independently of every frontend failure.
4. Repeat native cross-architecture/distribution journeys and measure control-plane interference with representative benchmark loads.
5. Verify install/firewall/TLS/rotation/revocation/backup/troubleshooting documentation and ensure remote exposure remains opt-in.

## Acceptance criteria

No critical/high unresolved finding remains; unauthenticated/plaintext/default-public exposure is impossible; fuzz/fault limits hold; authorization and audit are complete; sensitive/project data does not cross by default; lifecycle invariants survive failures; performance interference stays within published bounds; and every unsupported combination or residual risk is explicit.

## Evidence and completion

Record tool/corpus versions, minimized public reproducers, remediation commits, independent approvals, exact CI/native run IDs, threat-model closure, platform matrix, and post-release checks without publishing exploit secrets prematurely.
