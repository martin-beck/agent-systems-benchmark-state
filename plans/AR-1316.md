# AR-1316 implementation plan

## Outcome

Publish the authenticated, target-bound ASB agent catalog that the standalone
asb-tui setup wizard consumes for first-run and reconfiguration agent selection.

## Owned paths

ASB only: `crates/asb-cli/src/control.rs`, `crates/asb-control/`, the verified
agent/package metadata source, generated schemas/fixtures, and focused tests.
Do not weaken catalog validation or expose credentials, paths, prompts, or
provider traffic in the catalog.

## Design obligations

1. Return a non-empty, canonical `AgentCatalog` for `Status` and a bounded,
   generation-fenced refresh for `Refresh`; reject stale runner identity or
   catalog generations.
2. Source entries only from verified, locally available package metadata. If a
   package is not proven selectable, expose it as unavailable with a precise
   reason; never fabricate package, signature, provenance, or target identity.
3. Advertise the capability in the negotiated control response and preserve
   schema compatibility through additive/versioned changes.
4. Ensure restart persistence and deterministic ordering/digest calculation.
   The versioned digest must not include response-only `refreshed` state; the
   identity/generation binding must be explicit and stable across Status and
   Refresh responses.

## Tests and evidence

Focused producer, schema, generation-fencing, restart, and exact TUI fixture
tests; then locked clippy/workspace tests, DCO/signature, exact-head CI, and
post-merge verification.
