# AR-0805: Add terminal run control and status

## Outcome

Let `asb-tui` launch a validated plan once and show reconnectable live status without becoming part of benchmark execution.

## Dependencies and ownership

Dependencies: AR-0104, AR-0204, AR-0803, AR-0804.
Owned paths: TUI launch confirmation, current-run dashboard, event projection, cancellation controls, and integration tests.
Branch: `feature/tui-run-control`. Worktree: `agent-systems-benchmark-tui-run-control`.

## Work sequence

1. Submit an immutable plan with an idempotency key and display the durable run ID before following progress.
2. Show queued/running/completed attempts, scheduler capacity, deadlines, leases, provider/replay source, metrics, warnings, failures, and evidence availability.
3. Reconnect from a cursor after frontend restart; handle compaction and authoritative snapshot refresh.
4. Make pause/cancel/stop controls explicit about scope and acknowledgement; never report success before durable runner confirmation.
5. Test duplicate launch, slow/dropped events, out-of-order or stale status, runner restart, frontend kill, cancellation races, terminal resize, and high-cardinality runs.

## Acceptance criteria

One confirmation produces at most one durable run; displayed state is labeled by freshness and causal revision; reconnect converges to runner truth; UI resource use is bounded and cannot backpressure measurements; cancellation is accurately acknowledged; and runner execution continues when the TUI exits or crashes.

## Evidence and completion

Record fault traces in redacted synthetic form, resource measurements, immutable commits, reviews, exact-head CI, native platform checks, and post-merge runner/frontend separation evidence.
