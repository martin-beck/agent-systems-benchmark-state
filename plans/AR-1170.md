# AR-1170: Build complete standalone asb-tui wizard journeys

## Outcome

Implement first-run, reconfiguration, authentication, recording, offline run and analysis workflows.

## Dependencies and ownership

Dependencies: AR-1034 and AR-1160; AR-0804, AR-0870, AR-0871, AR-1025 and AR-1033 are required frontend design inputs. Repository: `martin-beck/asb-tui`. Owned paths: wizard routes/screens, agent/provider/model selectors, auth handoff, defaults, recording coverage, run/analysis integration and tests.
Branch: `feature/ar-1170`. Worktree: `agent-systems-benchmark-ar-1170`.

## Work sequence

1. Consume exact negotiated ASB catalogs and port only reviewed legacy behavior into standalone typed state.
2. Guide clean first setup and later connection, authentication, model, global-default and per-agent changes.
3. Use masked non-retained input and the ASB-owned one-shot enrollment boundary; never store or transport secrets ordinarily.
4. Select agents and selected/all workloads for recording, show cost/network/storage effects, progress and cassette coverage.
5. Connect setup to run, monitor, reports, compare and repeat with explicit live, live-recording and strict-replay labels.
6. Qualify keyboard access, tiny/resize/plain terminals, SSH/tmux, reconnect, malformed data and privacy-safe snapshots.

## Acceptance criteria

A first-time user can set up, record, run offline and analyze entirely in the standalone TUI; ASB remains authoritative and CLI/TUI normalized settings agree.

## Evidence and completion

Record bounded public fixtures, exact schema and repository identities, focused/full gates, privacy scans, independent immutable-head review, exact-head CI and post-merge verification. Never publish credentials, prompts, responses, private paths, host identities or raw logs.
