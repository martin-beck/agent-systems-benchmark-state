# AR-0310: Define common provider profiles

## Outcome

Create a versioned, credential-free provider profile that every agent adapter can translate or explicitly reject.

## Dependencies and ownership

Dependencies: AR-0101, AR-1001.
Owned paths: provider profile protocol types, schemas, fixtures, capability negotiation, and adapter-facing interfaces.
Branch: `feature/provider-profile-contract`. Worktree: `agent-systems-benchmark-provider-profile-contract`.
Shared Cargo, lockfile, and schema integration requires the coordinator fence.

## Work sequence

1. Model provider kind, endpoint class, model, sampling/reasoning/token settings, transport limits, and a canonical credential-free settings digest.
2. Define per-adapter capability negotiation and exact/lossless translation rules.
3. Separate secret references from serializable profiles; never persist credential values, authorization headers, raw prompts, or host-private paths.
4. Add positive, malformed, unknown-field, lossy-translation, unsupported-setting, and canonical cross-language fixtures.
5. Run all protocol, formal, privacy, schema, build, and full quality gates on the exact tree.

## Acceptance criteria

The same profile has one deterministic identity across languages; supported adapters prove the effective provider/model/settings match it; unsupported fields fail before an agent starts; endpoint and credential provenance are represented without secrets; no adapter silently substitutes defaults; and version negotiation is bounded and forward-compatible.

## Evidence and completion

Record exact manifests, immutable commits, signatures/DCO, reviews, exact-head CI, and post-merge checks. Claim only provider fields proven at the actual agent boundary.
