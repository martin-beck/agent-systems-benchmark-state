# AR-1200: Pin the OpenRouter provider profile (free model) and credential boundary

## Outcome

Add a pinned OpenRouter provider profile (OpenAI-compatible endpoint, one frozen `:free` model
snapshot) with the environment credential boundary and exact adapter translations, exposed through
the provider catalog and `AllAgentsProviderSelection`, so live record (AR-1201) and replay
benchmarking have one deterministic provider target.

## Dependencies and ownership

Dependencies: AR-0310 (provider-profile contract), AR-0313 (all-agents selection), AR-0318 and
AR-0320 (credential reference/resolver integration). Repository:
`martin-beck/agent-systems-benchmark` only. Owned paths are `crates/asb-agents/src/openrouter.rs`,
the provider catalog and `provider-plan` in `crates/asb-cli/src/lib.rs`, the provider parity
module, and the capabilities output. `crates/asb-protocol` provider enums change only if strictly
required and are coordinator-fenced. Branch: `feature/openrouter-provider`. Worktree:
`agent-systems-benchmark-openrouter-provider`.

## Work sequence

1. Record availability evidence for a specific `:free` model identifier (exact string, date,
   endpoint, observed rate limits) and freeze it in a `const` snapshot; moving aliases are
   rejected.
2. Implement `OpenRouterProfile` mirroring `OpenAiProfile` with base `https://openrouter.ai/v1`,
   `EndpointClass::PublicService`, `CredentialSource::Environment`, `OPENROUTER_API_KEY` target,
   and transport bounds.
3. Translate for every supported agent (ChatCompletions / Responses routes exactly as the OpenAI
   profile), reusing `ProviderProfileAdapter`/`bind_provider_profile` and the
   `verify_effective_request` fail-closed boundary.
4. Add the catalog entry (`provider-catalog`, `provider-plan --provider-profile openrouter`) and
   the `AllAgentsProviderSelection` route; keep `ollama` unavailable.
5. Prove the credential reference digest path: synthetic environment credential injected into an
   empty child environment, no key bytes in argv/env/manifest/errors.

## Acceptance criteria

`provider-plan --provider-profile openrouter` yields a canonical, digest-pinned selection for every
supported agent; effective requests match the pinned model, route, stream/tools and reasoning
settings; mismatched/moving/unknown models fail closed; no credential value leaves the resolver
boundary; catalog digest changes are deterministic; capability output lists the profile as
selectable only with the exact pin.

## Evidence

Profile unit tests, effective-request fixtures, credential-boundary negative tests, catalog digest,
signed DCO commits, exact-head CI, parity module rows.
