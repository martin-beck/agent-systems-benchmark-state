# AR-1200: Kernel diagnostic rejection fixture stability

## Scope

Stabilize the `asb-metrics` unit test
`kernel::tests::bounded_tool_boundary_covers_success_denial_timeout_and_cleanup`.
The change is test-only. Do not alter `KernelDiagnostics` production timeout behavior,
classification semantics, or cleanup policy.

## Evidence and implementation

- Hosted PR #174 run `34951783425` failed in the existing test with `TimedOut` where
  `ProbeRejected` was expected.
- The failing test launched the instrumented Rust test binary with a 100 ms deadline for
  the rejection branch; this creates a scheduler/startup race.
- Signed candidate branch: `repair/metrics-timeout-flake`.
- Candidate head: `0a7f6a192af9b6a538c7547dfff9e65842d59049`.
- Candidate replaces that subprocess with a small pinned executable fixture that exits
  nonzero for the probe while retaining the same `run` path and parser/classifier.

## Acceptance and tests

1. Keep the production timeout and all runtime code unchanged.
2. Verify the candidate is signed with the host ED25519 key and has DCO sign-off.
3. Run the focused boundary test at least 30 times, the full `asb-metrics` unit suite,
   formatting, clippy with `-D warnings`, and `git diff --check`.
4. Require exact-head hosted CI for the separate PR and independent review before merge.
5. Record post-merge green evidence; do not mix this change into catalog digest PR #174.

## Ownership boundary

This is ASB metrics test infrastructure only. It contains no TUI, renderer, Ratatui,
Crossterm, or coordinator implementation.
