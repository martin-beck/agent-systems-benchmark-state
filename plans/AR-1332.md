# AR-1332: Record-live to replay-offline workflow

## Outcome

A documented, user-visible `record-live -> replay-offline` workflow: an
opt-in live record mode persists intent before provider contact and seals
per-tuple cassettes, followed by a replay mode that accepts only runtime-issued
authority and replays the exact sealed evidence strictly offline with no
provider fallback.

## Dependencies and ownership

Dependencies: AR-1331 (runtime-owned replay authority). Owned paths: the
record-mode CLI surface, the record-live and replay-offline command wiring,
workflow documentation, and the per-tuple record and replay result records in
the ASB product. Branch: `feature/ar-1332-record-live-replay-offline`.
Worktree: `agent-systems-benchmark-ar-1332-record-live-replay-offline`.

## Work sequence

1. Define the record-live command form: explicit opt-in flag, persisted intent
   before provider effects, and per-tuple sealed cassettes with digests.
2. Define the replay-offline command form: runtime-issued authority only,
   strict replay of the sealed matrix, and recorded replay outcomes.
3. Connect the two through the runtime context so a recorded run's authority
   and cassettes are the only inputs replay accepts.
4. Reject replay inputs that lack authority, contain stale or mismatched
   digests, or request live fallback; keep duplicates and interruptions
   fail-closed.
5. Document the workflow in QUICKSTART and add end-to-end workflow tests using
   loopback and sealed fixture cassettes.

## Acceptance criteria

Record then replay works end to end with real evidence, replay never contacts a
provider and never fabricates authority, interrupted or duplicated records fail
closed, and the workflow is documented truthfully with its opt-in and offline
limits.

## Evidence and completion

Record immutable commits, workflow fixtures, captured and replayed evidence
pairs, independent review, exact-head CI, and post-merge verification.
