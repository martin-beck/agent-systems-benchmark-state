# AR-1270: Runtime-issued cassette-service handle

## Outcome

Extend the dependency-neutral replay transport with a runtime-issued cassette-service handle so the
supervised launch bundle can execute real request/response traffic without importing CLI, agent, or
replay implementation types.

## Dependencies and ownership

Dependencies: AR-1237, AR-1238, AR-1239. AR-1269 is blocked design evidence and its unmerged branch
is not an input. Owned paths: shared replay transport contract, runtime cassette-service handle,
CLI adapter, and integration fixtures/tests. Branch:
`feature/ar-1270-runtime-cassette-handle`. Worktree:
`agent-systems-benchmark-ar-1270-runtime-cassette-handle`.

## Work sequence

1. Define a bounded opaque service-handle/operation contract in the dependency-neutral core. Runtime
   issues it only after cassette identity, route, namespace, lease, and command attestation; callers
   cannot provide service endpoints or fallback providers.
2. Bind the handle to the launch bundle and actual CLI replay dispatch with exact-once consumption.
3. Add real credential-free request/response fixtures and prove route mismatch, malformed cassette,
   provider/descendant egress denial, no-live-fallback, cancellation/restart, timeout/crash reaping,
   and cleanup/no-leak behavior.
4. Run full locked offline gates, policy/privacy/schema/signature/DCO, independent review, exact-head
   CI, signed merge, and all post-merge assurance workflows.

## Acceptance criteria

The actual replay command performs real cassette traffic through a runtime-issued handle under
supervision, with all authority and lifecycle failure paths bounded and fail-closed. No dependency
cycle or metadata-only substitute remains.
