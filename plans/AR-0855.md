# AR-0855: Enforce Huawei MIT source headers

## Outcome

Require every tracked first-party source file in the Agent Systems Benchmark product and state
repositories to carry the exact 2026 Huawei copyright immediately before its SPDX MIT identifier.

## Dependencies and ownership

Dependencies: AR-0003. Owned paths: first-party tracked source files, product repository-policy
tooling and tests, dedicated product CI workflow, state first-party source files, and the state
verification workflow. Exclude vendored coordinator files, generated coordination views, generated
artifacts, dependency/vendor trees, fixtures that intentionally model external or malformed input,
and non-source data/documentation. Branch: fix/huawei-mit-license-headers. Worktree:
agent-systems-benchmark-huawei-mit-headers.

## Work sequence

1. Audit the current tracked-file classifier and record the exact first-party source scope.
2. Extend the existing product SPDX policy to require adjacent Huawei 2026 and MIT SPDX lines while
   preserving executable shebangs, and add positive and hostile-path tests.
3. Add the required header to every in-scope product and state source file.
4. Add dedicated product and state CI enforcement without duplicating the product policy engine.
5. Run focused tests and every applicable full product and state gate on the exact candidate commits.
6. Publish focused signed and DCO-certified product and state pull requests; do not merge.

## Acceptance criteria

- Exact adjacent header lines are enforced for all tracked first-party Rust, Python, and shell source.
- Shebang placement remains valid; wrong company, year, rights text, order, spacing, SPDX value, or
  missing line fails with a path-specific diagnostic.
- Product enforcement extends `tools/quality/repository_policy.py`; CI invokes that existing policy.
- State enforcement excludes the pinned vendored coordinator and covers state-owned Python and shell.
- Tests prove success and representative failure modes without weakening existing quality gates.
