# AR-1451: Central orchestration authority contract and ASB redesign

## Outcome

Freeze the architecture for one runtime-owned `asb-orchestrator` service that
authorizes every benchmark attempt. CLI, TUI, and other frontends submit only
validated declarative run requests; they never construct credentials, provider
targets, namespaces, relays, leases, sandbox backends, launch tokens, or live
attempts. The service owns admission, authority acquisition, lifecycle,
journaling, recovery, and teardown for local mock, strict replay, and optional
live-provider modes.

## Design boundaries

- Keep `asb-control` as the versioned frontend transport and keep `asb-runtime`
  as the process/sandbox primitive layer. The orchestration service sits above
  them and is the sole authority boundary.
- Introduce a Rust `asb-orchestrator` crate with no shell, dynamic-library
  plugin, floating dependency, credential persistence, or implicit network.
- A request contains stable agent/provider/workload identifiers, immutable
  revision and policy digests, mode, resource limits, and bounded deadlines.
  Paths and secret bytes are resolved only from enrolled runtime state.
- Model `AdmittedRun`, `PreparedAttempt`, `RunningAttempt`, `CollectingAttempt`,
  terminal outcomes, and `NeedsReconciliation` as closed state machines.
- Define opaque service-owned `RunHandle`, `AttemptHandle`, and capability
  handles. The service creates the local mock/replay authority and the optional
  live authority; callers can only request cancellation, status, and bounded
  result pages.
- Persist intent before effects and outcomes after effects through the existing
  store/journal contracts. Recovery must inspect processes, leases, relays, and
  artifacts before retrying an attempt.
- Preserve `NetworkPolicy::Deny` for local/replay modes. Live mode requires an
  enrolled credential reference, concrete allowlisted target, runtime-observed
  namespace/relay, sandbox/backend attestation, lease, launch token, and one
  per-attempt live capability. External reachability remains optional evidence,
  never a CI prerequisite.

## Required artifacts

1. Architecture decision record and authority matrix covering CLI, control,
   orchestrator, runtime, agents, replay, workloads, store, and adapters.
2. Versioned request/response/event schemas with unknown-field rejection,
   bounded frames, idempotency keys, cancellation fencing, and privacy rules.
3. State-transition and failure/recovery diagrams, including stale handles,
   duplicate requests, crash between intent/effect, and cancellation races.
4. Threat model proving no caller-supplied authority, credential disclosure,
   direct/alternate egress, lease reuse, or namespace substitution.
5. Migration map from current CLI injection seams and `LiveLaunchFactory` to
   the service-owned API, with compatibility and deprecation boundaries.

## Acceptance

- Independent review accepts the ownership matrix and migration design.
- Positive and hostile contract tests cover admission, unknown fields, stale
  handles, duplicate idempotency keys, cancellation, recovery, and privacy.
- The design explicitly supports container/VM execution where host semantics
  differ and does not require a specific native host.
- No existing local-mock, replay, or fail-closed security gate is weakened.
