# AR-1266: Authenticated replay dispatch context

## Outcome

Add the missing authenticated runtime-to-CLI dispatch boundary so the actual `replay` command can
consume runtime-issued strict-replay launch context without fabricating readiness, endpoint,
commands, leases, or authority digests.

## Dependencies and ownership

Dependencies: AR-1237, AR-1238, AR-1239. AR-1265 is preserved as design evidence but its partial
unmerged branch is not an input. Owned paths: ASB CLI dispatch, runtime context types, strict-replay
schemas/fixtures, and focused lifecycle tests. Branch:
`feature/ar-1266-authenticated-replay-dispatch`. Worktree:
`agent-systems-benchmark-ar-1266-authenticated-replay`.

## Work sequence

1. Define a runtime-issued, authenticated opaque dispatch context whose authority cannot be built
   from caller booleans, paths, endpoint strings, or digest values. Bind it to one command request.
2. Change the real ASB CLI replay dispatch path to require and consume that context; reject absent,
   stale, duplicate, mismatched, or forged context before any child or sidecar starts.
3. Exercise real bounded cassette request/response through the command path, provider and descendant
   egress denial, cancellation/restart, timeout/crash cleanup, and no-live-fallback behavior.
4. Run focused repeats, full locked offline workspace gates, schema/policy/privacy/signature/DCO
   checks, independent exact-head review, PR CI, signed protected merge, and all post-merge gates.

## Acceptance criteria

The actual replay command launches only from runtime-issued context and supervises the complete
replay lifecycle. No CLI metadata path claims readiness or fabricates authority; all rejection and
cleanup cases are bounded, fail-closed, and durably evidenced.
