# AR-1227: Publish authenticated startup-readiness contract

## Outcome

Expose a versioned, authenticated ASB readiness projection that an independent frontend can
consume before startup routing. The projection must distinguish configured, unconfigured,
incomplete, unavailable, malformed, stale and unauthorized states without exposing paths,
credentials, provider values, prompts or raw diagnostics.

## Dependencies and ownership

Dependencies: AR-1060, AR-1151 and AR-1160. Repository: `martin-beck/agent-systems-benchmark`.
Owned paths: ASB CLI/control protocol, readiness schema and fixtures, server-side validation and
tests. All Ratatui, TUI state, rendering, terminal handling and application startup routing remain
in `martin-beck/asb-tui`.

## Work sequence

1. Choose one authenticated control operation or a structured `asb readiness --format json` command
   and reserve a versioned schema with closed enums and bounded response size.
2. Derive the projection from ASB's validated configuration/control source of truth; never infer
   readiness from local files, environment variables, process presence or cached frontend state.
3. Define fail-closed mappings for unavailable, malformed, stale, unauthorized, unknown-version,
   unknown-field and oversized responses. Keep authorization and freshness explicit.
4. Add canonical privacy-safe fixtures for every state, schema-conformance tests, deterministic exit
   and output tests, retry/reconnect tests, and authenticated peer/identity checks.
5. Publish the immutable schema/fixture revision and integration instructions for asb-tui's
   `ReadinessProvider`; do not implement TUI rendering or wizard behavior here.
6. Run focused and full locked Rust/CLI/control, privacy, signature/DCO, exact-head CI and
   post-merge verification before promoting this AR.

## Acceptance criteria

- An authenticated independent client can obtain one bounded readiness response from ASB.
- Configured, unconfigured and incomplete are explicit; unsafe/unknown states never claim ready.
- No response or diagnostic contains credentials, secret-like values, host paths or raw payloads.
- Schema, fixtures, compatibility behavior and exact revision are documented and tested.
- The contract is sufficient for asb-tui to wire both ordinary and broker startup without duplicating
  ASB truth, while all actual TUI behavior remains standalone.

## Evidence and completion

Record exact schema/fixture revision, focused/full gates, independent immutable-head review,
hosted CI and post-merge results. Do not mark complete based on a mock provider alone.
