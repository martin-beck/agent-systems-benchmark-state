# AR-0909: Harden mini-SWE cancellation reap test isolation

## Outcome

Make the mini-SWE owned-descendant cancellation test deterministic under ordinary, parallel and
Repository Quality coverage execution while preserving production cancellation, process-group
termination, timeout and reaping behavior byte-for-byte unless a separately reviewed product defect
is independently reproduced.

## Dependencies and ownership

Dependencies: completed AR-0101, AR-0102, AR-0103, AR-0308 and AR-0902.

Owned product path:

- `crates/asb-agents/src/mini_swe.rs`, embedded `#[cfg(test)]` support and tests only

Do not alter production mini-SWE process launch/cancel/wait logic, `asb-runtime`, Cargo manifests,
schemas, workflows, other adapters or replay fixtures without a separate scope amendment and
independent evidence. This AR must not weaken a liveness/reaping assertion merely to make CI green.

## Investigation and implementation

1. Reproduce the exact PR #126 failure with pinned Rust 1.93.0 and cargo-llvm-cov 0.9.0, then repeat
   it under serial and bounded parallel stress. Record whether the retained `/proc` identity is a
   live descendant, zombie awaiting its actual parent or init, PID reuse, or an isolation collision.
2. Bind observations to PID plus Linux `/proc/<pid>/stat` start time and process group/session
   identity. A recycled PID must not be treated as the original child, and disappearance alone must
   not conceal a still-live owned process group.
3. Use an atomically unique, private, canonical, repository-disjoint test root. Reject stale paths,
   symlinked ancestors/leaves, unsafe ownership or mode, and path replacement without deleting an
   unrelated tree.
4. Synchronize helper readiness and cancellation with bounded explicit evidence rather than timing
   guesses. Retain the exact terminal `Cancelled` assertion and prove no runnable owned descendant
   remains before cleanup.
5. If the original child can remain a zombie that the ASB process cannot legally reap, distinguish
   that kernel state without claiming ASB reaped a non-child. Keep the test name/claim honest, or
   arrange the controlled helper parent to reap its child before termination. Any changed lifecycle
   claim requires independent review.

## Negative and stress evidence

- Reject missing, malformed, oversized, reused and changed-start-time PID evidence before polling
  or signalling any process.
- Exercise live descendant, zombie, prompt disappearance and simulated PID-reuse classifications;
  only the original runnable owned identity is a cancellation failure.
- Prove non-owned process/session identities are never signalled, waited on or credited as reaped.
- Run concurrent test subprocesses sharing one configured external base without root collision or
  cross-cleanup; inject stale roots, ancestor/leaf symlinks and cleanup replacement.
- Exercise bounded timeout and cancellation races repeatedly under the exact coverage command; all
  failures must be generic and must not expose paths, process command lines, environment or content.

## Gates and acceptance

Run the focused mini-SWE cancellation test serially and in bounded parallel subprocesses; all
mini-SWE unit/boundary/replay tests; exact Repository Quality workspace and critical-package
coverage floors; full locked workspace format, Clippy, tests, rustdoc and release build; failure,
fault and contract gates; repository policy, source headers, privacy and Gitleaks; immutable scope,
SSH-signature and DCO review; exact-head CI and post-merge exact-main verification.

Acceptance requires deterministic, identity-bound evidence that cancellation reaches terminal
`Cancelled`, no original runnable descendant/process group survives, PID reuse cannot create a
false result, every created test root is private and independently owned, and cleanup never removes
a substituted tree. The exact PR #126 coverage failure must be reproduced or honestly classified as
unreproduced/flaky with repeated evidence. Production lifecycle behavior remains unchanged unless a
separate product repair is justified and authorized.

## Evidence limits

Linux `/proc` test evidence does not prove non-Linux behavior, distributed reaping, arbitrary init
latency or kernel-failure recovery. A zombie owned by another reaper is not a runnable descendant,
but it is also not evidence that ASB reaped that process; documentation and test names must preserve
that distinction.
