# AR-1033: Establish the professional TUI visual system

## Outcome

Give the standalone application a coherent high-fidelity visual language that remains legible,
responsive and honest across terminal capabilities.

## Dependencies and ownership

Dependencies: AR-1010 and AR-1025. Repository: `martin-beck/asb-tui` only. Owned paths are Ratatui
theme/layout primitives, reusable presentation widgets, visual tokens, responsive rules, accessible
text equivalents and snapshot galleries. No ASB source or protocol semantics are owned.
Branch: `feature/tui-visual-system`. Worktree:
`agent-systems-benchmark-asb-tui-visual-system`.

## Work sequence

1. Define spacing, borders, typography hierarchy, focus/selection/status semantics and restrained
   color tokens for dark, light, high-contrast and NO_COLOR modes.
2. Build reusable header, breadcrumb, status badge, list/table, detail panel, empty/loading/error,
   progress and confirmation components without embedding benchmark business logic.
3. Specify compact/standard/wide breakpoints, truncation/wrapping, scroll indicators and minimum
   viable tiny-terminal behavior; preserve labels and numeric equivalents when decoration drops.
4. Use color and symbols only redundantly. Validate contrast, Unicode width/fallback behavior,
   focus visibility, flicker-free redraw and deterministic layout.
5. Produce a sanitized snapshot matrix and visual-review checklist covering every reusable state.

## Acceptance criteria

Screens look cohesive and production-grade rather than like raw debug widgets; focus, warnings,
success, stale data and disabled actions are immediately distinguishable without color alone; and
all supported widths/themes have stable unclipped text equivalents.

## Evidence

Record exact TestBackend snapshots, theme/contrast checks, Unicode-width and tiny-terminal tests,
resize/flicker probes, sanitized visual gallery, independent visual/accessibility review, exact-head
CI and post-merge verification.
