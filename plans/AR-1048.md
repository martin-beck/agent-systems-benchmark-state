# AR-1048: Make tmux window-option setup portable

## Outcome

Restore trusted-main terminal qualification after exact merge `f5434c938883b4f756f525038dc1b6e6c0a90761`
proved that the ambiguous `set-option` form for `remain-on-exit` is not portable across the
supported tmux installations. Configure the exact first window explicitly and retain the complete
AR-1042/AR-1044 readiness and cleanup trust boundary.

## Scope and ownership

`agent-systems-benchmark-asb-tui-tmux-window-option-portability`. No renderer, application,

## Failure evidence and invariant

Trusted-main run 34553880557 at exact merge `f5434c938883b4f756f525038dc1b6e6c0a90761`
completed 17 of 21 terminal tests successfully, while all four tmux integration tests failed at
`set-option -t <session> remain-on-exit on`. `remain-on-exit` is a window option; the harness must
use the unambiguous `set-window-option -t <session>:0 remain-on-exit on` shape. Failure diagnostics
must remain bounded and sanitized, and the harness must preserve exact private-socket, server
generation, pane/TTY/foreground-group, pre-TERM/pre-KILL revalidation, and no-manual-unlink safety.

1. Extract or centralize the exact window target and command shape so every tmux fixture uses
   `set-window-option -t <session>:0 remain-on-exit on`.
2. Add deterministic command-shape coverage that rejects the ambiguous session-option form and
   proves the exact window target. Add an actual local compatibility probe where tmux is available.
3. On setup failure, capture only bounded output and render a closed sanitized diagnostic; never
   expose paths, socket names, session names, environment values, or raw tmux output.
4. Run repeated focused terminal suites with exact-process/private-socket leak checks, then all
   applicable format, lint, locked test, documentation, release, supply-chain, coverage, schema,
   provenance, shell/workflow, privacy and clean-tree gates.
5. Freeze a signed+DCO test-only commit, obtain immutable different-agent review and exact-head CI,
   then await merge authorization. After exact reviewed-tree integration, require both post-merge
   workflows and trusted-main terminal qualification to pass before AR-1048, AR-1044, AR-1042 or
   AR-1010 can be accepted.

## Acceptance
