# AR-1151: Integrate strict offline replay and defaults

## Outcome

Run real agents and tools from exact cassettes with provider networking denied and no fallback.

## Dependencies and ownership

Dependencies: AR-0505 and AR-1150; AR-0502 through AR-0504 are transitive and AR-1100 is reached through the launch chain. Repository: `martin-beck/agent-systems-benchmark`. Owned paths: strict replay execution, network denial, cassette selection, offline defaults, coverage matrix and conformance.
Branch: `feature/ar-1151`. Worktree: `agent-systems-benchmark-ar-1151`.

## Work sequence

1. Select only exact agent/provider/model/settings/workload/tool-compatible cassettes.
2. Launch the real agent and workload tools against the strict local replay service and fail unmatched requests immediately.
3. Deny provider egress and prohibit live fallback under every error and recovery path.
4. Allow next-run offline defaults only when every requested tuple has complete current coverage.
5. Qualify all seven current workloads, concurrency, pacing, corruption, cancellation and report labeling.

## Acceptance criteria

A fully covered next run works without calling the provider; incomplete coverage fails before execution, and strict replay is never reported as fresh model-quality evidence.

## Evidence and completion

Record bounded public fixtures, exact schema and repository identities, focused/full gates, privacy scans, independent immutable-head review, exact-head CI and post-merge verification. Never publish credentials, prompts, responses, private paths, host identities or raw logs.
