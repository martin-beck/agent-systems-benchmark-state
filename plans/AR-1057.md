# AR-1057: Harden asb-tui control v1.3 readiness

## Outcome

Make the standalone asb-tui client and measurement-selection UX explicitly consume ASB's additive
control v1.3 validation diagnostics while preserving a safe, less-specific v1.2 fallback. Keep the
wire client in AR-1025 and all selector presentation/interactions in AR-1014.

## Scope and ownership

Repository: `martin-beck/agent-systems-benchmark-state` only. Owned paths are this task and plan,
the AR-1025 and AR-1014 task/plan records, and generated state views. No path in
`martin-beck/agent-systems-benchmark` or `martin-beck/asb-tui` may change. AR-1025, AR-1014,
AR-1037 and their dependencies retain their existing nonterminal status and owner.

The schema reservation identifiers are branch `docs/asb-tui-control-v1-3-readiness` and worktree
key `agent-systems-benchmark-state-asb-tui-control-v1-3-readiness`. This state-only audit creates no
product branch or worktree.

## Verified contract facts

The clean signed ASB AR-1037 candidate is
`5093a96108f41a13d26f7dedef113c38c8848938`, tree
`a370fe3c81706c80a966ab37d22f80247543a8d3`, based directly on live ASB main
`229f5ae6e2991cf2bbcf4bfe6a715ca44645af7e`. It adds exact selectable control versions 1.0, 1.2
and 1.3; 1.1 remains types-only and future 1.4 is unsupported. The checked-in v1.0 and v1.2 request,
response and fixture bytes are unchanged from the base. Their server projection retains only
`invalid_format`, `unsupported_capability`, `unverified_component` and `invalid_resource_bound`,
and omits `measurement_issue`.

Control v1.3 adds one closed `measurement_issue` to failed-settings failures. It contains an exact
`MeasurementSelectionReason` and an optional identity only when the identity came from the trusted
catalog. Unknown caller-controlled IDs are never copied. Runtime validation requires the precise
issue category to agree with the reason, rejects detail on valid responses, bounds and validates an
optional ID, rejects an ID for `unknown_id`, and rejects v1.3-only categories or detail on a v1.0 or
v1.2 connection. The candidate is local and unmerged; consumers must bind its exact schemas and
fixtures only after governed integration, exact-head CI and post-merge verification.

## AR-1025 client contract

Add AR-1037 as an explicit dependency. The standalone wire client must offer the exact implemented
set `{1.0, 1.2, 1.3}`, select 1.3 with a current runner, accept an exact 1.2 downgrade for catalog
and generic validation, and treat 1.0 as incapable of measurement-catalog selection. It must reject
1.1, future/unknown versions, a selected version it did not offer, and any response shape not valid
for the negotiated version.

Implement separate closed decoders generated or reproduced from the exact published v1.0, v1.2 and
v1.3 schemas without an ASB Cargo/path dependency. On v1.3, require exact consistency between the
legacy-compatible issue category, precise reason and optional safe catalog ID. On v1.2, accept only
the four byte-stable legacy categories and no detail. Preserve these downgrade projections:

- source-unqualified becomes `unverified_component`;
- mode, platform, permission and target-scope failures become `unsupported_capability`;
- cadence presence, minimum and capacity failures become `invalid_resource_bound`;
- schema, catalog/selection digest, cardinality, ordering, duplicate, unknown and malformed failures
  become `invalid_format`.

Tests must use exact cross-repository schema/fixture digests and synthetic peers for successful 1.3,
1.2 downgrade and 1.0 negotiation; 1.1/future/mismatched selection; v1.3 fields or categories sent
under v1.2; unknown fields; contradictory valid/issues/reason/category; unsafe, oversized and unknown
caller IDs; every fallback category; truncation/frame bounds; and disconnect/reconnect. Parsing must
not render UI, mutate a selection or launch a plan.

## AR-1014 validation UX contract

Require v1.3 support for precise measurement-validation UX. When 1.3 is negotiated, map every exact
reason to a stable actionable message, and focus or annotate an optional ID only after confirming it
exists in the currently authenticated catalog. `unknown_id` and all global failures have no echoed
ID and remain page-level. Contradictory or unsafe detail is a protocol failure, never display text.

Retain a v1.2 fallback mode because it still supplies the authoritative catalog. Display only its
generic stable category and explicitly state that the runner did not provide per-measure precision;
never infer a reason or culprit ID. A v1.0 connection disables the selector with the closed
measurement-catalog-unavailable reason. Catalog-generation/digest failures require refresh and
explicit revalidation; no response may silently add, remove, reorder, substitute or re-enable a
selection.

Add deterministic fixtures for all precise reasons, catalog-owned and global details, unknown-ID
non-reflection, malicious/oversized ID rejection, category/reason mismatch, stale-catalog refresh,
v1.2 category fallbacks, v1.0 disablement, focus retention/fallback and privacy-safe plain/NO_COLOR
text. Exact v1.2 and v1.3 validation of the same invalid draft must differ only by the permitted
diagnostic precision; both block launch and preserve the draft.
