# AR-1325: Support a shared OpenRouter provider

## Outcome

Configure every compatible ASB agent adapter against one pinned OpenRouter
provider profile built on the reviewed AR-0310 common contract, with an exact
endpoint identity, a dated model snapshot, bounded transport, and a
credential-free `OPENROUTER_API_KEY` reference.

## Dependencies and ownership

Dependencies: AR-0310 (common provider profile contract) and AR-0318
(credential-reference boundary), both done. Owned paths: the OpenRouter provider
profile, its endpoint/model/settings pinning, transport bounds, credential
reference resolution, and provider-specific documentation. Branch:
`feature/ar-1325-provider-openrouter`. Worktree:
`agent-systems-benchmark-ar-1325-provider-openrouter`.

## Work sequence

1. Pin the OpenRouter endpoint identity (`https://openrouter.ai/api/v1`),
   API mode, a dated model snapshot rather than a moving alias, sampling
   defaults, and transport bounds without embedding any credential.
2. Express the profile through the reviewed `ProviderProfileV1` contract with
   `ProviderKind::OpenAiCompatible` placement and the environment credential
   source bound to the `OPENROUTER_API_KEY` reference digest.
3. Verify redacted request observations against a disposable synthetic
   OpenRouter-compatible service: model, settings, streaming, tool calls,
   retries, cancellation, and secret non-disclosure.
4. Test absent credentials, unsupported settings, malformed responses, endpoint
   mismatch, cancellation, and credential redaction; every negative case fails
   closed.
5. Record the exact endpoint/model digests, licenses, and the per-agent
   support/limitation boundary as immutable evidence.

## Acceptance criteria

The profile carries no credential and resolves secrets only through the
`OPENROUTER_API_KEY` reference; the model is a pinned dated snapshot; the
endpoint identity cannot be confused with the public OpenAI profile; partial or
lossy translations are rejected before launch; and real provider connections
are opt-in and never required for offline CI.

## Evidence and completion

Record pinned endpoint/model/settings digests, redacted request-field
observations, immutable commits, independent review, exact-head CI, and the
unsupported-combination matrix. README claims alone are insufficient.
