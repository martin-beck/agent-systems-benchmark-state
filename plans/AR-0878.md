# AR-0878: Qualify immutable TLA tool provenance

## Outcome

Produce one independently verifiable, license-complete origin for the exact TLA+ tool consumed by
ASB formal checks. Prefer an authoritative immutable upstream release publication. If upstream
cannot provide one, build from an exact reviewed source commit with a closed, pinned toolchain and
dependency graph, demonstrate deterministic byte output, and publish only the resulting digest and
public provenance for AR-0877 integration. Mutable or continuously replaced prerelease assets do
not qualify.

## Qualification sequence

1. Ask for or discover an authoritative upstream TLA+ v1.8.0 final release publication. Bind the
   canonical project/repository, exact tag and signed or otherwise authenticated source commit,
   release metadata, stable asset name and URL policy, creation time, byte length, SHA-256 and MIT
   license. Re-fetch at separated times and require identical metadata and bytes. A prerelease asset
   that is deleted or replaced fails this branch.
2. If no qualifying immutable publication exists, freeze the exact source commit and source archive
   digest plus every included license/notice. Pin the build OS/container image digest, architecture,
   JDK vendor/version/archive digest, Gradle wrapper/distribution digest, build command, locale,
   timezone, environment allowlist, archive timestamps/order/modes, and the complete dependency
   lock with repository URLs and artifact digests. No ambient plugin, repository, network, or cache
   input is allowed.
3. Acquire every source/tool/dependency artifact into a bounded provenance cache using authoritative
   HTTPS origins, then perform the actual build with network denied. Verify all inputs before build,
   reject symlinks/path escapes/duplicates and ensure the build writes only under a new private
   scratch root.
4. Build at least twice from clean independent scratch/cache copies and require byte-identical JARs.
   Where upstream packaging embeds nondeterministic metadata, normalize only through a reviewed,
   documented deterministic packaging step that preserves classes/resources/licenses; never bless
   one machine's opaque output. Record output size, SHA-256, archive-entry manifest and license.
5. Run the resulting JAR against ASB's positive `Recovery.tla` model and require successful bounded
   completion. Run `RecoveryStaleMutation.tla` and require the exact
   `Invariant StaleEventsFenced is violated` failure. Also retain Alloy positive/mutation evidence so
   the formal lane is not reduced to a Java startup test.
6. Deliver a small verifier contract that AR-0877 can consume without trusting this worktree: exact
   manifest version, source/build-input/output digests, license and support limits. AR-0877 remains
   responsible for workflow URL/cache integration after independent review.

## Negative, privacy and reproducibility tests

- Mutate source repository/commit/tag/archive digest, license/notice, JDK or Gradle identity,
  dependency coordinate/repository/digest, container image, environment allowlist, build flags,
  output size/digest, archive entries and verifier version independently; every mutation fails.
- Reject branch heads, moving tags, GitHub asset IDs without durable release guarantees, community
  mirrors, unpinned Maven metadata, dynamic dependency versions, hidden local caches, network use
  during build, timestamps outside the canonical epoch, duplicate ZIP entries and path traversal.
- Exercise missing/corrupt/oversized input, 404/403/429/5xx acquisition, partial cache, concurrent
  build, cancellation and cleanup. Failed builds cannot publish or replace an accepted output.
- Seed secret-shaped values and private paths in environment, cache roots, Gradle properties,
  diagnostics and failures. Assert manifests, logs, receipts, fixtures and errors expose neither.
- Prove repeated clean builds on every claimed architecture are byte-identical. If cross-architecture
  identity is not achieved, restrict the supported build architecture explicitly and require the
  resulting JAR to remain platform-independent under positive/mutation execution evidence.

## Acceptance criteria

- One path is proven: either an authoritative immutable upstream artifact remains retrievable with
  stable exact provenance, or two clean source builds produce the same exact JAR bytes from the
  fully pinned and license-audited closure. A mutable prerelease URL alone is never sufficient.
- The source/build manifest is closed, bounded, offline-verifiable and mechanically binds exact
  source commit, all toolchain/dependency inputs, licenses, deterministic packaging and output
  size/SHA-256. The build itself performs no network access.
- The exact output passes TLC positive recovery and the deliberate stale-epoch mutation fails for
  the expected invariant; the Alloy positive/mutation lane also remains green.
- Hostile provenance/build/cache mutations fail closed, concurrent or cancelled builds leave no
  accepted partial, privacy scans are clean, and source-tree cleanliness is preserved.
- Focused provenance/verifier tests, ShellCheck, repository policy, privacy/Gitleaks, dependency
  audit, reproducibility repeats, full formal gates, immutable review and exact-head CI pass. Only
  then may AR-0877 integrate the manifest under its separate workflow fence.

## Evidence limits

An authoritative publication proves publisher provenance and byte identity, not reproducibility.
A deterministic source build proves the declared closure reproduces one JAR, not that upstream
endorses it or that TLA+ is correct. TLC/Alloy results remain bounded model evidence. No native,
platform-wide, or unbounded formal claim follows from this AR.
