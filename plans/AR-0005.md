# AR-0005: Add transactional AR promotion

## Outcome

Provide a first-class `handoffctl promote` transition so coordinators never need to edit task source
outside the same transaction that regenerates and validates `CURRENT.md` and `STATUS.md`.

## Dependencies and ownership

Dependencies: AR-0002 and AR-0004.
Owned paths: state-repository handoffctl, schemas where required, coordinator tests, and coordination docs.
Branch: feature/transactional-promotion. Worktree: agent-systems-benchmark-state-promotion.
One worker owns this task; generated-view and state-schema edits are serialized by the coordinator.

## Acceptance criteria

- A documented `handoffctl promote AR-NNNN --expected-revision N --note TEXT` atomically changes only a
  dependency-ready inactive `planned` task to `open`, increments its revision, timestamps and records
  the transition, regenerates both public task views, validates, creates a signed DCO state commit, and
  replicates it using the existing durable-push semantics.
- Missing dependencies, stale revisions, active claims, invalid source/generated state, dirty overlapping
  state, or an invalid transition fail closed without a partial task/view commit.
- Concurrent reconcile, claim, update, release, render, and promote processes cannot publish source/view
  skew or lose a transition. Deterministic fault injection covers failures before write, after task write,
  during rendering/validation/commit, and after a durable commit but before/during replication.
- Tests verify successful automatic status-document regeneration and graphical dependency updates, not
  merely task metadata.
- README and development documentation replace the manual promotion procedure and specify retry/recovery
  rules after an ambiguous interruption.

## Required evidence

Run the complete state schema, static type/lint, branch-aware coverage, fault/conformance, privacy,
signature/DCO, generated-state, live doctor, concurrency, and controlled failure checks. Record exact
commits and test results without private runtime configuration or raw coordination history.
