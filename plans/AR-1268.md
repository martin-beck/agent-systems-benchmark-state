# AR-1268: Break strict-replay runtime/CLI dependency cycle

## Outcome

Provide a small dependency-safe runtime-to-CLI transport contract so runtime-owned strict-replay
launch context can carry immutable cassette execution inputs without the runtime importing CLI or
agent implementation types.

## Dependencies and ownership

Dependencies: AR-1237, AR-1238, AR-1239. AR-1267 is blocked design evidence and its unmerged branch
is not an input. Owned paths: shared ASB contract types or runtime transport boundary, crate
manifests, runtime/CLI adapters, schemas/fixtures, and contract tests. Branch:
`feature/ar-1268-replay-transport-boundary`. Worktree:
`agent-systems-benchmark-ar-1268-replay-transport`.

## Work sequence

1. Map the current crate dependency graph and define the minimum opaque, versioned transport
   contract. Runtime must issue authenticated context; CLI must not supply readiness, endpoint,
   command, lease, isolation, or digest authority.
2. Move or introduce only dependency-neutral request/response, cassette identity, and launch-context
   types needed by both sides; reject unknown/forged fields and preserve zero-runtime dependencies.
3. Add positive/negative contract tests proving one-shot consumption, stale/duplicate/route mismatch,
   malformed cassette, no-fallback, and bounded serialization behavior.
4. Integrate the boundary into the actual replay dispatch path, then run full locked offline gates,
   independent review, exact-head CI, signed merge, and post-merge assurance.

## Acceptance criteria

The runtime can issue and retain all launch authority without importing CLI/agent types; the actual
CLI replay path consumes that context through the shared contract, with no dependency cycle or
caller fabrication. Contract and privacy/schema/signature/DCO evidence is complete.
