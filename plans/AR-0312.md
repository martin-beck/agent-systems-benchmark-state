# AR-0312: Support a shared local Ollama provider

## Outcome

Configure every compatible ASB agent adapter against one pinned, local Ollama model and normalized settings.

## Dependencies and ownership

Dependencies: AR-0301 through AR-0310 as listed in the task metadata.
Owned paths: Ollama provider profile, adapter translations, local probes, fixtures, and provider-specific documentation.
Branch: `feature/provider-ollama`. Worktree: `agent-systems-benchmark-provider-ollama`.

## Work sequence

1. Pin Ollama server/model identity, content digest, API mode, context, sampling, reasoning, keep-alive, and concurrency semantics.
2. Require loopback by default and explicitly negotiate native Ollama versus OpenAI-compatible adapter paths.
3. Observe actual effective requests for each agent; reject ignored, renamed, or lossy settings.
4. Test missing model, changed model digest, unavailable daemon, incompatible API mode, remote bind, cancellation, overload, and secret/log redaction.
5. Run native x86_64/aarch64 and supported Linux checks where real Ollama binaries/models are available; label unavailable combinations honestly.

## Acceptance criteria

All supported agents use the identical pinned model content and normalized settings; ASB detects daemon/model drift before measurement; loopback is the safe default; no implicit model pull or network egress occurs during an offline run; partial configuration fails closed; and resource/model limitations are visible in the support matrix.

## Evidence and completion

Record binary/model digests, licenses, native platforms, immutable commits, reviews, exact-head CI, resource limits, and post-merge verification. Emulation cannot satisfy native evidence.
