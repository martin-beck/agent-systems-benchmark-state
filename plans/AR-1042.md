# AR-1042: Capture alternate-screen TUI readiness deterministically

## Outcome

Make standalone `asb-tui` tmux qualification observe the actual Ratatui alternate screen and emit
bounded actionable diagnostics, independent of ambient tmux configuration.

## Dependencies and ownership

Repository: `martin-beck/asb-tui` only. Owned paths are the tmux/screen PTY qualification helpers
and tests. Renderer behavior, user-facing screens, ASB source and protocol semantics are out of
scope. This repairs the exact AR-1010 post-merge failure on main `882c315e`.
Branch: `fix/tmux-alternate-screen-readiness`. Worktree:
`agent-systems-benchmark-asb-tui-tmux-alternate-screen-readiness`.

## Work sequence

1. Preserve both trusted-main failures from run 34546963576 and the exact tmux 3.4 correction:
   `capture-pane -p` observes the displayed live alternate frame while `-a` observes blank
   alternate-history storage when `alternate_on=1`.
2. Start the unique test server with explicit `-f /dev/null` before the command so user/global tmux
   configuration cannot change capture or alternate-screen semantics.
3. Poll `capture-pane -p` and require one bounded valid UTF-8 recognized `Connection` frame
   bracketed by exact `alternate_on=1` observations before and after capture. A pre-alternate,
   transitioned, oversized, malformed or non-UTF-8 observation is never readiness.
4. On timeout, report only bounded sanitized pane output plus exact `alternate_on`, `pane_dead`,
   `pane_dead_status` and `pane_current_command` fields. Bound every subprocess and output read and
   always kill the exact unique server/session.
5. Test pre-alternate, rendered, exited-before-render, timeout, malformed output and cleanup paths;
   run repeated focused and full parallel terminal suites, all local gates, exact-head hosted CI and
   trusted-main post-merge verification.

## Acceptance criteria and evidence

The probe detects a real frame only from alternate-screen content; clean-hosted and trusted local
environments agree; hostile ambient tmux configuration cannot affect the result; failures retain
bounded useful evidence without paths or environment data; no multiplexer process/socket leaks.
Require signed+DCO commits, immutable review, exact-head CI, exact tree/signature verification and
successful trusted-main post-merge qualification.
