# AR-1050: Acquire authenticated tmux startup readiness

## Outcome

Restore trusted-main terminal qualification by treating detached tmux creation and authenticated
server/session observability as separate asynchronous stages. Continue only after bounded evidence
proves one stable exact created server, session, immutable window and pane authority.

## Scope and ownership

Repository: martin-beck/asb-tui only. Owned path: tests/terminal_foundation.rs. Branch:
fix/tmux-authenticated-startup-readiness. Worktree:
agent-systems-benchmark-asb-tui-tmux-authenticated-startup-readiness. No renderer, application,
lifecycle protocol, dependencies, release semantics, workflow, or ASB source changes.

## Exact failure evidence

Trusted-main run 34556679585 at merge aacf672c018706ef8a361e1a2dd6c19d890f02d8
passed 19 of 24 terminal tests. All five live tmux fixtures reported
tmux_server_or_session_disappeared after bounded new-session succeeded but before window parsing or
option setup. Repository quality 34556679558 passed. The immediate server observation is therefore
not a valid startup synchronization boundary on the trusted runner.

## Readiness and cleanup invariants

1. Construct the privately scoped tmux session guard immediately after a successful creation status
   and before parsing creation output or probing further. Never infer readiness from elapsed time.
2. Poll only for a fixed number of short attempts. Acquire the exact socket device/inode/owner,
   server PID/start-time, unique session, and exact returned immutable @window identity through
   bounded commands. Require two consecutive complete equal observations. Any unavailable,
   malformed, mismatched or transitioning sample resets stability and can never authorize options.
3. Once the first authenticated server observation is available, retain it in the guard. If later
   observations disagree, fail closed: do not signal or kill the replacement. The private disposable
   root remains the only eventual stale-node cleanup authority.
4. Acquire and retain the exact pane PID/start-time, TTY identity and foreground group before
   invoking set-window-option. Existing pre-TERM and pre-KILL full-tuple revalidation remains
   mandatory.
5. Target only the exact observed @window ID. Immediately before option setup, require the stable
   server/session/window observation still matches. On failure expose only closed categories:
   tmux_startup_not_ready for bounded acquisition exhaustion, tmux_server_or_session_disappeared
   when previously authenticated authority is gone, and existing closed malformed/unsupported
   categories. Never expose raw output, paths, session names or environment values.

## Adversarial tests and gates

1. Inject observer sequences proving unavailable then two stable equal samples succeeds; single,
   alternating, transitioned, malformed and exhausted samples fail closed; no sleep is accepted as
   evidence.
2. Inject retained-authority transition/disappearance before option and prove zero option command
   and zero widened signalling. Preserve server/socket substitution and pre-TERM/pre-KILL negatives.
3. Exercise all live tmux fixtures, including malformed creation identity, HUP-resistant child and
   no-pane-authority unwind. Verify no exact process leaks after repeated complete serial suites.
4. Run all format, lint, locked test, documentation, release, supply-chain, coverage, schema,
   provenance, shell/workflow, privacy and clean-tree gates. Freeze signed+DCO for immutable review
   before push, then exact-head CI and authorized protected merge.
5. Verify exact reviewed merge tree/parent/signature/raw trailer and both post-merge workflows.
   Trusted-main must pass before AR-1050 or AR-1049/1048/1044/1042/1010 can be accepted.

## Acceptance

Every live tmux path proves two consecutive stable, bounded, authenticated server/session/window
observations and retains pane authority before option setup. Unavailable, transition, timeout and
disappearance paths remain closed and cleanup-safe. Repeated/full tests leak no owned process, and
exact-head plus trusted-main workflows pass. The diff is test-only, signed, DCO-compliant and
independently reviewed.
