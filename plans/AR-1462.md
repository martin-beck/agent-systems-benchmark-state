1. Read the complete product development, architecture, quality, release and
   coordination documentation. Work only from a clean isolated worktree at
   exact protected-main `36d4bdf35a644a36a8acfdb31078eb7f668a17c4` (or a later
   exact protected-main commit after a documented requalification).
2. Add a pinned, reproducible tool path for `cargo-deny` and `cargo-audit`.

3. Define a checked-in release manifest and bundle command/workflow that records
   the exact commit, version, source digest, file checksums, SBOM, provenance,

   prompts, transcripts or unbounded logs.

   existing handoff and CI boundaries. It must be idempotent and fail closed;

   external signing as optional. Verify the published tag/release and fresh
   downstream consumption from the exact commit. Never force-update a tag.
5. Run focused positive/negative tests, the full applicable test suite, format,
   clippy, rustdoc, coverage, formal and supply-chain gates. Publish a PR only
   from a clean exact tree, wait for exact-head CI, merge only when all required
   checks are green, and record post-merge evidence.
6. Rerun AR-1461 against the resulting exact protected-main commit. If any
   gate remains unavailable, release this AR blocked with the concrete command,
   exit status, and next action; do not fabricate a release or weaken a gate.

## Acceptance evidence

- pinned tool versions and offline setup are documented and tested;
- cargo-deny and cargo-audit pass in the supported runner/container;
- bundle manifest, SBOM, provenance and checksums are deterministic and
  independently verifiable;
- dirty/mismatched/duplicate-tag/privacy-invalid inputs fail with actionable
  errors;
- exact-head hosted checks are green and the public tag/release consumes the
  same commit, or the AR is truthfully blocked with preserved evidence;
- no asb-tui or remote-provider dependency was introduced.
