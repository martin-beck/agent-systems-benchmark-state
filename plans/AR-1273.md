# AR-1273: Complete runtime-owned replay request context

## Outcome

Create one opaque runtime-issued replay request context containing the authenticated launch record,
route/request identity, cassette-service handle, isolation capability, and lifecycle owner, so the
actual CLI command cannot substitute any execution authority or input.

## Dependencies and ownership

Dependencies: AR-1237, AR-1238, AR-1239. AR-1272 is blocked design evidence and its unmerged branch
is not an input. Owned paths: shared/runtime/CLI replay context contract, actual command dispatch,
and executable lifecycle fixtures/tests. Branch: `feature/ar-1273-complete-replay-context`.
Worktree: `agent-systems-benchmark-ar-1273-complete-replay-context`.

## Work sequence

1. Define bounded dependency-neutral request identity fields and an opaque runtime-issued context;
   reject caller paths, bytes, endpoints, routes, methods, leases, isolation, readiness, and
   provider fallback fields.
2. Have runtime issue the complete context only after attestation and launch-bundle validation;
   consume it exactly once in the actual replay command.
3. Execute real cassette request/response through the supervised sidecar and prove route/method/body
   parity, provider/descendant egress denial, no-live-fallback, cancellation/restart, timeout/crash
   reaping, cleanup/no leaks, stale/duplicate/forged/malformed rejection.
4. Run focused repeats, full locked offline gates, schema/policy/privacy/signature/DCO, independent
   review, exact-head CI, signed merge, and all post-merge assurance workflows.

## Acceptance criteria

The actual replay command accepts only runtime-issued complete context and performs real supervised
cassette traffic. No caller-provided execution authority remains, and all lifecycle/egress failure
paths are bounded and fail closed.
