# AR-1055: Harden asb-tui install integration readiness

## Outcome

Make the remaining path to an easy, verified `asb tui install` and complete interactive
cross-repository qualification explicit and dependency-executable. Retain AR-1026's end-to-end
interactive acceptance; do not reduce it to an application-shell test.

## Scope and ownership

Repository: `martin-beck/agent-systems-benchmark-state` only. Owned paths are this task and plan,
the AR-1026 task and plan records, and generated state views. No path in
`martin-beck/agent-systems-benchmark` or `martin-beck/asb-tui` may change. AR-1024, AR-1025,
AR-1026, AR-1029, AR-1011 and all focused UI feature tasks retain their existing status and owner.

The schema reservation identifiers are branch `docs/asb-tui-install-integration-readiness` and
worktree key `agent-systems-benchmark-state-asb-tui-install-integration-readiness`. This is a
state-only audit and intentionally creates no product branch or worktree.

## Required state correction

Add AR-1011 to AR-1026's dependencies. AR-1025 owns only the functional application shell after
roadmap hardening; AR-1011 transitively integrates AR-1014 and AR-1031 through AR-1035 and is the
first task that can satisfy AR-1026's retained full interactive benchmark, navigation,
accessibility and complete-screen acceptance. Keep AR-1024, AR-1025 and AR-1029 as dependencies.

Update AR-1026's next action and plan to state that qualification starts only after the router,
standalone shell, complete UI and legacy ASB renderer removal are done. The integration must then
bind exact commits, trees, schemas and release artifact digests; exercise install, status, launch,
doctor, upgrade, rollback and remove from clean unprivileged homes; prove native x86_64 and pinned
QEMU AArch64 routing plus unsupported-target rejection; and show atomic interrupted/concurrent
replacement keeps the prior verified active version. Removal must be idempotent, network-free and
must preserve ASB, configuration, run state and a running benchmark.

## AR-1024 executable next steps

After AR-1054 merges, exact-main Repository quality and Trusted main pass, and AR-1010 closes:

1. Rebase the AR-1024 patch onto exact current ASB main, resolve only current CLI/schema/provenance
   integration, retain a clean router-only delta, and correct signature/DCO metadata as required by
   current policy.
2. Freeze an exact qualified asb-tui commit/tree, replace the null interactive qualification pin,
   and verify the copied schema bytes still match. Do not pin a failed or source-only head.
3. Produce authorized reproducible release-mode x86_64 and AArch64 artifacts plus exact source,
   license, SPDX SBOM and provenance documents. Publish immutable versioned manifests and the
   signed stable-channel index only after their hosted and trusted exact-head gates pass.
4. Re-run the router's hostile signed-channel, artifact, expiry, downgrade, redirect, truncation,
   resume, symlink, permission, low-disk, clock, race and crash tests. Add real process-boundary
   install, upgrade, failed-activation rollback, repeated/idempotent removal, offline reuse and
   unsupported-platform coverage against the exact qualified binary; the existing local candidate
   has helper-level coverage but no installable release to prove this end to end.
5. Prove `asb tui install` performs one-command target selection and verified activation, while
   status, launch, doctor and remove are network-free. Verify that ASB contains lifecycle routing
   and protocol seams only—no Ratatui, Crossterm, renderer, widget, application state or terminal
   event-loop implementation.
