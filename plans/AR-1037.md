# AR-1037: Add measurement selection to validated run plans

## Outcome

Make standalone frontend measurement choices authoritative by carrying stable catalog IDs through
ASB's immutable run plan, validation, launch, collection and evidence records.

## Dependencies and ownership

Dependencies: AR-0104 and AR-1036. Repository: `martin-beck/agent-systems-benchmark` only. Owned
paths are runner/control plan types, schema and migrations, validation, deterministic hashing,
collector scheduling/filtering, journal/report provenance, CLI parity and public fixtures. No
Ratatui, Crossterm, renderer, search, grouping interaction, selector widget, navigation, help,
terminal lifecycle or frontend state path is owned. All visible selection behavior belongs to
AR-1014 in `martin-beck/asb-tui`.

Branch: `feature/measurement-selection-plan`. Worktree:
`agent-systems-benchmark-measurement-selection-plan`.

## Work sequence

1. Add a closed, versioned selection object to the immutable benchmark plan containing the exact
   AR-1036 catalog digest, a canonically sorted unique list of at most 128 stable measurement IDs,
   execution mode and any bounded sampling cadence required by the selected definitions.
2. Distinguish optional selectable collector measurements from mandatory run, outcome, integrity,
   scoring and provenance evidence. An empty optional selection is valid and must not disable or
   mislabel mandatory evidence.
3. Validate every selected ID against the exact catalog generation/digest, execution mode,
   platform, permissions, source qualification and cadence/overhead constraints before mutation.
   Unknown, duplicate, stale, unsupported, unavailable and incompatible selections fail closed with
   stable per-ID reasons; no fallback silently adds, removes or substitutes a measurement.
4. Bind canonical selection bytes into plan hashing, dry-run output, idempotency, launch requests,
   runner journals and report provenance. Define explicit migration behavior for plans created
   before the selection field and reject forward-unknown generations.
5. Make collection honor the validated set before source reads or sampling work whenever the source
   can be independently gated. Prove deselected metrics do not incur their collector work and that
   selection cannot change benchmark scheduling, agent inputs, scoring or mandatory evidence.
6. Publish CLI/import/export/control fixtures that the standalone consumer can validate read-only;
   any frontend parser or presentation changes remain in AR-1014.

## Acceptance criteria

An exact TUI choice can round-trip through ASB validation and launch without drift; plan hashes and
idempotency identities change deterministically with the canonical selected set; the runner records
exactly which optional measurements were requested, collected, unavailable or omitted; empty,
maximal and partial selections behave explicitly; unsupported or stale choices cannot launch; and
ASB contains no presentation or interaction implementation.

## Evidence

Record schema/migration fixtures, empty/one/group/maximal plans, ordering/duplicate/catalog-digest/
mode/platform/permission/cadence negatives, source-read sentinels for deselected measurements,
plan-hash and CLI/control parity, replay and journal recovery tests, performance-isolation probes,
full ASB quality/security/privacy/formal gates, independent protocol/runtime review, exact-head CI
and post-merge verification.
