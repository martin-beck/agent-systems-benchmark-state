# AR-1326: Select OpenRouter through the CLI provider catalog

## Outcome

Let a user select the reviewed AR-1325 OpenRouter profile through the closed
`asb provider-catalog` and `asb provider-plan` selection path and bind an
experiment plan to the pinned OpenRouter model identity, without weakening the
existing fail-closed content-address and selection checks.

## Dependencies and ownership

Dependencies: AR-0313 (all-agents provider selection, done) and AR-1325
(OpenRouter provider profile). Owned paths: `provider_catalog`,
`provider_catalog_digest`, `provider_plan`, `validate_provider_selection`,
selection-manifest handling, and provider-specific CLI documentation in the
ASB product. Branch: `feature/ar-1326-openrouter-catalog-selection`. Worktree:
`agent-systems-benchmark-ar-1326-openrouter-catalog-selection`.

## Work sequence

1. Add the `openrouter` entry with its pinned model and `environment`
   credential source to `provider_catalog` and fold it into
   `provider_catalog_digest` without leaking credentials or paths.
2. Accept `--provider-profile openrouter` in `provider_plan` and construct the
   canonical OpenRouter selection manifest with the exact profile/model/agent
   projections and the `OPENROUTER_API_KEY` credential reference digest.
3. Extend `validate_provider_selection` and the plan/experiment binding so a
   saved OpenRouter selection matches the experiment agent, provider, model,
   and `additional_settings_sha256` identity exactly.
4. Reject stale catalogs, altered selections, unsupported agents, and
   mismatched experiments before any run or provider contact; keep `openai`
   behavior unchanged.
5. Add CLI negative tests: stale/unknown profile, mixed selection, missing
   credential reference, and selection/experiment model mismatch.

## Acceptance criteria

`asb provider-plan --provider-profile openrouter` produces a dry-run selection
whose identity is stable and secret-free; plan/run/sweep accept the saved
selection only when the experiment matches every projection; the OpenRouter
selection cannot be confused with the OpenAI profile; and all existing OpenAI
behavior and content-address gates remain green.

## Evidence and completion

Record stable catalog/selection digests, negative and positive CLI fixtures,
immutable commits, independent review, exact-head CI, and post-merge
verification.
