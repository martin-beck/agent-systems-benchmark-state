# AR-1288: Runtime certificate issuance and chain validation

## Outcome

Close the certificate issuance and trust-chain gap identified by AR-0814 with an ASB-owned,
offline-testable certificate authority boundary. The result must issue short-lived runner
credentials only after an explicit enrollment ceremony and validate the complete chain before any
remote control mutation. This successor does not implement terminal UI screens or frontend flows.

## Dependencies and ownership

Dependency: AR-0813 (completed secure remote-control transport). AR-0814 is the parent protocol
contract and remains open until this successor's certificate/chain scope is integrated and reviewed.
Repository: `martin-beck/agent-systems-benchmark`. Owned paths: `crates/asb-control` certificate,
identity-store and authorization boundary code; `crates/asb-cli` enrollment/rotation/revocation
argument handling; versioned protocol schemas, docs and focused tests. No `asb-tui` paths, renderer,
terminal event handling, private keys, credentials, or runtime downloads.
Branch: `feature/ar-1288-certificate-chain-authz`; worktree:
`agent-systems-benchmark-ar-1288-certificate-chain-authz`.

## Work sequence

1. Audit the AR-0814 identity and authorization contract and freeze a versioned certificate
   issuance/import/rotation/revocation schema with strict unknown-field rejection.
2. Implement offline deterministic certificate-chain validation: pinned trust anchor, runner and
   controller identity constraints, validity/clock-skew bounds, key-usage/role constraints,
   revocation and generation binding, and fail-closed malformed/signature/issuer mismatches.
3. Implement a bounded issuance ceremony requiring the existing out-of-band fingerprint or
   one-time pairing, storing only privacy-safe digests and mode/owner-checked identity metadata.
   Never emit private key material or credentials in manifests, logs, audit records or errors.
4. Add positive and negative tests for valid chains, wrong issuer/anchor, expired/not-yet-valid,
   revoked, wrong role/IP binding, replayed pairing, rotation races, unknown fields and audit
   tampering. Run focused/full locked gates, independent review and exact-head CI before merge.

## Acceptance and boundaries

- Certificate issuance and import are runtime/CLI authority operations, not caller-provided trust
  flags; every mutation requires an authenticated, chain-validated identity and generation.
- Chain failures, unavailable trust stores, clock uncertainty, revocation races and malformed
  artifacts fail closed without network access or fallback trust.
- Identity files are regular, private, owner-checked, size-bounded and symlink-safe; only hashes,
  stable IDs and bounded audit outcomes are retained.
- Protocol schemas/docs and tests are updated; all applicable format, clippy, workspace, docs,
  policy/privacy, formal and portability gates pass with signed SSH+DCO commits and post-merge
  verification.
- No TUI implementation or UX is in scope; AR-0817 remains the standalone frontend owner.
