# AR-1203: Enable replay-mode `run`/`sweep` benchmarking

## Outcome

Remove the `run cannot use a replay plan` gate so `run`/`sweep` execute attempts through the
strict-replay sidecar when `controls.replay.mode == replay`, recording replay-labelled evidence in
the run store and supporting concurrency/sweep for replay headroom.

## Dependencies and ownership

Dependencies: AR-0204 (sweeps/arrival scheduling), AR-0401 (workloads), AR-1202 (replay authority
path). Repository: `martin-beck/agent-systems-benchmark` only. Owned paths are
`crates/asb-cli/src/lib.rs` `execute_inner`/`run_point_with_selection`, the runtime scheduler
launch path (replay variant), `asb-protocol` `ReplaySettings` validation (coordinator-fenced), and
store labelling of replay runs (`source`, `cassette_sha256`, pacing mode). Branch:
`feature/replay-run-sweep`. Worktree: `agent-systems-benchmark-replay-run-sweep`.

## Work sequence

1. Replace the hard rejection with a validated replay path: a replay plan must carry an exact
   `cassette_sha256` and a compatible provider selection; otherwise fail closed.
2. Per attempt, issue a `ReplayLaunchAuthority` for the cassette and run the workload through the
   loopback strict-replay sidecar exactly like AR-1202, under the scheduler (concurrency, queue,
   warmup, timeout, cancellation).
3. Persist replay evidence: mode, cassette digest, pacing, per-attempt outcome, metric samples, and
   a `comparable` label so `compare`/`report` can pair live vs replay.
4. Validate replay concurrency against `assess_replay_headroom`; record saturation points without
   claiming live model quality.
5. Keep live-mode behavior byte-identical (no regression).

## Acceptance criteria

`asb run`/`asb sweep` complete a workload under replay mode with correct quality/latency/resource
evidence and no provider contact; replay manifests and live manifests of the same workload are
comparable; replay headroom is measured and reported; invalid/absent cassette, mismatched profile
and exhausted cassettes fail closed.

## Evidence

Replay-mode run/sweep transcripts, headroom calibration, live-vs-replay comparison fixtures,
negative fixtures, exact-head CI.
