# AR-1341: Runtime-observed namespace attestation repair

## Outcome

Repair the merged AR-1340 live-provider handoff so a capability is accepted
only when the runtime observes the actual child network namespace and proves
that the relay handoff is bound to that namespace. A caller-supplied namespace
string is not an attestation. Preserve `NetworkPolicy::Deny` for all launches
unless the runtime-issued live capability passes this check.

## Dependencies and ownership

Dependency: AR-1339 (the merged runtime-owned relay backend). AR-1340 is the
security-hold context being repaired, not a dependency that may block the
repair. Owned paths are the runtime namespace handoff, sandbox
child-launch boundary, and focused denial/evidence tests. Do not modify
asb-tui, enable host networking, expose credentials, or weaken any existing
quality, formal, portability, fault, or exact-head gate.

## Work sequence

1. Compare `NamespaceIdentity::current()` (or an equivalent runtime-observed
   child identity) with the handoff identity immediately before the first live
   effect; fail closed if observation is unavailable or differs.
2. Ensure the bwrap/child launch path cannot substitute a copied, stale,
   replayed, or caller-forged capability. Bind the capability and endpoint
   only after the runtime identity check, and revoke it on teardown.
3. Add positive and negative tests for same-namespace acceptance, copied and
   mismatched identities, stale/expired handoffs, descendant direct-egress
   denial, and restart/teardown revocation. Evidence must contain digests and
   outcomes only, never credentials or private paths.
4. Independently review the complete diff, run focused and full workspace
   gates, publish a clean exact-head PR, wait for every required check, merge
   only when green, and verify post-merge workflows before releasing both the
   repair and AR-1340.

## Acceptance criteria

No live provider effect is possible without runtime-observed namespace
agreement. Caller-supplied identity, copied/stale capability, cross-namespace
handoff, expiry, cancellation, and descendant direct egress are denied.
Offline/default and strict-replay paths remain network-denied and receive no
live capability. All required checks and post-merge evidence are green.
