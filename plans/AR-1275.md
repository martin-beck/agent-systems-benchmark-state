# AR-1275: Runtime operation injection into replay dispatcher

## Outcome

Add an explicit runtime-owned operation-handle injection point to the actual ASB replay dispatcher,
so a strict cassette request is forwarded to the supervised runtime executor rather than merely
validated or reported as metadata.

## Dependencies and ownership

Dependencies: AR-1237, AR-1238, AR-1239. AR-1274 is blocked design evidence and its unmerged branch
is not an input. Owned paths: ASB CLI argument dispatch, runtime operation integration, cassette
fixtures, and executable lifecycle tests. Branch:
`feature/ar-1275-replay-operation-injection`. Worktree:
`agent-systems-benchmark-ar-1275-operation-injection`.

## Work sequence

1. Extend the replay dispatcher API with a required runtime-issued operation handle/context. Keep
   the legacy metadata-only path fail-closed or remove it; callers cannot inject providers,
   endpoints, readiness, leases, isolation, or cassette bytes as authority.
2. Forward bounded request envelopes to the runtime executor and decode validated response envelopes
   into strict replay output through the actual command path.
3. Add executable credential-free cassette request/response tests plus provider/descendant egress
   denial, no-live-fallback, cancellation/restart, timeout/crash reaping, stale/duplicate/malformed
   rejection, and cleanup/no-leak evidence.
4. Run full locked offline gates, policy/privacy/schema/signature/DCO, independent review, exact-head
   CI, signed merge, and all post-merge assurance workflows.

## Acceptance criteria

The real replay command cannot run without a runtime-issued operation handle and performs supervised
cassette traffic with bounded fail-closed lifecycle and egress behavior. No metadata-only substitute
or caller-fabricated authority remains.
