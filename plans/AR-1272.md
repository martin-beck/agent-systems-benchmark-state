# AR-1272: Authenticated immutable cassette backend

## Outcome

Provide a dependency-safe runtime cassette backend handle that binds immutable cassette content to
the authenticated service identity, allowing real request/response execution without importing
`asb-replay` implementation types into the runtime.

## Dependencies and ownership

Dependencies: AR-1237, AR-1238, AR-1239. AR-1271 is blocked design evidence and its unmerged branch
is not an input. Owned paths: shared cassette-content transport, runtime backend handle, CLI/replay
adapter, and executable lifecycle fixtures/tests. Branch:
`feature/ar-1272-authenticated-cassette-backend`. Worktree:
`agent-systems-benchmark-ar-1272-cassette-backend`.

## Work sequence

1. Define a bounded immutable cassette-content reference/transfer contract with digest, generation,
   route identity, size and schema; reject mutable paths, symlinks, credentials, unknown fields,
   stale/duplicate handles, and live-provider fallback.
2. Issue the backend handle only from runtime-owned attested context and bind it to the launch bundle
   and operation transport. Keep runtime independent of CLI/agent/replay crates.
3. Implement CLI decoding into strict replay service behavior and run the actual replay command with
   a credential-free cassette. Prove response parity, provider/descendant egress denial,
   cancellation/restart, timeout/crash reaping, cleanup/no leaks, malformed and no-fallback cases.
4. Run full locked offline gates, policy/privacy/schema/signature/DCO, independent review, exact-head
   CI, signed merge, and all post-merge assurance workflows.

## Acceptance criteria

Immutable cassette content is runtime-authenticated and reaches real supervised replay through a
bounded handle. The CLI cannot substitute bytes, paths, authority, or providers; all lifecycle and
egress failure paths are tested and fail closed.
