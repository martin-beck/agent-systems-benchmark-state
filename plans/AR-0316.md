# AR-0316: Publish reproducible agent runtime bundles

## Outcome

Replace top-level-binary-only compatibility evidence with complete,
content-addressed runtime environments for every supported agent. Installation
and verification must work without trusting mutable package indexes or ambient
host dependencies.

## Dependencies and ownership

Dependencies: AR-0301 through AR-0309.

Owned paths: agent runtime lock manifests, offline bundle/install tooling,
agent dependency SBOM and license evidence, runtime verification tests, and the
corresponding supply-chain documentation. Shared release and platform manifests
require coordinator serialization with AR-0702 and AR-0820.

Branch: `feature/agent-runtime-bundles`. Worktree:
`agent-systems-benchmark-agent-runtime-bundles`.

## Work sequence

1. Inventory each accepted agent's executable, interpreter/runtime, dynamic
   libraries, packages, plugins, and transitive dependencies from pinned
   upstream code and package metadata; record licenses and redistribution terms.
2. Define a versioned bounded manifest with SHA-256 digests, source revisions,
   platform/libc constraints, dependency relationships, and signed provenance.
3. Build deterministic offline bundles or verified installers for every claimed
   platform. Never execute an artifact before its digest and manifest signature
   pass. Do not redistribute components whose licenses have not been satisfied.
4. Make adapters verify the complete selected runtime identity, not only the
   top-level executable. Reject missing, extra, mutable, mismatched, or
   unsupported components before prompt or provider effects.
5. Generate SPDX and CycloneDX SBOMs and machine-check their agreement with the
   runtime manifest, license files, and installed tree.
6. Test clean offline installation, repeatability, corruption, substitution,
   symlink/race, incomplete-cache, wrong-architecture/libc, upgrade, and rollback
   paths in disposable environments on the native support matrix.

## Acceptance criteria

- Every supported agent/platform pair has an immutable complete dependency
  graph with content hashes, source/version provenance, licenses, and explicit
  redistribution status; unsupported pairs fail closed.
- Two independent clean builds or materializations produce byte-identical
  manifests and equivalent addressed trees; any unavoidable non-reproducible
  byte is isolated and explained without weakening verification.
- Offline installation and a credential-free real agent fixture pass after the
  cache is populated. Network denial proves no mutable package lookup occurs.
- Tampering with any executable, interpreter, native library, wheel/package,
  plugin, manifest, signature, SBOM, or license evidence prevents execution.
- Native x86_64 and aarch64 plus glibc/musl claims are made only where actually
  exercised; mainstream Linux/openEuler results and limitations are recorded.
- The release and one-line installer consume the same manifests rather than
  maintaining a second dependency model.

## Required checks and evidence

Run focused manifest/parser/install tests, meaningful corruption and race
negatives, full repository quality gates, dependency/license/security scans,
exact-tree signatures/DCO/privacy review, native platform fixtures, reproducible
build comparisons, SBOM validation, immutable-head CI, post-merge checks, and an
independent supply-chain audit. Keep caches and artifacts under
`/srv/data/projects`; publish no credentials, private paths, raw prompts,
responses, or private logs.
