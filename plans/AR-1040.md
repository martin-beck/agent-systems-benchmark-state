# AR-1040: Reconcile protected-merge signature verification

## Outcome

Make ASB's required GitHub merge-commit publication path verifiable by the offline repository policy
without weakening SSH signature requirements for ordinary commits or pull-request heads.

## Dependencies and ownership

No implementation dependency. This focused recovery unblocks AR-1039 and AR-1013 in
`martin-beck/agent-systems-benchmark`. Owned paths are signature-policy code/tests, the exact
protected-main workflow invocation, a provenance-pinned public GitHub Web Flow verification key,
and integration documentation. No benchmark semantics, catalog behavior, installer, TUI, renderer,
Ratatui, Crossterm, screen, widget or frontend state is owned.
Branch: `fix/protected-merge-signature-policy`. Worktree:
`agent-systems-benchmark-protected-merge-signature-policy`.

## Work sequence

1. Obtain GitHub's Web Flow public signing key from an official GitHub source; record exact armored
   bytes, SHA-256 and full fingerprint, and independently verify that immutable merge commits
   `0c65159d`, `a01f7f21` and `cad9fa97` report the expected signer while ordinary local heads retain
   the configured allowed SSH signer.
2. Keep the default/PR signature policy SSH-only. Add a separate explicit protected-main mode that
   may accept the exact pinned Web Flow PGP fingerprint only for a two-parent GitHub merge commit
   whose first parent is the supplied immutable range base, committer identity is exact, author has
   a matching raw DCO trailer, and every non-merge commit in the range still passes allowed SSH.
3. Bind workflow event/ref/range arguments so only canonical `push` events on `refs/heads/main` can
   request that mode. Pull requests, forks, workflow dispatch and local default invocation must not
   enable it. Reject wrong key, unsigned, one-parent, octopus, wrong-first-parent, wrong committer,
   missing/nonmatching DCO and mixed-range adversaries.
4. Publish through a signed+DCO pull request. The final `--merge` message must carry the exact
   GitHub-author trailer `Signed-off-by: martin-beck <martin.beck2@gmx.de>`, then the updated policy
   must validate that merge and all protected-main workflows must pass.

## Acceptance criteria

PR heads remain restricted to the configured SSH signer; only structurally exact protected-main
GitHub merge commits may use the one provenance-pinned PGP fingerprint; no network lookup occurs
during policy verification; the current valid GitHub merges validate in protected-main mode while
their documented DCO failures remain failures; `cad9fa97` passes signature and DCO; and a final
corrective merge is green on current main.

## Evidence

Record official key source, armored-key SHA-256/full fingerprint, exact positive merge objects,
negative signature/topology/event/ref/DCO fixtures, workflow policy self-checks, local full gates,
independent security review, exact-head CI and post-merge main verification.
