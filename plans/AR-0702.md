# AR-0702: Validate native Linux kernels and architectures

## Outcome

Exercise native x86_64 kernel behavior and required pinned QEMU AArch64 portability. Record native
ARM64 kernel and performance testing as optional future qualification.

## Dependencies and ownership

Dependencies: AR-0701, AR-0103, AR-0201, AR-0401.
Owned paths: native test harness and platform evidence.
Branch: feature/native-platforms. Worktree: agent-systems-benchmark-native-platforms.
One worker owns this task; shared workspace/schema edits require coordinator integration.

## Work sequence

1. Use disposable native x86_64 environments and the AR-0707 pinned QEMU AArch64 lane with
   isolated benchmark resources.
2. Implement the smallest complete boundary and its independent failure tests.
3. Run focused and applicable full quality gates on the exact commit.
4. Publish a focused PR, reconcile CI and record verified limitations.

## Acceptance criteria

Native x86_64 fixtures validate cgroup/PSI/cancellation/cleanup; missing privileges and
SELinux/AppArmor are handled. QEMU AArch64 must validate applicable userspace, protocol, packaging,
and failure paths but is never used as a native performance or kernel baseline. Native ARM64
evidence is an optional future test and cannot block completion.

## Evidence and completion

Record source/tool versions, commands by digest, immutable commit and CI identifiers,
observed outcomes and remaining limitations. No raw private configuration or transcripts.
Include negative cases and a real production-boundary integration where applicable.
Keep native and emulated evidence labels distinct. Finish after required native x86_64 and
applicable QEMU AArch64 checks, review, exact-head checks and post-merge checks pass.
