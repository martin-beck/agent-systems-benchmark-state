# AR-1228: Qualify provider authentication backends and probes

## Outcome

Provide the approved concrete authentication authority required by AR-1120: qualified
environment, inherited-descriptor and helper integrations, an optional system-secret backend,
bounded provider-specific authentication probes, and durable application/config/control wiring.
The implementation must preserve ASB's zero-runtime-download boundary and never store or expose
credential values.

## Dependencies and ownership

Dependencies: AR-0319, AR-0320 and AR-1100. Repository: `martin-beck/agent-systems-benchmark`.
Owned paths: concrete credential backend adapters, provider probe contracts and fixtures,
configuration/registry persistence integration, authenticated control requests, and tests.
Branch: `feature/ar-1228-auth-backends-probes`. Worktree:
`agent-systems-benchmark-ar-1228-auth-backends-probes`.

## Work sequence

1. Define backend capability contracts for environment, one-shot FD, pinned helper and optional
   system-secret storage. Reject unavailable backends explicitly; never fall back to plaintext,
   ambient environment or caller-owned unvalidated paths.
2. Bind each backend to the existing credential reference digest and resolver boundary. Make
   replacement transactional, with explicit pending/unavailable state when rollback cannot be
   proven; add crash and partial-revoke recovery.
3. Add bounded provider-specific probe adapters using pinned endpoint/protocol identities and
   credential-free result classes. Reject redirects, oversized responses, malformed auth,
   unsupported providers and stale connection generations before durable activation.
4. Integrate enrollment metadata with `asb-config` and authenticated `asb-control`; persist only
   references, generations, digests and public status. Add CLI commands with secret input exclusively
   through one-shot terminal/descriptor/helper channels.
5. Add hostile fixtures for leakage, ambient configuration, malformed/unknown fields, source or
   digest mismatch, stale probes, cancellation, timeout, partial backend failure, crash recovery,
   concurrent rotation and unavailable system-secret services.

## Acceptance and evidence

Every supported backend has concrete bounded implementation and qualification evidence. A key
never appears in argv, ordinary environment, config, control frames, logs, diagnostics or public
evidence. Run focused/full quality, privacy, fault and recovery gates; independent exact-head review;
exact-head CI; and post-merge verification. Unsupported backend combinations remain unavailable.
