# AR-0811: Audit workflow documentation and publication

## Outcome

Independently verify that all required workflows are accurate, executable, accessible, privacy-safe, and identical in repository and deployed forms.

## Dependencies and ownership

Dependencies: AR-0808, AR-0809, AR-0810.
Owned paths: documentation audit harness, coverage matrix, release checks, and audit report.
Branch: `test/documentation-qualification`. Worktree: `agent-systems-benchmark-documentation-qualification`.

## Work sequence

1. Map every supported capability, agent/provider combination, operational task, frontend journey, failure/recovery path, platform, install/upgrade, and evidence limitation to documentation and an executable check.
2. Follow workflows from fresh native x86_64 and pinned QEMU-emulated AArch64 environments and
   representative available Linux/openEuler userspaces.
3. Compare repository pages, built site, deployed Pages content, released CLI/TUI help, schemas, defaults, support matrix, checksums, and release identity.
4. Audit accessibility, language clarity, navigation/search, links, privacy, licenses, dependency integrity, CSP, SBOM/provenance, rollback, and archival version access.
5. Create defect ARs for gaps; required documentation cannot be waived to finish the queue.

## Acceptance criteria

Every released user-visible capability and limitation is documented and tested; no workflow relies on hidden state or stale commands; live/replay and cost/security effects are unmistakable; the deployed site corresponds to the verified release; accessibility and privacy gates pass; and unsupported combinations are explicit.

## Evidence and completion

Record the requirement-to-page-to-test matrix, native and emulated evidence labels, immutable
commits, independent approvals, exact CI/deployment IDs, deployed URL/hash, defects, and
post-release verification. Native ARM64 evidence is optional and cannot block completion.
