# AR-1307: Repair and publish the portable TLC runner

## Objective

Replace the incomplete AR-1302 portable TLC runner with a reusable, clean,
reproducible runner that can qualify the state repository's AR-1293 formal
tiers without bypassing the canonical admission, execution, or attestation
contracts. The implementation remains entirely in the Agent Systems Benchmark
state repository and must unblock AR-1293 with fresh exact-head evidence.

## Dependency and ownership boundary

AR-1302 is the predecessor and records the initial runner/VM work as done. The
successor must independently audit and repair that result; it must not assume
the old candidate is publishable. AR-1293 is the downstream consumer and is
intentionally not a hard dependency because it is blocked on this runner.

Own only state-repository formal runner code, launch/container or VM
definitions, pinned offline fixtures, tests, documentation, and sanitized
qualification evidence. Do not modify ASB product sources, asb-tui, the
vendored or extracted handoffctl implementation, the external root-owned TLC
lock, unrelated host services, or private credentials and captures. Native
ARM64 is not required; use a pinned x86_64 container or QEMU lane and label
emulated evidence accurately.

## Development-profile boundary

The explicit `unsigned-development` profile is permitted only for local
diagnostic fixtures and preflight tests. Such fixtures must be labelled
`diagnostic` and must never be emitted as canonical full qualification,
formal attestation, publication evidence, or release evidence. The
portable-smoke, pr-publication, and full-exhaustive qualification paths remain
fail-closed unless the exact reviewed signed input bundle, pinned provenance,
and terminal attestation are present. A missing, unsigned, stale, or
profile-mismatched bundle is a preflight error, not an invitation to continue
with synthetic authority.

The diagnostic profile must be selected explicitly at the validator boundary
(`--profile unsigned-development`) and its result is labelled `diagnostic`;
the default `signed` profile remains the only profile eligible for
qualification, publication, or release evidence.

## Required implementation

1. Start from a clean current state `main` checkout and preserve the existing
   AR-1293 contracts. Route every model through `tools/tlc_runner.py` and
   `formal/handoffctl/verify.sh`; never invoke `tlc2.TLC` directly from the
   qualification helper. Preserve canonical queue/admission locking,
   cancellation/restart behavior, `TLC_CGROUP_MODE`, and fail-closed
   attestation. A private queue/lock is diagnostic-only and must never be
   represented as publication evidence.
2. Provide a digest-pinned Linux/amd64 container or disposable x86_64 QEMU
   runner entirely under `/srv/data/projects`. Deny network and host mounts,
   use an immutable reviewed source and pinned JDK/TLC inputs, isolate state
   and evidence paths, and fail closed when containment, architecture,
   capacity, image, or offline prerequisites are missing.
3. Match the canonical AR-1293 tier profiles exactly, including the current
   portable-smoke, pr-publication, and full-exhaustive deadlines, heap,
   workers, CPU, process, memory, and memory+swap limits. Record the effective
   cgroup or portable limits rather than merely requested values. Correct the
   Docker memory/swap interpretation and keep tmpfs documentation and code
   consistent.
4. Bound every external process and cleanup operation. Use finite launch,
   staging, model, extraction, and teardown deadlines; bound captured output
   before it can enter memory; reap process groups; and guarantee cleanup of
   containers, overlays, volumes, temporary files, and failed-create paths.
   Commands must remain argument arrays without a shell.
5. Emit sanitized, schema-validated evidence binding the exact source commit
   and tree/payload digest, runner/helper commit or digest, image and JDK/TLC
   digests, architecture/emulation label, Docker/QEMU/runtime version,
   effective resource properties, exact command argv digest, queue/lock and
   artifact paths (all under the approved root), model outcomes, attestation
   status, and cleanup result. Do not retain raw model output, host paths,
   credentials, prompts, or transcripts.
6. Add positive and negative tests for canonical runner routing, profile
   values, missing or mismatched images/JAR/source, network and host-mount
   rejection, insufficient capacity, missing portable tools or user bus,
   timeout/output limits, private path confinement, stale evidence, exact
   receipt/input binding, and cleanup after each failure class. Include a
   repeatable portable-smoke run sufficient to detect capacity flakiness.

## Qualification and handoff

After implementation, run the focused state tests, full applicable state suite,
vendor verification, source-header/privacy checks, Ruff, format, and strict
mypy offline. Independently review the complete diff and signed+DCO history.
From a clean exact tree, run fresh exact-head portable-smoke repeatedly and
fresh pr-publication and full-exhaustive tiers with retained sanitized
attestation. Evidence must prove the runner used the canonical path and bind
all inputs; prior f1931686 or AR-1302 evidence cannot substitute for current
exact-head evidence.

Publish only through the protected pull-request workflow, wait for exact-head
required CI, merge only when every required check is green, and perform
post-merge exact-main verification. Update AR-1293 with the immutable runner
identity and qualification results, then release AR-1307 with durable merge,
CI, post-merge, and evidence references. Any unavailable infrastructure or
failed gate must remain an explicit blocked/open next action; do not weaken a
gate or claim a qualification from a local diagnostic run.

## Acceptance criteria

- Clean exact-head state runner executes all AR-1293 tiers through
  `verify.sh`/`tlc_runner.py` and produces truthful attestation.
- Tier resource and timeout contracts are exact and independently evidenced;
  no host-wide EAGAIN/swap failure is hidden or reclassified.
- Network, host-mount, image/JAR/source, path, timeout, output, stale-input,
  and cleanup negative cases fail closed with bounded sanitized evidence.
- Fresh repeated portable-smoke plus required/publication and exhaustive runs
  pass at the reviewed exact head, or the precise external blocker is durable.
- The complete diff has independent privacy/provenance/signature/DCO review,
  all applicable local and hosted gates are green, protected merge and
  post-merge checks are complete, and AR-1293 is updated with the handoff.
