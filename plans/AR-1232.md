# AR-1232: Sandboxed replay process supervision

## Outcome

Connect strict replay launch records to the approved `asb-runtime` sandbox so real adapter child
processes and descendants run with provider egress denied and bounded lifecycle supervision.

## Dependencies and ownership

Dependency: AR-1231. Repository: `martin-beck/agent-systems-benchmark`. Own the runtime sandbox
adapter launcher, process lifecycle/recovery seam, and focused tests. Do not modify `asb-tui` or
AR-1151 campaign/default code.

## Acceptance

- Accept only a validated `StrictReplayLaunchRecord` and an actually probed `SandboxBackend` with
  `NetworkPolicy::Deny`; caller-supplied attestations are insufficient.
- Launch the selected adapter and descendants through `SandboxBackend::spawn`, exposing only the
  authenticated loopback replay route and no provider endpoint, credential, or ambient network.
- Consume the approved runtime sidecar handoff only after its namespace, listener-readiness, route,
  generation, and command attestations verify; never construct or widen the handoff in AR-1232.
- Supervise bounded startup, timeout, cancellation, shutdown, retry, crash recovery, and restart;
  stale sockets, cursors, generations, and duplicate attempts fail closed and are never reused.
- Map sandbox/process failures to bounded privacy-safe evidence without child output retention.
- Add deterministic positive and negative tests for real child replay, provider/descendant egress
  denial, unmatched request, timeout, cancellation, restart, crash, partial launch, stale route,
  and duplicate attempt.
- Update public schema/docs and hand off the executable consumer contract to AR-1151.
- Run focused and full locked gates, privacy/supply-chain/formal checks, exact-head review/CI, and
  post-merge verification with signed DCO commits.

## Explicit non-goals

No provider discovery, credential storage, campaign matrix, TUI changes, or live network access.
