# AR-1034: Add the standalone TUI configuration center

## Outcome

Provide one safe configuration menu for frontend preferences and reusable benchmark-plan defaults,
separate from credentials and authoritative runner state.

## Dependencies and ownership

Dependencies: AR-1014, AR-1025 and AR-1033. Repository: `martin-beck/asb-tui` only. Owned paths are
the configuration screen, preference schema/store, forms, import/export, migrations, help and
tests. It extends the reviewed settings-wizard model ported by AR-1025 and reuses AR-1014's canonical
measurement-selection/state/serialization model rather than defining another selector. Runner-
owned configuration mutation is out of scope: the TUI edits local preferences and validated
benchmark-plan drafts only, and may display runner values only when already supplied by a public
read-only contract. Secret values are never stored by the TUI.
Branch: `feature/tui-configuration-center`. Worktree:
`agent-systems-benchmark-asb-tui-configuration-center`.

## Work sequence

1. Separate frontend preferences (theme, contrast, motion/update cadence, key presentation, default
   landing destination) from benchmark draft defaults (agents, workloads, measures, repetition and
   resource presets) and from read-only runner-owned configuration. Stored measurement presets are
   opaque canonical AR-1014 plans and must round-trip through its validation model.
2. Show origin, default, effective value, validation and restart/reconnect consequence for every
   setting; capability-gate unavailable values with reasons.
3. Store only bounded non-secret preferences in an owner-private XDG config file using closed
   versioned schema, atomic writes, durable rename, migration and corruption recovery.
4. Support search, category navigation, reset one/reset section/reset all, preview, apply/cancel,
   import/export and unsaved-change confirmation.
5. Test malformed/legacy files, symlink/race/permission faults, interrupted writes, unknown fields,
   resize/plain mode, secret-shaped input and parity with exported plan configuration.

## Acceptance criteria

Users can discover and safely change all supported frontend preferences and plan defaults from one
configuration menu; cancellation loses no prior state, apply is atomic, secrets cannot enter the
store, and runner-owned values are never silently overridden.

## Evidence

Record schema/migration fixtures, filesystem fault tests, exact screen snapshots, import/export
round trips, privacy scans, keyboard/accessibility review, exact-head CI and post-merge verification.
