# AR-0202: Add optional kernel diagnostics

## Outcome

Integrate perf and optional eBPF diagnostics without making privileged tools mandatory.

## Dependencies and ownership

Dependencies: AR-0201, AR-0103.
Owned paths: asb-metrics optional kernel collectors.
Branch: feature/kernel-diagnostics. Worktree: agent-systems-benchmark-kernel-diagnostics.
One worker owns this task; shared workspace/schema edits require coordinator integration.

## Work sequence

1. Design capability probes and bounded diagnostics profiles.
2. Implement the smallest complete boundary and its independent failure tests.
3. Run focused and applicable full quality gates on the exact commit.
4. Publish a focused PR, reconcile CI and record verified limitations.

## Acceptance criteria

Tests cover unsupported PMU/BTF, denied access, attach failure and teardown; native x86_64
counter evidence is required. The pinned QEMU AArch64 lane must exercise portable build, parsing,
unavailable-capability, and cleanup paths where applicable. Native ARM64 PMU/eBPF evidence is an
optional future test and cannot block completion. Report overhead and stop on kernel anomalies.

## Evidence and completion

Record source/tool versions, commands by digest, immutable commit and CI identifiers,
observed outcomes and remaining limitations. No raw private configuration or transcripts.
Include negative cases and a real production-boundary integration where applicable.
Do not label emulation as native evidence. Finish after the required native x86_64 and applicable
emulated-AArch64 outcomes, review, exact-head checks and post-merge checks pass.
