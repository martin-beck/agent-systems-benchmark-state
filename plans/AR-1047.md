# AR-1047: Close the Gemini hook-marker appearance race

## Outcome

Restore deterministic Gemini fake-node readiness on emulated AArch64 by correcting the exact
marker-publication interleaving in `hook_marker_state`. Preserve the fail-closed marker identity,
type, ownership, mode, link-count, size and content checks; change no TUI or frontend code.

## Failure and race evidence

- Current-main AArch64 run `34550483005` failed
  `gemini::tests::duplicate_and_stale_route_ownership_fail_closed_then_cleanup_allows_reuse` with
  `HookUnavailable`.
- PR #137 run `34550643921` failed
  `gemini::tests::ambient_config_prompt_limits_and_cancellation_fail_closed` with the same error.
- AR-1046 PR #138 serialized the complete `asb-agents` library inventory, but exact-head run
  `34552034116` failed the ambient-config fixture again. PR #138 was closed unmerged, disproving
  scheduling contention as the sufficient cause.
- In `hook_marker_state`, `open(O_NOFOLLOW)` may return `ENOENT`, then an atomic rename may publish
  the regular marker before fallback `symlink_metadata`. The fallback currently classifies every
  present object as `Invalid`, so a valid publication in that window fails readiness immediately.

## Work sequence

1. Add a test-only observation/interposition seam immediately after the no-follow marker open
   returns `NotFound` and before fallback metadata inspection. Use bounded channels to atomically
   rename a valid private regular marker during that exact window.
2. Classify fallback `NotFound` as `Pending`; a symlink or non-regular object as `Invalid`; and a
   newly appeared regular file as `Pending`. The next poll must reopen it with `O_NOFOLLOW` and
   perform every existing owner/mode/link/size/content validation before returning `Ready`.
3. Add deterministic tests proving the interposed valid rename yields `Pending` then `Ready`, and
   that a dangling symlink appearing in the same window remains immediately `Invalid`. Retain all
   existing malformed marker, timeout, cancellation and cleanup tests.
4. Run focused Gemini tests repeatedly, the full workspace and applicable quality, coverage,
   portability and policy gates. Publish a clean signed+DCO single-parent commit from exact current
   main for immutable review and all 12 exact-head checks, including emulated AArch64.
5. Merge only through the protected PR path with a genuine multiline body ending exactly
   `Signed-off-by: martin-beck <martin.beck2@gmx.de>`. Verify exact parents/tree, pinned GitHub
   signature, raw trailer, and every post-merge main workflow before releasing this AR.
6. Resume AR-1043 only after recovered main is terminal green; rebase its preserved exact policy
   patch cleanly and do not reuse the failed PR #137 base.

## Acceptance criteria and evidence

The exact absent-open/regular-rename interleaving deterministically returns `Pending` and later
`Ready`; absent remains `Pending`; symlink and non-regular appearances remain `Invalid`; no marker
is trusted without a successful no-follow open plus all existing descriptor-based validations.
Focused repeats, full gates, immutable review, all exact-head checks, exact merge provenance and
post-merge main checks pass. The product diff is only the Gemini marker state machine and its tests,
