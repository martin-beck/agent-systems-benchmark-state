# AR-1336: Live benchmark workflow documentation and support matrix

## Outcome

QUICKSTART, ARCHITECTURE, README, and the support matrix truthfully document the
end-to-end live benchmark workflow from enrollment through selection, campaign
execution, capture, and offline replay, with exact digests and evidence limits,
and no longer claim that live-provider selection and record/replay are not CLI
commands.

## Dependencies and ownership

Dependencies: AR-1333 (benchmark campaign), AR-1334 (conformance and hostile
qualification), and AR-1335 (credential-free CI). Owned paths: QUICKSTART,
README, ARCHITECTURE, the support matrix, and workflow documentation in the ASB
product. Branch: `feature/ar-1336-live-benchmark-workflow-docs`. Worktree:
`agent-systems-benchmark-ar-1336-live-benchmark-workflow-docs`.

## Work sequence

1. Document the live benchmark workflow: enroll the key, persist the free-model
   selection, plan, run or campaign with explicit opt-in, capture, and replay
   offline.
2. Update QUICKSTART and README to remove stale claims that live-provider
   selection and record/replay are not CLI commands.
3. Publish the supported agent by provider by model matrix with exact pinned
   digests, per-agent support and limitation boundaries, and evidence limits.
4. Keep every page credential-free and truthful about opt-in, offline-default,
   and egress limits.
5. Validate every documented command against the grammar and add a docs test
   that fails on stale claims or unverifiable matrix entries.

## Acceptance criteria

Every documented command works offline-safe or under explicit opt-in as stated;
the support matrix is exact, digest-anchored, and evidence-limited; stale
claims are removed; and the documentation passes the grammar and consistency
check.

## Evidence and completion

Record immutable commits, grammar-validation results, reviewed documentation,
independent review, exact-head CI, and post-merge verification.

## Current development and CI qualification boundary

The mandatory development and CI qualification path for this AR is a deterministic
local provider/LLM mock (LiteLLM-compatible where practical), including hostile
negative tests and offline replay where applicable. External/live OpenRouter or
other provider reachability is optional supplementary evidence only; it is never a
completion, dependency-readiness, or CI gate. Production egress policy, credential
non-disclosure, runtime-owned authority, namespace/relay attestation, cancellation
and teardown, and fail-closed denial of unapproved external traffic remain required
contracts. Existing live-provider dependency edges describe production integration
ordering only and must not be used to block local qualification or to claim external
reachability.
