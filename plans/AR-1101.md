# AR-1101: Refactor provider profiles and translation to be registry-driven

## Outcome

Profile construction and adapter translation consume validated registry entries instead of
compile-time constants, so a model or provider change is a data-only change, while every default
`settings_sha256`, model spelling and adapter route stays byte-identical.

## Dependencies and ownership

Dependencies: AR-0310, AR-0313 and AR-1100. Repository:
`martin-beck/agent-systems-benchmark` only. Owned paths are `crates/asb-agents/src/openai.rs`,
`crates/asb-agents/src/ollama.rs` and `crates/asb-agents/src/all_agents_provider.rs`. The public
`OpenAiProfile`, `OllamaProfile`, `VerifiedOllamaProfile`, `OpenAiTranslation`,
`OllamaTranslation` and `AllAgentsProviderSelection` contracts keep their signatures and behavior;
`OPENAI_MODEL`, `OLLAMA_MODEL` and the endpoint constants may be redefined in terms of the registry
but their values must not change. No live API, network or credential is required: unit tests reuse
the existing credential-free loopback fixtures. Branch: `feature/registry-profiles`. Worktree:
`agent-systems-benchmark-registry-profiles`.

## Work sequence

1. Add a registry-driven profile factory that builds a `ProviderProfileV1` for a provider id and
   model from the AR-1100 registry entry: endpoint class and api base, default settings, transport,
   and credential source. Keep the redacted `credential_reference_sha256` parameter for
   environment-sourced providers and the validated loopback `root` for Ollama.
2. Refactor `OpenAiProfile::new(credential_reference_sha256)` to construct from the registry entry
   for id `openai` (model, endpoint, settings, transport) instead of `OPENAI_MODEL` and the
   `OPENAI_API_BASE` constant. The produced `settings_sha256` must equal the current value.
3. Refactor `OllamaProfile::new(root)` similarly from the registry entry for id `ollama`,
   preserving the loopback endpoint validation, `ADDITIONAL_SETTINGS` digest and the verified
   probe model checks. The produced `settings_sha256` must equal the current value.
4. Change `OpenAiProfile::translate` and `OllamaProfile::translate` to take the model and endpoint
   from the profile itself (`requested.model`, `requested.endpoint`) rather than the constants,
   including the `openai/{model}` prefix path used by OpenCode. Default behavior stays identical.
5. Add a registry-driven generic resolution path in `all_agents_provider.rs` that maps one
   provider id plus model to the existing per-adapter `translate` calls, so AR-1104 can resolve
   per-agent profiles from configuration without new provider-specific branches.
6. Test: all existing profile, translation and selection tests pass unchanged; add tests proving
   that a non-default registry model flows into the constructed profile, its translation and its
   `settings_sha256` without hard-coded constants.

## Acceptance criteria

Every existing asb-agents test passes unchanged, default profiles keep their exact
`settings_sha256`, and a registry entry change is sufficient to alter the model used by profile
construction and translation. No adapter behavior changes for the default registry.

## Evidence

Record exact `settings_sha256` values before and after, existing-test pass output, new
non-default-model translation tests, privacy scan and exact-head CI.
