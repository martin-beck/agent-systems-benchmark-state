# AR-1453: Route ASB frontends through central orchestration

## Outcome

Replace direct execution and injection seams in `asb-cli` and the existing
`asb-control` adapter with the AR-1452 orchestration service. `run`, `sweep`,
record, replay, cancellation, status, and result retrieval all use the same
service-owned lifecycle and journal.

## Requirements

- Frontends submit only versioned declarative requests and receive opaque run or
  attempt handles; they cannot pass sandbox, relay, lease, credential, or token
  objects.
- Preserve existing provider/workload catalogs and credential-free configuration
  contracts. Unknown agents, models, workloads, paths, or modes fail before
  effects.
- Qualify setup-to-run-to-report and cancellation/recovery through a local
  mock, plus strict replay. Live-provider mode stays explicit and optional.
- Add CLI/control contract fixtures, privacy checks, and negative tests for
  attempted authority injection and stale handles.

## Acceptance

Normal CLI dispatch uses the orchestrator for all supported local modes; no
production path calls the old injection-only live factory directly. Full local
gates, exact-head CI, independent review, and post-merge evidence pass.
