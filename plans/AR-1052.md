## Diagnostic and repair sequence

1. Refactor server observation behind a bounded injected probe that records only a closed stage:
   socket metadata unavailable/invalid, server PID output unavailable/malformed, process generation
   unavailable, repeated PID changed, repeated socket identity changed, process generation changed,
   or complete. Never include PID, UID, path, session, raw tmux output, `/proc` content or timing.
2. Emit the final closed stage only when bounded trusted acquisition exhausts. Add deterministic
   fixtures for every stage, transition and oversize/non-UTF-8 input; diagnostics must remain fixed,
   bounded ASCII and privacy-safe.
3. Run the exact live fixtures in a branch workflow to learn which subpredicate differs on trusted
   CI. Do not speculate or weaken an authority check before that exact evidence exists.
4. Replace only the proven non-portable subpredicate with an equally strong authenticated primitive.
   Preserve exact owner-private socket type/owner/device/inode, exact server generation, stable
   session/window/pane/TTY/foreground-group authority, and full pre-option/pre-TERM/pre-KILL
   revalidation. A missing or changed observation performs zero option, signal, server kill or
   unlink against an unproven identity.
5. Keep guard construction immediately after successful session creation. Cleanup must always be
   bounded, may target only the exact authenticated server/process group, and never manually unlink
   a socket pathname. Stale nodes remain inside the disposable private test root.
