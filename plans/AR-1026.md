# AR-1026: Qualify cross-repository ASB and asb-tui integration

## Outcome

Prove that exact candidate revisions from the two repositories interoperate safely through the
public `asb tui` command family before either release channel is promoted.

## Dependencies and ownership

Dependencies: AR-1024 and AR-1025.
Primary repository: `martin-beck/agent-systems-benchmark`, consuming an exact immutable asb-tui
candidate as external test input. Owned paths: cross-repository conformance fixtures, disposable
install harness, lifecycle/runner-continuity tests and bounded public evidence. Product fixes found
in either repository require a focused owner-specific successor or handoff rather than overlapping
an active worktree.
Branch: `test/asb-tui-cross-repository-integration`.
Worktree: `agent-systems-benchmark-asb-tui-cross-repository-integration`.

## Work sequence

1. Bind exact ASB/asb-tui commits, trees, schemas, build inputs and artifact digests in the harness.
2. Build release-mode artifacts reproducibly and create a local signed channel/bundle fixture using
   dedicated test keys that production binaries cannot trust.
3. From clean unprivileged homes run capabilities, install, status, launch, doctor, upgrade and
   remove through ASB only; verify stable human and JSON output.
4. Launch a real synthetic benchmark through the TUI, detach/kill/restart/reconnect the frontend and
   prove one durable run, causal status and unperturbed completion.
5. Repeat with interrupted download/stage/activation, concurrent installers, tampered metadata and
   bytes, wrong signer/namespace, expiry, clock skew, downgrade, redirect, symlink, permissions,
   low disk, wrong ASB/protocol/architecture and corrupted active state.
6. Exercise local TTY, SSH, tmux, GNU Screen, minimal/no-color and resize paths on native x86_64 and
   applicable pinned QEMU AArch64.
7. Measure attached/detached frontend resource use and benchmark timing against a declared budget.

## Acceptance criteria

The exact command sequence succeeds on supported clean cells; all hostile cases fail before unsafe
mutation or execution; frontend loss/removal never changes benchmark truth; protocol and artifact
drift are detected mechanically; and every support claim is tied to exact revisions and platforms.

## Evidence

Publish sanitized fixture identities, exact commands by digest, exit/result matrices, terminal and
platform labels, resource comparisons, full local gates, independent security/usability review,
exact-head hosted CI, trusted exact-revision evidence and post-merge verification. Do not publish
raw homes, paths, prompts, credentials or logs.
