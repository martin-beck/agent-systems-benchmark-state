# AR-1026: Qualify cross-repository ASB and asb-tui integration

## Outcome

Prove that exact candidate revisions from the two repositories interoperate safely through the
public `asb tui` command family before either release channel is promoted.

## Dependencies and ownership

Dependencies: AR-1011, AR-1024, AR-1025, and AR-1029. AR-1025 supplies the functional standalone
shell; AR-1011 transitively integrates AR-1014 and AR-1031 through AR-1035 into the complete
standalone UI required by this task's real interactive benchmark acceptance. AR-1029 proves the ASB
repository no longer contains the legacy renderer before cross-repository qualification begins.
Primary repository: `martin-beck/agent-systems-benchmark`, consuming an exact immutable asb-tui
candidate as external test input. Owned paths: cross-repository conformance fixtures, disposable
install harness, lifecycle/runner-continuity tests and bounded public evidence. Product fixes found
in either repository require a focused owner-specific successor or handoff rather than overlapping
an active worktree.
Branch: `test/asb-tui-cross-repository-integration`.
Worktree: `agent-systems-benchmark-asb-tui-cross-repository-integration`.

## Work sequence

1. Bind exact ASB/asb-tui commits, trees, schemas, build inputs and artifact digests in the harness.
2. Build release-mode artifacts reproducibly and create a local signed channel/bundle fixture using
   dedicated test keys that production binaries cannot trust. Verify the executable, source
   archive, license report, SPDX SBOM and provenance bytes, sizes and digests before candidate
   execution, and prove production trust never accepts the test signer.
3. From clean unprivileged homes run capabilities, install, status, launch, doctor, upgrade,
   failed-upgrade rollback and repeated remove through ASB only; verify stable human and JSON output.
   Target selection must route exact native x86_64 and pinned QEMU AArch64 artifacts, while an
   unsupported OS/architecture or wrong artifact fails before mutation or execution.
4. Launch a real synthetic benchmark through the TUI, detach/kill/restart/reconnect the frontend and
   prove one durable run, causal status and unperturbed completion.
5. Repeat with interrupted download/stage/activation, concurrent installers, tampered metadata and
   bytes, wrong signer/namespace, expiry, clock skew, downgrade, redirect, symlink, permissions,
   low disk, wrong ASB/protocol/architecture and corrupted active state. At every interruption or
   failed candidate self-test, the previous verified active version must remain launchable; retry
   must converge without a partial active installation.
6. Prove update advances only to a newer authenticated release, automatic downgrade is rejected,
   and remove is idempotent and network-free. Remove may delete only standalone extension state: it
   must preserve the ASB executable, ASB configuration, stored runs/artifacts and any running
   benchmark process.
7. Exercise local TTY, SSH, tmux, GNU Screen, minimal/no-color and resize paths on native x86_64 and
   applicable pinned QEMU AArch64.
8. Mechanically scan the exact ASB tree and dependency closure: lifecycle router, protocol,
   validation, runner and conformance seams may remain, but no Ratatui, Crossterm, renderer, widget,
   application state, terminal event loop or other frontend implementation may be present.
9. Measure attached/detached frontend resource use and benchmark timing against a declared budget.

## Acceptance criteria

The exact command sequence succeeds on supported clean cells; all hostile cases fail before unsafe
mutation or execution; interrupted update retains the prior verified active version; uninstall is
network-free, idempotent and preserves ASB and benchmark state; frontend loss/removal never changes
benchmark truth; protocol and artifact drift are detected mechanically; ASB contains no renderer or
frontend implementation; and every support claim is tied to exact revisions and platforms.

## Evidence

Publish sanitized fixture identities, exact commands by digest, exit/result matrices, terminal and
platform labels, resource comparisons, full local gates, independent security/usability review,
exact-head hosted CI, trusted exact-revision evidence and post-merge verification. Do not publish
raw homes, paths, prompts, credentials or logs.
