# AR-1290: Dependabot DCO boundary recovery

Repair the protected-main DCO failure reported for immutable Dependabot commit
`07d4b62ad5c10444e5d0ba5f014613cd7c34c0f5`. Preserve all published history and
never weaken the general Signed-off-by or SSH-signature policy.

## Scope and decision gate

First establish whether the commit is already an ancestor of protected main. If it
is only an unmerged/open pull-request commit, close or supersede that PR and create
a fresh signed+DCO replacement from current protected main with the identical
dependency diff; no historical exception is needed. If protected main already
contains the commit, implement the smallest forward-only, hash-bound admission
attestation required to classify this one immutable historical commit while keeping
all other commits strict. The attestation must bind the exact commit hash, parents,
tree, author identity, dependency-only diff and review/CI evidence, and must fail
closed for any altered hash, tree, parent, author or unrelated path.

## Acceptance

- Exact ancestry and PR/main state for `07d4b62` are recorded without rewriting history.
- Preferred replacement path, when possible, uses a clean current-main signed+DCO topic,
  exact dependency diff, independent review, exact-head CI and protected merge.
- Any unavoidable immutable-history attestation is one-time, hash-specific, documented,
  covered by positive and negative tests, and cannot admit arbitrary unsigned commits.
- Repository policy, DCO, SSH signature, privacy, dependency, workspace, formal and
  post-merge gates pass; no runtime downloads, credentials, TUI paths or gate weakening.
- AR-1288 remains a narrative predecessor/context only; it is deliberately not a dependency
  because its closure is waiting on this repair. Its certificate implementation is not
  modified by this AR.
