# AR-1328: OpenRouter free-model user configuration and key enrollment

## Outcome

A user can persist one pinned OpenRouter selection with a dated free-model
snapshot and enroll the `OPENROUTER_API_KEY` credential reference through the
credential-free `asb-config` boundary, then load it through the CLI with a
`--use-config` path. No secret value ever enters durable state, and stale,
unsupported, or credential-bearing configurations fail closed.

## Dependencies and ownership

Dependencies: AR-1325 (OpenRouter provider profile), AR-1326 (CLI catalog and
selection), and AR-1100 (`asb-config` authoritative configuration with
`AuthEnrollment`, `CredentialReference`, `CONFIG_SCHEMA_VERSION = 1`), all
planned/done as recorded. Owned paths: the per-user configuration file format,
the enrollment and reference records, the CLI `--use-config` wiring, and the
configuration documentation in the ASB product. Branch:
`feature/ar-1328-openrouter-free-model-config`. Worktree:
`agent-systems-benchmark-ar-1328-openrouter-free-model-config`.

## Work sequence

1. Define the durable per-user configuration that names the exact free-model
   OpenRouter selection, its model snapshot, and the `OPENROUTER_API_KEY`
   credential reference digest, with a schema version and forward-rejection.
2. Express the enrollment through the `asb-config` `AuthEnrollment` and
   `CredentialReference` boundary so secrets resolve only from the environment
   at run time and never serialize to disk.
3. Wire the CLI `--use-config` path so provider-plan, run, sweep and the
   benchmark commands load the persisted selection and verify every projection
   against the experiment identity.
4. Reject absent, stale, altered, mixed, or credential-bearing configurations
   before any run or provider contact; keep `openai` and default behavior
   unchanged.
5. Add configuration tests: enrollment, load, mismatch, missing reference,
   secret non-disclosure in diagnostics and logs, and offline behavior without
   a key.

## Acceptance criteria

The configuration carries no credential and resolves the secret only through
the enrolled environment channel; the free model is a pinned dated snapshot;
loading is deterministic and content-addressed; unsupported or lossy
configurations are rejected before launch; and offline CI without a key remains
green.

## Evidence and completion

Record pinned configuration/enrollment digests, redacted load observations,
negative configuration fixtures, immutable commits, independent review,
exact-head CI, and post-merge verification. README claims alone are
insufficient.
