# AR-1130: Wire effective provider settings into real agent launches

## Outcome

Resolve configuration and credentials into exact adapter launches with durable non-secret evidence.

## Dependencies and ownership

Dependencies: AR-0876 and AR-1110; AR-1100 and AR-1120 are transitive. Repository: `martin-beck/agent-systems-benchmark`. Owned paths: provider launch v2, adapter wiring, credential injection, durable run bindings, recovery and conformance.
Branch: `feature/ar-1130`. Worktree: `agent-systems-benchmark-ar-1130`.

## Work sequence

1. Bind configuration generation, agent adapter, provider connection, protocol, model/settings, credential reference, runtime and workload.
2. Resolve credentials immediately before spawn and inject them only through the adapter-owned target.
3. Apply endpoint, API mode and model explicitly; reject unsupported or changed state before durable run creation.
4. Persist launch intent and non-secret identity before effects and recover without repeating uncertain provider calls.
5. Qualify loopback doubles and separately authorized live probes, including invalid keys, drift, rates, timeouts and cancellation.

## Acceptance criteria

Provider choice changes the actual request path rather than metadata only, every launch is reproducibly identified, and failures cannot create a false connected or completed state.

## Evidence and completion

Record bounded public fixtures, exact schema and repository identities, focused/full gates, privacy scans, independent immutable-head review, exact-head CI and post-merge verification. Never publish credentials, prompts, responses, private paths, host identities or raw logs.
