# AR-1308: full-exhaustive QEMU capacity qualification

## Objective

Provide a disposable x86_64 QEMU or equivalent isolated container/VM capacity contract that can
run the exact AR-1307 full-exhaustive TLC liveness workload to terminal completion while preserving
the reviewed 3G memory, 3G swap, 2-worker, 2-core and bounded-time admission contract. Measure and
publish enough sanitized evidence to distinguish successful qualification from JVM OOM, disk or
timeout failure.

## Dependencies and ownership

- Consume the reviewed AR-1304 required-tier QEMU runner and user-bus foundation.
- Consume the exact signed AR-1307 head, pinned TLC JAR/JDK, model/config digests and seed.
- Own only runner image/overlay, capacity provisioning, lifecycle, bounded evidence and formal
  qualification orchestration. Do not modify AR-1307's 3G/3G limits, TLC model, handoffctl, product
  code, asb-tui, or native-ARM requirements.

## Development-profile boundary

An `unsigned-development` guest or fixture may be used only for bounded local
capacity and preflight diagnostics, and its result must remain labelled
`diagnostic`. It cannot satisfy the exact full-exhaustive qualification gate,
produce a liveness attestation, or become publication or release evidence.
The capacity run must fail closed when the exact reviewed signed AR-1307
bundle or any pinned input is absent, unsigned, stale, or mismatched; it must
not substitute a synthetic bundle or downgrade the 3G/3G contract.
The validator defaults to `--profile signed`; callers selecting
`--profile unsigned-development` receive only a labelled diagnostic result,
never a ready/qualification result.

## Required work

1. Build or select a disposable x86_64 QEMU guest/container with immutable image and exact source,
   JDK and TLC inputs; keep image, overlay, swap, scratch and evidence under `/srv/data/projects`.
2. Declare and verify guest vCPU, physical memory, swap, disk/inode headroom, kernel, Java and TLC
   versions before execution. Require enough host capacity for the declared 3G/3G process envelope
   plus guest/runtime overhead, without changing the process envelope itself.
3. Run exactly one full-exhaustive qualification for the AR-1307 head with network disabled, no host
   mounts, bounded timeout, canonical admission lock, cleanup and orphan recovery.
4. Capture only bounded sanitized terminal diagnostics, measured cgroup/guest memory and swap
   counters, disk/inode counters, JVM/TLC provenance, exact model/config/runner digests and cleanup
   result. Never retain raw logs, credentials, private paths or unbounded subprocess output.
5. Add positive and negative tests for insufficient memory, insufficient swap, disk exhaustion,
   wrong architecture/image/digest, timeout, stale lease, concurrent admission, cleanup failure and
   terminal Java OOM. Every negative case must fail closed and remain distinct from model failure.
6. Run focused/full applicable gates, independent diff review and exact-head CI. Publish a fresh
   terminal full-exhaustive attestation only if all evidence and policy gates pass; otherwise leave
   the AR blocked with the exact measured cause.

## Acceptance gates

- Disposable x86_64 QEMU/container capacity is reproducible, isolated, offline and measured.
- The exact AR-1307 candidate and pinned inputs are bound in the evidence.
- The existing 3G memory/3G swap and bounded admission contract remains unchanged.
- Full-exhaustive TLC reaches a truthful terminal success with liveness attestation, or a bounded
  classified failure is recorded without qualification.
- Signed SSH commits, matching DCO, focused/full tests, privacy and formal gates, exact-head CI,
  independent review, merge and post-merge verification all pass before release.
