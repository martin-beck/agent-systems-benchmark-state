# AR-1031: Build the standalone TUI landing screen

## Outcome

Give `martin-beck/asb-tui` a useful, professional home screen that makes the next safe action clear
without requiring memorized commands.

## Dependencies and ownership

Dependencies: AR-1025 and AR-1033. Repository: `martin-beck/asb-tui` only. Owned paths are landing
screen widgets/state/actions, recent-activity summaries, navigation tests, snapshots and focused
documentation. It consumes ASB state only through the published control protocol and owns no ASB
source, benchmark process, installer or release-channel behavior.
Branch: `feature/tui-landing-screen`. Worktree:
`agent-systems-benchmark-asb-tui-landing-screen`.

## Work sequence

1. Define and test the exact authoritative-state to primary-action table: unavailable or untrusted
   maps to install/connect guidance; stale or disconnected maps to reconnect; an active run maps to
   monitor; a resumable draft maps to continue/review; and ready with no draft maps to configure.
   Show connection/trust/freshness state, active-run state, the latest bounded run summaries and
   clear entries for configure, start, monitor, reports, compare and help.
2. Make the primary action depend on authoritative state: connect/install guidance when unavailable,
   reconnect/monitor when a run exists, and configure a benchmark otherwise.
3. Support keyboard-first focus order, direct shortcuts, Back/Home behavior, empty/loading/error/
   stale states, narrow terminals and plain text.
4. Keep recent activity bounded and privacy-safe; never infer completion, compatibility or success
   from list order or cached frontend state.
5. Add deterministic state tests, exact Ratatui snapshots and complete first-run/returning-user
   interaction fixtures.

## Acceptance criteria

The first rendered application screen is a landing screen; a new user can identify the next safe
action, an expert can reach every top-level workspace in one action, active runner state is prominent
and authoritative, and tiny/plain/no-color modes preserve the same choices without clipped controls.

## Evidence

Record TestBackend snapshots for every state/size/theme, keyboard-only journeys, protocol-freshness
faults, privacy checks, independent UX review, exact-head CI and post-merge verification.
