# AR-1247: Bind Rust verification to protected-main DCO admission

## Outcome

The Rust verification workflow must accept authenticated GitHub protected-main merge commits
through the same durable policy path as repository quality, while retaining strict DCO checks for
reviewed pull-request topics and local/SSH-only validation.

## Acceptance

- `verify.yml` routes canonical `push` events for `refs/heads/main` through
  `repository_policy.py --mode protected-main --event push --ref refs/heads/main` with exact base
  and head identities.
- Pull-request and non-canonical contexts continue to use strict `check_dco.py` validation.
- Offline tests assert the workflow binding and reject a regression to full-range DCO on main.
- Signed, DCO-certified PR passes all required checks and its post-merge Rust workflow is green.
