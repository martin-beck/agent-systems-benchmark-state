# AR-1105: Add the provider model discovery diagnostic

## Outcome

A read-only `asb provider-models` command that lists the pinned registry models without any
network access, and with `--probe` performs bounded live discovery (Ollama `/api/tags` on the
validated loopback root, OpenAI `/v1/models` when the environment credential reference is present)
that always returns an explicit available/unavailable result and never auto-selects or stores a
discovered model.

## Dependencies and ownership

Dependencies: AR-1100. Repository: `martin-beck/agent-systems-benchmark` only. Owned paths are the
new `crates/asb-cli/src/provider_models.rs`, the `provider-models` dispatch addition in
`crates/asb-cli/src/lib.rs` and tests. Discovery is strictly diagnostic: it never writes to the
registry, to a config file, or to any selection output. It reuses the existing bounded probe and
digest helpers and keeps credentials out of all output (a probe is attempted only when the
reference digest is present; the value is read at probe time and never logged). No network is
required for the default listing; `--probe` fails closed with a bounded reason when a daemon or
credential is absent. Branch: `feature/provider-models`. Worktree:
`agent-systems-benchmark-provider-models`.

## Work sequence

1. Implement `asb provider-models` (no flags) printing the pinned registry providers and models as
   a bounded JSON envelope consistent with `ProviderCatalogOutput`, with no network access.
2. Implement `--probe`: for Ollama, probe the validated loopback root using the existing bounded
   `/api/version` and `/api/tags` helpers; for OpenAI, attempt `/v1/models` only when the
   `OPENAI_API_KEY` reference is resolvable, with a short bounded timeout. Each probe reports
   `available: true` plus the observed model list, or `available: false` plus an explicit bounded
   reason (daemon absent, timeout, credential absent, response malformed). Never follow redirects
   off the expected base, never exceed bounded timeouts, and never include authorization material
   in output.
3. Assert by construction that probe results are informational only: no probe path may write a
   registry overlay, config file or selection file.
4. Test with the existing synthetic loopback fixtures: listing is credential-free and offline;
   probe with no daemon/key returns unavailable; probe with a malformed or oversized response
   returns unavailable; probe output contains no secret-shaped content.

## Acceptance criteria

The default listing works fully offline and credential-free; `--probe` always returns a bounded,
structured available/unavailable result with an explicit reason; no command path can mutate the
registry, config or selection; no secret ever appears in output.

## Evidence

Record offline listing output, probe fixtures for available/unavailable/oversized cases, a
no-mutation assertion, privacy scan and exact-head CI.
