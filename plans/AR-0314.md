# AR-0314: Choose matching replay or live provider execution

## Outcome

When compatible recordings exist for the chosen provider profile and settings, offer those recordings and an explicit live-connection choice.

## Dependencies and ownership

Dependencies: AR-0104, AR-0310, AR-0313, AR-0503, AR-0504.
Owned paths: privacy-safe recording catalog, compatibility query, interactive chooser, noninteractive source selection, and recovery state.
Branch: `feature/provider-recording-choice`. Worktree: `agent-systems-benchmark-provider-recording-choice`.

## Work sequence

1. Build a bounded catalog keyed by normalized provider/profile identity, agent/version, workload contract, replay format, and integrity digest.
2. List only compatible recordings using safe labels, timestamps, immutable IDs, completeness, platform limits, and redacted metadata.
3. In interactive use, ask the user to select one prior recording or an actual live connection; never preselect either.
4. In noninteractive use, require `live` or an exact recording ID whenever matches exist; define explicit offline behavior when none exist.
5. Test stale/corrupt/incomplete/ambiguous recordings, changed settings, missing credentials, network denial in replay, live opt-in, cancellation, races, and crash recovery.

## Acceptance criteria

Only exact compatible recordings are offered; choosing replay keeps the provider network denied and pins the cassette digest; choosing live performs a fresh connection preflight and cannot consume a recording; no match is never presented as a match; selection is durably recoverable; and catalogs expose no credentials, raw prompts/responses, transcripts, private paths, or sensitive log data.

## Evidence and completion

Record matching proofs, negative fixtures, immutable commits, signatures/DCO, reviews, exact-head CI, recovery evidence, and explicit behavior for interactive, noninteractive, and offline runs.
