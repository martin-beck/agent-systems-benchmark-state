# AR-1025: Build the standalone asb-tui application

## Outcome

Ship the functional standalone application shell in `martin-beck/asb-tui` with a versioned
connection to the authoritative ASB runner and stable seams for focused downstream screens.

## Dependencies and ownership

Dependencies: AR-0804, AR-0805, AR-0806, AR-0870, AR-0871, AR-1010, AR-1022 and AR-1023.
AR-0804, AR-0805, AR-0806, AR-0870 and AR-0871 are read-only migration/behavior inputs and never
authorize changes to legacy ASB frontend paths.
Repository: `martin-beck/asb-tui`.
Owned paths: application/event-loop and route modules, standalone control-wire client, authoritative
state projection and fixtures, terminal lifecycle, generic foundation rendering/accessibility
fallbacks, user-facing shell documentation and application-shell tests. Lifecycle/bundle contract
changes remain AR-1022-owned. AR-1014 and AR-1031 through AR-1035 exclusively own final selection,
landing, contextual-help, professional visual, configuration and report/comparison implementation.
Branch: `feature/standalone-asb-tui-application`.
Worktree: `agent-systems-benchmark-asb-tui-standalone-application`.

## Work sequence

1. Consume the reviewed immutable Ratatui/Crossterm closure and reproduce AR-1010's single-writer
   action/state/render architecture in the standalone repository.
2. Implement the ASB control v1 framing, negotiation, peer authentication, limits and typed messages
   from published schemas/fixtures without a Cargo path dependency on ASB.
3. Port only the reviewed authoritative connection, validated launch, run-progress, causal-cancel and
   reconnect projections needed by the shell. Define typed route/action extension seams and closed
   disabled reasons for not-yet-integrated downstream destinations; do not implement their screens.
4. Connect only advertised capabilities; unavailable or unknown methods remain disabled with reasons.
5. Implement safe raw/alternate-screen setup and restoration on normal exit, error, panic, signal,
   suspend/resume, SSH loss and multiplexer detach; handle resize storms and tiny terminals.
6. Provide deterministic generic plain-text/NO_COLOR output, visible shell focus and keyboard route
   access. Final contextual help, navigation polish and visual components remain downstream work.
7. Keep runner journals authoritative. A frontend crash/disconnect must never launch twice, cancel,
   corrupt state or lose the ability to reconnect.
8. Add cross-repository fixture drift checks and an isolation proof that ASB builds/runs without the
   frontend repository.

## Acceptance criteria

- `asb tui` launches a responsive real Ratatui interface through the authenticated runner channel.
- Every visible state is derived from negotiated capability or authoritative runner events.
- Every declared route/action has one typed ID, capability gate and deterministic disabled reason;
  downstream destinations can register without changing the control client or event loop.
- Terminal state is restored on every tested exit/fault path.
- Detach, crash, upgrade and removal do not perturb running benchmark processes or outcomes.
- There is no ASB workspace/path dependency and no provider, credential or benchmark engine code.

## Evidence

Run unit/property/state tests, TestBackend snapshots, PTY/escape-stream tests, signal/panic/fault
tests, control protocol conformance, reconnect and idempotency tests, keyboard/accessibility checks,
route registration and missing-destination tests, resource-overhead probes, full
Rust/coverage/supply-chain/workflow/privacy gates, ASB isolation,
independent exact-diff review, exact-head CI and post-merge verification.
