# AR-0906: Verify formal OCI build identity portably

## Outcome

Make the deterministic TLA+ source builder accept the exact reviewed OCI image on conforming Docker
engines whose local configuration ID differs from the pinned registry manifest digest, while still
rejecting tag substitution, missing or extra repository identities, wrong platform, malformed
inspection output, and unverified local-only images before any build command executes.

Dependencies: AR-0003, AR-0878, AR-0901, and AR-0902. This task intentionally does not depend on
AR-0877, avoiding a cycle while providing a separately reviewed repair that AR-0877 can consume.

## Verification contract

1. Invoke image inspection for the exact name-at-digest reference already pinned by AR-0878; never
   resolve a tag, moving alias, or ambient latest image.
2. Parse bounded machine-readable inspection output with a closed schema. Require exactly one
   inspected image, Linux OS, amd64 architecture, and the exact pinned repository digest in the
   repository-digest set. Treat local configuration ID as separate informational identity and do
   not compare it to the registry manifest digest.
3. Reject empty, malformed, duplicated, oversized, truncated, non-UTF-8, unknown-field, wrong-name,
   wrong-digest, digest-prefix/suffix, wrong-OS, wrong-architecture, tag-only, and local-ID-only
   evidence before `docker run` or source extraction.
4. Keep the existing digest-pinned `docker run --pull never --network none --read-only` boundary,
   non-root identity, build inputs, output digest, license receipts, and deterministic packaging
   unchanged.
5. Record only public image reference, digest, platform and stable reason codes. Never publish host,
   environment, socket, registry credential, private path, or daemon diagnostic values.

## Tests and evidence

- Positive fixtures cover the reviewed image when configuration ID equals and differs from the
  registry digest, proving both engine representations bind the same exact repository identity.
- Mutation fixtures independently cover every malformed identity, repository-digest and platform
  case, and a closed test partition proves no declared mutation is skipped.
- A fake Docker boundary proves every negative exits before run/build effects. Positive execution
  preserves exact argv and the existing offline/network-denied build contract.
- Run focused verifier/source-build tests, ShellCheck, full formal tests, TLC/Alloy positive and
  stale negatives where applicable, repository/workflow policy, privacy and Gitleaks, full
  workspace gates, immutable review, exact-head CI, and post-merge exact-main verification.

## Acceptance and limits

The same exact pinned repository digest succeeds on at least the previously qualified engine and
the hosted engine representation that exposed the configuration-ID mismatch. Every wrong or
ambiguous identity fails before build effects. The exact AR-0878 output remains byte-identical.
This proves portable verification of one OCI identity and platform only; it does not qualify tags,
other registries, other architectures, Docker daemon trust, TLA+ correctness, or unbounded models.
