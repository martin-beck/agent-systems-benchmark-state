# AR-0891: Qualify local inference provider profiles

## Outcome

Generalize pinned Ollama into a small negotiated local-profile family with frontend/backend/model/hardware provenance and no inference that OpenAI-compatible means identical.

## Dependencies and ownership

Depends on AR-0879, AR-0312/0313/0315. Own profile contracts, probes, justified launch/verify logic, conformance fixtures, provenance and qualification docs. Coordinate shared catalogs. Branch `feat/local-inference-provider-profiles`; worktree `agent-systems-benchmark-local-inference-provider-profiles`.

## Work sequence

1. Verify official sources for Ollama plus llama.cpp v0.4.0, vLLM v0.28.0 and LocalAI v4.9.0; pin artifacts, licenses, model/tokenizer and templates.
2. Negotiate routes, streaming, usage, tools, cancellation, seed and concurrency; report unsupported explicitly.
3. Record LocalAI frontend/backend; control vLLM generation config/parser/parallelism; pin llama.cpp templates/parsers; update Ollama only as one complete profile.
4. Probe identity, isolate network, strip remote credentials, bound resources, verify teardown and reject drift.
5. Run shared conformance/repeated live trials with warm-up, device/driver/runtime, context/batch/thread/scheduler settings and variability.
6. Add profiles only for tested benchmark needs; reuse route abstractions and keep unqualified candidates out of CLI/TUI.

## Acceptance criteria

Accepted profiles verify immutable server/frontend/backend/model/tokenizer/config; matrices derive from tests; drift/unsupported routes fail; labels stay local-live; resources/network are bounded; variability is measured; and Ollama compatibility is explicit.

## Evidence and completion

Record artifact/model hashes, licenses, privacy-safe probes, capability/isolation/resource evidence, repeated distributions, hardware provenance, native/formal/quality gates, immutable review, exact-head CI and post-merge qualification.
