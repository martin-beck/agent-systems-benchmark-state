# AR-1103: Add the CLI setup wizard

## Outcome

A beginner-friendly `asb setup` wizard that walks from provider to model to scope to credential
reference and produces an atomically written UserConfigV1 file and/or a digest-pinned provider-plan
selection, with a fully scriptable `--non-interactive` mode so concurrent agents and CI never block
on a human, network or credential value.

## Dependencies and ownership

Dependencies: AR-0869, AR-1100, AR-1101 and AR-1102. Repository:
`martin-beck/agent-systems-benchmark` only. Owned paths are the new `crates/asb-cli/src/wizard.rs`,
the `setup`, `config print` and `config validate` dispatch additions in
`crates/asb-cli/src/lib.rs`, the TOML reader/writer for UserConfigV1, and tests. It reuses
AR-1100's registry, AR-1101's registry-driven resolution and AR-1102's UserConfigV1. Interactive
prompts read bounded lines from stdin; nothing is fetched over the network; the credential is
accepted only as an environment variable NAME whose SHA-256 reference digest is stored; secrets are
never written. Branch: `feature/cli-setup-wizard`. Worktree:
`agent-systems-benchmark-cli-setup-wizard`.

## Work sequence

1. Implement the UserConfigV1 TOML reader and atomic writer (temp file, fsync, rename) with strict
   bounds: files ≤ 64 KiB, bounded tables, no partial writes, last valid file preserved on error.
2. Implement the wizard flow: list registry providers (selectable first, then unavailable with
   their reason) and their offered models; choose `default` scope (all supported agents) or
   `selected` scope with an agent list bounded by `MAX_SELECTED_AGENTS`; for environment-sourced
   providers accept an environment variable NAME and store only its SHA-256 reference digest
   (never the value or a resolved secret). Support `--non-interactive` with all values as flags:
   `asb setup --provider openai --model gpt-5.2-2025-12-11 --scope default --credential-ref
   OPENAI_API_KEY --output config.toml`; interactive mode prompts one bounded question at a time
   with exact defaults and clear cancellation.
3. Emit two artifacts, each optional: a UserConfigV1 file and a provider-plan selection shaped
   exactly like `ProviderPlanOutput` (catalog_sha256, selection_sha256, provider_profile,
   provider_profile_sha256, model, credential_source, credential_reference_sha256, effective),
   produced through AR-1101's resolution so downstream `validate_provider_selection` and
   `plan --provider-selection` continue to work unchanged.
4. Add `asb config print` (resolved per-agent effective provider/model/profile_sha256 from the
   file) and `asb config validate` (fails closed with bounded errors).
5. Test non-interactive end-to-end for openai (default and selected scope), ollama (unavailable
   reason surfaced, never selectable without verified daemon), unknown provider/model/agent, stale
   or absent catalog digest, and interrupted atomic writes that preserve the last valid file.

## Acceptance criteria

A beginner can produce a valid config and selection without any network or secret value; the same
result is reproducible with `--non-interactive`; every malformed input fails closed with a bounded
error; the wizard output round-trips through `config validate`, `config print` and the existing
`provider-plan`/`plan --provider-selection` contract.

## Evidence

Record exact non-interactive transcripts, atomic-write fault tests, round-trip validation tests,
byte-identical selection contract output, privacy scan and exact-head CI.
