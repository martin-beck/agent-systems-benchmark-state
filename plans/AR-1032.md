# AR-1032: Add contextual hotkeys and complete action help

## Outcome

Make shortcuts and help continuously discoverable in `martin-beck/asb-tui`, with guidance that fits
the current screen, focus and terminal size.

## Dependencies and ownership

Dependencies: AR-1014, AR-1031, AR-1034 and AR-1035. Repository: `martin-beck/asb-tui` only. Owned
paths are the contextual action registry, hotkey bar/window, help overlay, command/search palette
integration, help coverage tests and snapshots. No ASB product path is owned.
Branch: `feature/tui-contextual-help`. Worktree:
`agent-systems-benchmark-asb-tui-contextual-help`.

## Work sequence

1. Define one typed action registry containing action ID, capability gate, enabled/disabled reason,
   key binding, concise label, detailed help, confirmation consequence and screen/focus context.
2. Render an always-visible compact hotkey bar and a clearly visible expandable hotkey window whose
   contents are limited to actions valid in the current context; adapt columns/rows to available
   space without hiding the Help/Escape path.
3. Add a global search field/command palette over available actions and destinations, with
   incremental deterministic matching, keyboard-only focus, clear query/reset/back behavior and
   explanations for disabled results.
4. Provide detailed help for every performable action. Maintain an explicit reviewed allowlist of
   passive, non-action status labels that need no action help; mechanically fail CI for any other
   registry item lacking concise help, detailed help, key/access path or consequence text and for
   any stale allowlist entry that becomes actionable.
5. Test conflicts, remapping, modal precedence, resize, tiny/plain/no-color, screen reader order,
   stale capabilities and destructive confirmations.

## Acceptance criteria

The current screen always exposes how to navigate and get help; the expanded shortcut window fits
the visible context; 100% of actionable registry entries have mechanically covered contextual help,
with exceptions permitted only for exact reviewed passive non-action IDs; no hidden shortcut is the
sole access path; and keyboard conflicts or unavailable actions fail closed. CI must fail for a
missing action, stale passive exception or action that becomes performable without complete help.

## Evidence

Record action/help coverage reports, exact snapshots across contexts and sizes, search fixtures,
keyboard-only usability sessions, accessibility review, independent review, exact-head CI and
post-merge verification.
