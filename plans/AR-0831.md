# AR-0831: Integrate development host ASB runners with GitHub workflows

## Outcome

Make the ASB GitHub project use qualified development host runners for selected trusted jobs while retaining
GitHub-hosted disposable execution for untrusted public pull requests.

## Dependencies and ownership

Dependencies: AR-0003, AR-0830.
Owned paths: ASB workflow YAML, actionlint/policy rules, trusted-event and label routing,
runner capability declarations, and sanitized workflow documentation.
Branch: feature/development-host-workflow-routing. Worktree: agent-systems-benchmark-development-host-workflow-routing.

## Work sequence

1. Classify every workflow by trust, secret need, native capability, artifact sensitivity, and
   whether it can execute attacker-controlled fork code. Default fork and public pull-request
   jobs remain disposable GitHub-hosted.
2. Route only protected-branch, trusted-repository, or explicitly approved release/qualification
   jobs to exact ASB labels. Prevent expression injection, label spoofing, fallback to arbitrary
   self-hosted runners, and accidental execution of fork code on development host.
3. Keep a disposable equivalent for every required public-PR quality gate. Make runner absence,
   offline state, label drift, architecture mismatch, and lease expiry fail closed with a clear
   status rather than silently changing trust class.
4. Pin actions and toolchains, bound caches/artifacts, redact diagnostics, and document rerun,
   cancellation, timeout, and workflow concurrency behavior.

## Acceptance criteria

- The ASB GitHub project visibly uses qualified development host labels for the intended trusted jobs.
- No public fork or untrusted pull-request code can reach a persistent development host runner.
- Every required PR gate remains reproducible on disposable GitHub-hosted runners.
- Actionlint, policy, secret scanning, provenance, scope, and negative routing tests pass.
- Workflow status identifies runner label, architecture, trust class, and unsupported combinations
  without exposing private infrastructure identity.

## Evidence and completion

Record workflow-to-runner matrix, protected-event rules, fork negatives, label/lease failures,
exact action refs, exact-head CI, and independent security review before changing default routing.
