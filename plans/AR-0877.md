# AR-0877: Repair formal TLA artifact availability

## Outcome

Make the formal workflow obtain the exact reviewed TLA+ toolchain artifact from an authoritative
available release location, or use an already present byte-identical cache offline. An unavailable,
redirected-to-unapproved, truncated, oversized, or digest-mismatched artifact fails closed before
TLC runs. The repair must preserve the positive recovery proof and deliberate stale-epoch mutation
failure rather than turning the workflow into a download-only check.

## Provenance and acquisition sequence

1. Reproduce and record the current HTTP 404 for the pinned TLA asset without treating the failed
   response body as an artifact. Resolve the exact upstream TLA+ v1.8.0 release, source commit,
   asset name, creation timestamp, immutable or documented stable URL, byte length, SHA-256, and
   MIT license from authoritative upstream release metadata and the downloaded bytes.
2. Prefer a versioned upstream release URL whose availability can be checked without credentials.
   If upstream offers only mutable API asset identities, bind the release tag, asset ID/name,
   metadata endpoint, final approved host set, size, digest, and source commit, and fail closed when
   any field changes. Do not substitute community mirrors or silently follow to an unapproved host.
3. Keep online acquisition bounded: HTTPS only, approved hosts, explicit time/size limits,
   create-new partial file, exact byte count and SHA-256 before atomic rename, owner-safe regular
   files only, no symlinks, and cleanup of failed partials. Diagnostics expose only stable reason
   codes and public release identities.
4. Define the offline/cache policy explicitly. `ASB_FORMAL_OFFLINE=1` may consume only the exact
   pre-existing regular non-symlink artifact after size and digest verification; it never performs
   network I/O. Online mode may reuse that same verified cache. Missing, corrupt, wrong-version,
   oversized, or symlinked cache entries fail closed; no latest-version fallback is allowed.
5. Keep workflow checkout/action/Java pins and least permissions unchanged. The formal job must run
   acquisition verification, TLC positive and deliberate-negative models, Alloy positive/mutation
   checks, and leave no artifact or partial file in the source tree.

## Positive, mutation, and fault fixtures

- A local credential-free HTTP fixture serves the exact expected bytes and authoritative metadata;
  acquisition succeeds once, a second online invocation reuses the verified cache, and offline mode
  succeeds from the same cache with zero requests.
- Mutation fixtures independently alter URL host/scheme/path/version, release tag/source commit,
  asset ID/name, size, digest, redirect target, response length/body, cache type and cached bytes.
  Every mutation must fail before Java/TLC and must not promote a partial file.
- Exercise HTTP 404/403/429/5xx, timeout, stalled/trickled body, redirect loop, disconnect, concurrent
  acquisition, pre-existing partial, read-only cache, symlink/hardlink substitution, and source-tree
  cleanliness. Retries, if any, are bounded and limited to documented transient classes; 404 and
  integrity failures are terminal.
- Run `Recovery.tla` to its successful bounded completion and prove `RecoveryStaleMutation.tla`
  still fails specifically with `Invariant StaleEventsFenced is violated`. Run the Alloy positive
  and mutation receipts too. A cached artifact or mocked downloader alone is not formal evidence.

## Acceptance criteria

- A fresh credential-free hosted runner can retrieve the exact authoritative TLA+ v1.8.0 artifact;
  its final URL, release provenance, size and SHA-256 match `formal/toolchains.toml` and the runner
  constants mechanically.
- Offline execution succeeds only with the byte-identical verified cache and provably makes no
  network request. Missing or altered cache input fails with a stable bounded error.
- The former 404, all integrity/redirect/cache mutations, and concurrent partial-file races fail
  closed without source-tree mutation or execution of unverified Java.
- TLC positive and deliberate mutation, Alloy positive/mutation, toolchain-pin tests, and source-tree
  cleanliness all pass on the exact candidate. The deliberate mutations must still be observed and
  cannot be skipped due to cached success.
- Focused acquisition tests, ShellCheck, repository/workflow policy, actionlint, zizmor, privacy and
  Gitleaks, full workspace/formal gates, immutable review, exact-head CI, and post-merge exact-main
  rerun pass. The repair is not complete based on a local cache alone.

## Evidence limits

Successful artifact acquisition proves only availability and byte identity for the pinned tool. It
does not independently establish correctness of TLA+, Java, the ASB models, native platforms, or
unbounded state spaces. Record hosted network and cache mode separately, and do not claim offline
portability where no verified cache was provisioned.
