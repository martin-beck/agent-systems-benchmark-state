# AR-0810: Publish workflow documentation to GitHub Pages

## Outcome

Build and deploy an official GitHub Pages site containing the tested main-program and terminal-frontend workflows.

## Dependencies and ownership

Dependencies: AR-0808, AR-0809.
Owned paths: static documentation site, navigation/search, Pages workflow, deployment configuration, version banners, and site tests.
Branch: `docs/github-pages`. Worktree: `agent-systems-benchmark-github-pages`.

## Work sequence

1. Generate the site solely from version-controlled documentation and pinned open-source tooling with locked dependencies.
2. Organize quickstarts, workflows, concepts, reference, support matrix, troubleshooting, security/privacy, evidence limits, and release-specific docs.
3. Add accessible responsive navigation, local search without third-party tracking, diagrams, anchors, canonical links, sitemap, and clear version/release selectors.
4. Build pull requests without deployment; deploy only reviewed exact product-main commits using least-privilege GitHub Pages permissions, pinned actions, provenance, and concurrency control.
5. Validate reproducible builds, CSP/no external trackers, links, anchors, assets, accessibility, mobile/terminal-readable fallback, redirects, and deployed commit identity.

## Acceptance criteria

The public site identifies the exact source/release commit; main and frontend workflows are discoverable and complete; no secrets/private paths/raw interactions enter source or artifacts; PRs cannot deploy; Pages permissions are minimal; local and hosted output match byte-for-byte except documented metadata; and rollback/version access are tested.

## Evidence and completion

Record site/tool digests, immutable commit, signed/DCO review, exact-head build and deployment run IDs, Pages URL, accessibility/link/security results, SBOM/provenance, and post-deploy verification.
