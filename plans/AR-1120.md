# AR-1120: Implement secure provider authentication enrollment

## Outcome

Support API-key enrollment, external credential references, connection probes, rotation and revocation.

## Dependencies and ownership

Dependencies: AR-0320 and AR-1100; AR-0319 is a required credential-helper design input. Repository: `martin-beck/agent-systems-benchmark`. Owned paths: authentication contract, API-key enrollment, system-secret integration, environment/helper/descriptor methods, probes and tests.
Branch: `feature/ar-1120`. Worktree: `agent-systems-benchmark-ar-1120`.

## Work sequence

1. Model system-secret storage, explicit environment, credential helper, sealed descriptor, one-run prompt and no-credential methods.
2. Read API keys only from a controlling terminal or one-shot sealed input and persist only logical references and digests.
3. Use a qualified system secret backend when available; report persistent storage unavailable rather than writing plaintext.
4. Perform a minimal bounded authenticated probe and expose only safe connected, rejected, expired, unavailable or untested status.
5. Support replace, rotate and revoke with rollback; scan processes, files, diagnostics and concurrent launches for leakage.

## Acceptance criteria

A user can securely set and test an API key or choose an external method; no credential enters argv, ordinary environment, configuration, control frames, logs or public evidence.

## Evidence and completion

Record bounded public fixtures, exact schema and repository identities, focused/full gates, privacy scans, independent immutable-head review, exact-head CI and post-merge verification. Never publish credentials, prompts, responses, private paths, host identities or raw logs.
