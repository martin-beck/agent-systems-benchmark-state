# AR-1014: Add grouped measurement selection to the TUI

## Outcome

Let users search the authoritative catalog, select or clear semantic groups, drill into a group and
independently select or clear individual optional measurements before submitting one canonical,
validated ASB run plan.

## Dependencies and ownership

Dependencies: AR-1013, AR-0804, AR-0805, AR-1025, AR-1033, AR-1036 and AR-1037. AR-0804 and
AR-0805 are read-only migration inputs and authorize no legacy ASB UI edits. Repository:
`martin-beck/asb-tui` only. Owned paths are selector views, state/actions, catalog projections,
search, presets, review presentation, accessibility output and TUI tests. Consume the bounded
AR-1036 catalog and submit the canonical AR-1037 selection through public contracts only. No ASB
source, catalog semantics, collector, plan validator or runner behavior is owned.

Branch: `feature/tui-measurement-selection`. Worktree:
`agent-systems-benchmark-asb-tui-measurement-selection`.

## Work sequence

1. Decode only a validated AR-1036 publication: at most 192 KiB outside the control envelope,
   256 KiB of catalog bytes, seven semantic groups, 128 measurements and 256 bytes per catalog text
   field. Reject an unknown schema, digest mismatch, duplicate/unknown ID, malformed ordering or
   larger input before rendering or mutating selection state.
2. Render an explicitly focused search field and semantic-group list. Each group shows selected and
   selectable counts and exactly one unchecked, partial or checked state. Mandatory evidence and
   unsupported optional measurements are displayed separately and never enter the selectable
   denominator.
3. Define bulk actions precisely: a group toggle affects all selectable children in that group,
   including children hidden by the current search; a separate explicitly labelled filtered toggle
   affects only visible selectable matches. A zero-selectable group is disabled with a closed
   reason. Drill-down permits independent per-measure selection and clearing without changing
   mandatory evidence.
4. Bound the search query to 256 Unicode scalar values, match deterministically over public ID,
   name and description fields, preserve selection across query clear, resize and backtracking, and
   restore a documented valid focus target when results disappear. Search order follows canonical
   catalog order and never changes the canonical selected-ID order.
5. Show units, aggregation, live/replay availability, platform support, sampling cadence, overhead
   and evidence limits. Unsupported or unavailable items remain visible with closed reasons but
   cannot be selected. Presets, reset and import may contain only known selectable IDs.
6. Bind every draft to the exact catalog generation and digest. On refresh, reordered identical
   content preserves selection; a changed digest makes the draft stale and blocks launch until it
   is explicitly revalidated. Removed, newly unsupported, mode-incompatible or cadence-invalid IDs
   are reported and never silently substituted or retained as valid.
7. Produce a final review with the exact canonical optional IDs, mandatory non-selectable evidence,
   mode/platform/cadence and digest. Export and non-interactive configuration must round-trip byte-
   stably through AR-1037 validation and yield the same plan/idempotency digest as the TUI draft.
8. When control v1.3 is negotiated, map every exact measurement-selection reason to a stable,
   actionable message. Focus or annotate an optional ID only after confirming it exists in the
   current authenticated catalog. Treat `unknown_id` and global failures as page-level; unsafe or
   contradictory detail is a protocol failure and is never display text.
9. Retain v1.2 fallback by showing only its generic stable category and explicitly stating that the
   runner supplied no per-measure precision; never infer a reason or culprit ID. Under v1.0, disable
   the selector with a closed catalog-unavailable reason. A catalog generation or digest failure
   requires refresh and explicit revalidation without silently changing the draft. A
   measurement-selection validation failure under v1.2 is exact `invalid_format`; the remaining
   v1.2 categories describe only generic settings failures.

## Acceptance criteria

Tests cover empty, one, partial, full and all-group selections; zero-selectable groups; whole-group
and filtered toggles; drill-down changes; search clear/focus/back/resize; mandatory and unsupported
items; maximum-size catalog/query/selection; one-over-limit, non-UTF-8 and malformed publications;
duplicate/unknown IDs; reordered catalogs; stale and changed digests; live/replay, platform and
cadence changes; preset/import rejection; and byte-stable AR-1037 plan round trips. No UI action may
imply that mandatory outcome, integrity, scoring or provenance evidence can be disabled.
Validation fixtures additionally cover every precise v1.3 reason, catalog-owned and global detail,
unknown-ID non-reflection, malicious/oversized IDs, category/reason mismatch, v1.2 category
fallbacks, v1.0 disablement, stale-catalog refresh, focus retention/fallback and privacy-safe
plain/NO_COLOR text. Exact v1.2 and v1.3 validation of the same invalid draft differs only by the
permitted diagnostic precision; both preserve the draft and block launch.
