# AR-1728 — Development cli2key contract and bridge qualification

## Objective

Freeze a precise development-only contract for using a locally authenticated
Codex subscription through an OpenAI Responses-compatible loopback bridge.

## Work

- Distinguish the upstream Codex OAuth credential from the fresh local proxy
  client key generated by ASB.
- Evaluate candidate bridges for pinned source/version/digest, license,
  Responses compatibility, documented credential import/login, loopback bind,
  model discovery, bounded operation, and secret handling.
- Define stable provider identity, provenance labels, failure taxonomy, model
  discovery limits, and the non-comparability prohibition for nested agents.
- Add a credential-free fake and an opt-in live development spike proving
  `/v1/models` plus one bounded `/v1/responses` exchange.

## Boundaries

No official OpenAI Platform key is created or claimed. ASB never scrapes Codex
auth files, writes OAuth material to coordination state, or treats this path as
production/provider qualification. The user must explicitly authorize any
interactive bridge login; CI remains credential-free.
