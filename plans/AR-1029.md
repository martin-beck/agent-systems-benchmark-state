# AR-1029: Remove the legacy in-tree TUI implementation

## Outcome

Make the repository boundary mechanically true: `martin-beck/agent-systems-benchmark` contains no
TUI application, screen, widget, renderer, terminal runtime, or Ratatui/Crossterm integration.

## Dependencies and ownership

Dependencies: AR-1024 and AR-1025. Repository: `martin-beck/agent-systems-benchmark`. Owned paths are
limited to deleting the legacy `crates/asb-tui` package, removing its workspace/dependency/bootstrap
references, and adding boundary checks. No replacement UI may be implemented here.

## Work sequence

1. Inventory all in-tree TUI code, Cargo members, terminal dependencies, docs, tests, build targets,
   feature flags, and command routes against exact ASB and asb-tui revisions.
2. Delete the legacy renderer/application package and remove now-unused Ratatui/Crossterm or terminal
   integration dependencies from ASB manifests and lockfiles.
3. Preserve `asb tui` solely as the trusted lifecycle/launch router delivered by AR-1024.
4. Add repository-boundary tests that fail if renderer crates, terminal application code, or direct
   Ratatui/Crossterm dependencies return to ASB.
5. Run full ASB gates and cross-repository smoke checks; verify standalone asb-tui remains the only
   application and can still install, launch, upgrade, and remove through ASB.

## Acceptance and evidence

ASB builds and tests without its former TUI crate; source and dependency audits find no actual UI
implementation; public lifecycle commands still work with exact standalone revisions; and removal
is covered by immutable review, exact-head CI, and post-merge verification.
