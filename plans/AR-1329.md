# AR-1329: Local-mock run execution with optional live-provider integration

## Outcome

`asb run` and `asb sweep` execute the selected agent path against a deterministic
local sub-1B provider/LLM mock (LiteLLM-compatible where practical) instead of
the digest-pinned `batch-stdio-v1` stub, with credential-free environment
resolution, declared-egress enforcement, and hostile negative tests. The local
mock path is mandatory for development and CI. Production live-provider
integration remains an explicitly gated, runtime-owned optional path; an
external OpenRouter/backend connection is never required for an AR and must not
block completion. Offline modes and synthetic doubles remain default and never
touch the network.

## Dependencies and ownership

Dependencies for the production integration ordering are AR-1327 (OpenRouter
adapter projections and parity), AR-1328 (per-user configuration and
enrollment), and AR-1340 (attested namespace-bound relay handoff). Local mock
qualification may proceed from the completed local runtime/CLI chain and does
not require external provider reachability. Owned paths: the execution path in
`asb-cli` (`execute_inner`, `ExecutionDefinition`), the agent process launcher,
credential resolution from the enrolled environment channel, the final CLI
egress enforcement hook, and the opt-in live-run flag. The runtime namespace
and child handoff are owned by AR-1340; this AR fails closed until that
capability is present. Branch:
`feature/ar-1329-live-provider-run-execution`. Worktree:
`agent-systems-benchmark-ar-1329-live-provider-run-execution`.

## Work sequence

1. Route `execute_inner` through the AR-1327 provider-aware launch projection
   so the constructed execution matches every requested provider, model,
   settings, and credential field.
2. Replace the digest-pinned runtime stub with the deterministic local mock
   agent path, keeping the digest-pinned mode available as the default offline
   fallback; do not make remote reachability part of qualification.
3. For the optional production path, resolve credentials only through the
   enrolled `OPENROUTER_API_KEY` environment channel and prove they never
   appear in argv, environment, logs, manifests, or errors.
4. Enforce the declared egress allowances explicitly; deny any outbound
   provider traffic unless the user passed the explicit live opt-in flag and
   runtime-owned authority has been attested.
5. Add execution tests using the local provider mock: mock opt-in path, offline
   default, missing credential, egress denial, agent failure propagation,
   cancellation, and secret non-disclosure. Remote-provider execution is
   optional supplementary evidence only.

## Acceptance criteria

The local sub-1B/LiteLLM-compatible mock path runs under deterministic tests and
is the mandatory completion/CI path; offline and double modes never contact an
external provider. Any production live path runs only under explicit opt-in with
a matching provider/model projection and runtime-owned attested authority;
credentials flow only through the enrolled environment channel; egress outside
declared allowances is denied; and all existing gates remain green. External
reachability is optional evidence and cannot satisfy or block completion.

## Evidence and completion

Record immutable commits, local-mock live/opt-in observations, offline test
fixtures, egress denial evidence, independent review, exact-head CI, and
post-merge verification. Any remote-provider observation is optional and must
remain outside the completion gate.

## Current development and CI qualification boundary

The mandatory development and CI qualification path for this AR is a deterministic
local provider/LLM mock (LiteLLM-compatible where practical), including hostile
negative tests and offline replay where applicable. External/live OpenRouter or
other provider reachability is optional supplementary evidence only; it is never a
completion, dependency-readiness, or CI gate. Production egress policy, credential
non-disclosure, runtime-owned authority, namespace/relay attestation, cancellation
and teardown, and fail-closed denial of unapproved external traffic remain required
contracts. Existing live-provider dependency edges describe production integration
ordering only and must not be used to block local qualification or to claim external
reachability.
