# AR-1300: Runtime-to-replay cassette dispatch seam

## Outcome

Connect the runtime-issued authenticated operation context to the real ASB strict-replay command.
The command must execute one actual bounded cassette request/response through the supervised
runtime service, with no caller-provided authority, live-provider fallback, or fabricated relay
state.

## Dependencies and ownership

Dependencies: AR-1282 and AR-1285, both completed transport/launch foundations. Blocked AR-1271,
AR-1273, AR-1262 and AR-1286 are evidence and design history only; do not reuse their unmerged
branches. Own only ASB `crates/asb-core`, `crates/asb-runtime`, `crates/asb-replay`, `crates/asb-cli`,
relevant schemas/docs and deterministic credential-free fixtures/tests. No asb-tui or coordinator
implementation changes. Branch: `feature/ar-1300-runtime-cassette-dispatch-seam`; worktree:
`agent-systems-benchmark-ar-1300-runtime-cassette-dispatch-seam`.

## Work sequence

1. Establish a clean isolated worktree from protected main and verify the dependency commits.
2. Define and implement the narrow versioned operation envelope/transport needed by the real CLI
   dispatch, binding generation, route, request, cassette identity, deadline and single-use state.
3. Wire the primary strict-replay command to the runtime-issued context and strict-replay service;
   keep service decoding dependency-neutral and reject malformed, stale, duplicate, credential-
   bearing, provider/fallback and non-loopback operations.
4. Add an executable positive request/response fixture and negative tests proving no live fallback,
   bounded body/deadline handling, authentication failure, stale/replayed operation rejection and
   response parity. Leave lifecycle fault qualification to AR-1301.
5. Run focused and full locked ASB gates, independent exact-head review, signed/DCO publication,
   protected merge and exact-main post-merge verification.

## Acceptance and evidence

Completion requires the real primary command path to issue and consume runtime-owned authority and
receive a strict-replay cassette response in an offline fixture. Unit-only transport tests,
caller-assembled plans, unqualified mocks, or a successful child launch without cassette traffic
do not qualify. Preserve privacy, bounded subprocesses, zero runtime downloads and fail-closed
no-fallback behavior.
