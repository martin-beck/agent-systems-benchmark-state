# AR-1340: Attested live-relay namespace and child handoff

## Outcome

Connect the runtime-owned provider relay to the live agent child through an
attested loopback or private mount handoff. The child must receive only the
exact launch-fenced relay capability; host networking and direct provider
egress remain unavailable. The relay capability is distinct from
`NetworkPolicy::Deny`, so offline and strict-replay launches retain their
existing deny policy while explicit live launches require a separate,
verified capability.

## Dependencies and ownership

Dependencies: AR-1329 (live-provider execution gate and CLI path) and AR-1339
(runtime-owned provider relay/backend). Owned paths are the runtime namespace
and child-launch handoff, relay capability attestation, descendant-egress
tests, and the final `asb run`/`asb sweep --live-provider` integration. Do not
modify asb-tui, enable host networking, or place credentials in argv,
environment snapshots, logs, manifests, or reports.

## Work sequence

1. Define a runtime-issued attestation for the private loopback/Unix relay
   endpoint, binding the launch identity, endpoint, route, adapter digest,
   credential reference, namespace identity, and deadline.
2. Mount or provision that endpoint only inside the approved child namespace;
   reject missing, stale, copied, cross-namespace, or mismatched handoffs
   before provider effects. Keep the live relay capability separate from
   `NetworkPolicy::Deny` and preserve deny as the default for offline/replay.
3. Add descendant-egress tests proving the child and grandchildren cannot
   bypass the relay, reach alternate hosts, use direct sockets, or retain
   relay access after cancellation, expiry, or namespace teardown.
4. Integrate the attested capability into `asb run` and `asb sweep
   --live-provider`, requiring an explicit live opt-in and failing closed when
   the runtime cannot provision the namespace handoff.
5. Record redacted evidence for capability admission, denial, cancellation,
   restart/reconciliation, secret non-disclosure, and offline/replay network
   isolation; run the complete repository gates and exact-head review.

## Acceptance criteria

Only an explicitly opted-in live launch with a runtime-issued, namespace-bound
relay attestation can contact the selected provider. Direct and descendant
egress, alternate endpoints, stale/cross-namespace capabilities, and expired
handoffs are denied. Offline/default and strict-replay launches continue to
use `NetworkPolicy::Deny` and never receive the live capability. Existing
quality, formal, fault, portability, and exact-head gates remain green.
