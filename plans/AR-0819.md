# AR-0819: Add SSH remote discovery and bootstrap

## Outcome

Make existing OpenSSH configuration the default remote-runner transport and guide users through secure, explicit passwordless setup when needed.

## Dependencies and ownership

Dependencies: AR-0803, AR-0804.
Owned paths: SSH host/profile discovery, recent-runner ledger, OpenSSH invocation, stdio control bridge, service probe, key bootstrap UI, and security/fault tests.
Branch: `feature/ssh-remote-bootstrap`. Worktree: `agent-systems-benchmark-ssh-remote-bootstrap`.

## Work sequence

1. Enumerate concrete `Host` aliases from the user's OpenSSH config and included files with bounded parsing; combine them with a mode-0600 ASB ledger of recently successful runner connections, ordered by last successful ASB connection. Do not inspect shell history or pretend `known_hosts` order is recency.
2. Resolve a selected alias using the installed OpenSSH client and its complete configuration semantics (`Include`, `Match`, `HostName`, `User`, `Port`, `IdentityFile`, agent, ProxyJump/ProxyCommand, canonicalization, multiplexing). Display a redacted effective destination and exact config source; never hand-roll connection semantics or pass unsafe shell strings.
3. Connect with normal host-key verification and interactive TTY handling, then invoke a fixed remote `asb remote-proxy --stdio --probe` command that checks the runner's owner-local Unix service. Carry the bounded AR-0803 JSON-RPC messages over stdin/stdout; keep logs on stderr and prevent shell/banner output from corrupting frames.
4. Try configured keys/agent first. If authentication requires a password, offer an explicit passwordless setup flow. If no usable key exists, offer to generate a dedicated Ed25519 key pair locally with `ssh-keygen`, user-selected path, optional passphrase, mode checks, displayed fingerprint, and no private-key copying or logging.
5. Offer a copy-id-like install only after showing target host/user/key fingerprint and receiving confirmation. Prefer a dedicated restricted `authorized_keys` entry (`restrict` and forced `asb remote-proxy --stdio` command where supported), append atomically without replacing existing keys, preserve ownership/modes, verify login/service, and provide revocation instructions. A general unrestricted login key requires a separate explicit expert choice and warning.
6. Keep password/passphrase prompts attached to the controlling terminal or SSH agent; never capture, persist, echo, or transmit them through ASB protocol/logs. Handle cancellation, wrong passwords, locked agents, changed host keys, duplicate keys, read-only homes, remote shell noise, missing/outdated service, ProxyJump failures, and partial installation safely.
7. Disconnecting SSH detaches the frontend only. Reconnection reruns host identity/service/version checks, resumes by durable cursor/run ID, and cannot duplicate launches or stop runner-owned work.

## Acceptance criteria

The default remote selector shows ASB-recent hosts and concrete configured SSH aliases; the most recent successful ASB host is easy to select but not auto-connected without user action; full OpenSSH config behavior is honored; host-key checking is never disabled; a local-only runner service is reachable through the fixed stdio bridge without opening a TCP listener; existing key/agent auth is reused; optional key generation/copy is explicit, fingerprinted, non-destructive, and secret-safe; restricted keys cannot obtain a general shell; and detach/reconnect preserves remote runs.

## Evidence and completion

Use only synthetic disposable keys/hosts under `/srv/data/projects` for tests. Record pinned OpenSSH behavior, config/include/ProxyJump fixtures, PTY prompt tests, host-key and authorized_keys negatives, immutable commits, independent security/UX review, exact-head CI, cross-distribution/architecture sessions, and unsupported SSH implementations.
