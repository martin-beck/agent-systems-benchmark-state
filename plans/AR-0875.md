# AR-0875: Extend control history and analysis protocol

## Outcome

Provide a versioned, machine-checked `asb-control` history and analysis extension that carries the
bounded public evidence AR-0806 needs without exposing sensitive artifacts or coupling the TUI to
CLI internals. Integrate the frozen contract into the production `asb-cli` backend only after the
protocol/schema commit is independently reviewed.

## Contract sequence

1. Freeze a backward-compatible negotiated protocol revision. Older v1 peers must either receive
   their original bounded projection or reject the newer minor version explicitly; fields cannot
   appear with ambiguous defaults.
2. Define bounded history summaries carrying creation/update time, selected agent identities,
   provider source and public profile identity, workload identity/revision, platform identity,
   result-integrity status, durable outcome, and explicit unavailable reasons. Times use one
   documented clock/format and are never inferred from list position.
3. Define analysis summaries that bind the exact input run IDs and revisions, AR-1001 compatibility
   decision, each confounder and exclusion, metric/scoring identities, uncertainty availability,
   result-integrity evidence, and a digest for any sensitive detailed artifact. Incompatible runs
   produce a typed non-comparable result, never a misleading empty or zero comparison.
4. Associate every history/analysis event with exact run, attempt, request, revision, and cursor
   identities where applicable. Reject mixed-run pages, duplicate or regressing revisions, stale or
   future cursors, missing strata, unknown enum values, and terminal outcome contradictions before
   advancing client-visible state.
5. Generate the canonical request, response, and event JSON Schemas from Rust types. Require exact
   `jsonrpc`, method/result matching, closed objects/enum variants, bounded arrays and text, and
   one-of result/error response semantics. Check in positive fixtures and hostile altered fixtures.
6. After independent contract review, acquire the serialized CLI/backend fence. Map durable store
   data to the frozen public projection without reading sensitive artifact bodies, preserve stable
   pagination under concurrent retention, and commit analysis intent/artifact before success.
7. Keep repeat separate from history reads: clone an immutable prior plan into a new draft/run
   identity, revalidate current pins/capabilities, expose drift, and require explicit confirmation.

## Negative, privacy, and compatibility tests

- Reject absent/invalid timestamps, unknown agents/providers/workloads/platforms, malformed public
  digests, oversized collections/text, duplicate identities, inconsistent result-integrity and
  outcome combinations, and success with missing evidence.
- Reject compatible claims when AR-1001 reports model, agent, provider, workload, scoring,
  platform, seed, resource, or collection confounders; retain every typed confounder deterministically.
- Exercise deleted, corrupt, legacy, partial, and concurrently retained history; stale/future
  cursors; cross-page event lifecycle violations; and backend restart during analysis commit.
- Prove request/response method matching, exact error alternatives, unknown-field rejection, stable
  canonical JSON, old-minor decoding, new-minor rejection by old peers, and fixture/schema parity.
- Seed secret-shaped provider values, host paths, environment names, artifact contents, diagnostic
  stderr, and credentials. Assert none appear in summaries, schemas, events, errors, logs, or CLI
  JSON. Sensitive detail remains digest-referenced and requires the separate artifact boundary.
- Prove pagination, analysis cardinality, confounder count, public text, frame, deadline, and storage
  reads are bounded. Cancellation/disconnect cannot fabricate an outcome or cancel runner-owned work.

## Acceptance criteria

- The negotiated protocol and checked-in schemas mechanically carry time, agents, provider source,
  workload, platform, result integrity, durable outcome, compatibility, and complete confounder
  evidence with no unversioned or optional-meaning ambiguity.
- History ordering and cursors are stable and fail closed under deletion, corruption, retention,
  restart, and concurrent updates; no page can mix identities or regress lifecycle state.
- Analysis is emitted only for the exact requested run/revision set. Comparable results cite the
  AR-1001 decision and scoring/metric identities; incompatible or incomplete evidence is explicitly
  non-comparable and cannot be rendered as zero or success.
- Existing protocol v1 fixtures and clients retain their documented behavior. Unsupported minor or
  field combinations fail with typed bounded errors rather than being silently ignored.
- The serialized production CLI backend returns the same canonical projections as protocol fixtures,
  performs no external effect for history reads, and durably orders repeat/analysis mutations.
- No credential, secret-shaped value, raw artifact, private path, host identity, or unbounded
  diagnostic crosses the public control boundary.
- Focused control/CLI/schema tests, backward-compatibility fixtures, full workspace quality,
  privacy/Gitleaks, fuzz/mutation/formal recovery gates, immutable review, exact-head CI, and
  post-merge verification all pass. Shared Cargo/schema/release fences are released afterward.

## Evidence limits

Schema and synthetic backend fixtures do not prove native workload execution, remote transport,
terminal usability, or benchmark comparability. Do not claim those outcomes without their separate
executable and platform evidence. If CLI integration cannot be serialized with an active shared
fence, preserve the reviewed protocol commit and split the backend integration into a blocked child
rather than weakening the contract.
