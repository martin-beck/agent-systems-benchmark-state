# AR-1024: Implement `asb tui` lifecycle routing

## Outcome

Make `asb tui install` a single safe rootless command and provide the complete typed lifecycle
surface without coupling frontend or benchmark process ownership.

## Dependencies and ownership

Dependencies: AR-0820, AR-0821, AR-0822, AR-1022 and AR-1023.
Repository: `martin-beck/agent-systems-benchmark`.
Owned paths: new `asb tui` CLI module/dispatch/help, extension release discovery and bounded
acquisition in `asb-bundle` or a focused crate, extension XDG state, bootstrap integration, schemas,
fixtures, tests and install documentation.
Branch: `feature/asb-tui-lifecycle-router`.
Worktree: `agent-systems-benchmark-asb-tui-lifecycle-router`.

Do not add an ASB source/path dependency to asb-tui, execute unverified bytes, silently install a
TUI from the base bootstrapper, own frontend rendering, or let a frontend own benchmark processes.

## Work sequence

1. Add typed commands: install, launch/default, status, upgrade, doctor and remove, with JSON output
   and stable error codes; add `--version`, `--offline`, `--dry-run` and `--launch` where appropriate.
2. Define a small signed stable-channel index whose authenticated entries point only to immutable,
   versioned manifests and bind release, manifest digest, target and ASB/protocol compatibility.
3. Embed the release trust root, validate the system clock and select exactly one compatible target.
4. Download through HTTPS with redirect/domain policy, byte/aggregate limits, bounded retries,
   verified resume and owner-private staging. Reject ambiguity, expiry, downgrade and substitution.
5. Verify manifest, signature, executable, source, license report, SPDX SBOM and provenance before
   any candidate execution. Store the highest accepted release/digest for rollback protection.
6. Execute the verified candidate from an inode-stable or anonymous descriptor, send the closed
   lifecycle request on stdin and require a bounded schema-valid response/exit code. The candidate
   must reverify before activation.
7. Make status, launch and remove network-free. For launch, authenticate the runner endpoint and
   pass an already-open control descriptor or equally reviewed owner-authenticated channel.
8. Use a rootless XDG extension root separate from ASB releases/config/runs; preserve atomic
   activation, rollback and non-destructive uninstall.
9. Remove the legacy bootstrap assumption that `asb-tui` is bundled under ASB's current release;
   advertise the explicit optional `asb tui install` follow-up instead.

## Acceptance criteria

- One command installs the latest compatible verified release without caller-provided URLs, digests,
  keys or timestamps.
- No byte executes before independent ASB verification; the candidate reverifies before activation.
- Automatic downgrade, mutable URL, redirect escape, wrong target/version and stale index fail closed.
- Interrupted/concurrent installation retains the previous verified active version.
- Status/launch/remove require no network and do not change or signal benchmark run state.
- Base ASB remains independently installable and usable without asb-tui.

## Evidence

Run synthetic signed-channel tests; tamper, expiry, downgrade, redirect, truncation, resume, race,
symlink, low-disk, clock and permission negatives; offline install; repeated install/upgrade/remove;
runner continuity tests; full workspace and quality/formal/fault gates; reproducible fixtures;
privacy review; exact-head CI and exact-main post-merge verification.
