# AR-1024: Implement `asb tui` lifecycle routing

## Outcome

Make `asb tui install` a single safe rootless command and provide the complete typed lifecycle
surface without coupling frontend or benchmark process ownership.

## Dependencies and ownership

Dependencies: AR-0820, AR-0821, AR-0822, AR-1010, AR-1022, AR-1023, AR-1037 and AR-1060.
Repository: `martin-beck/agent-systems-benchmark`.
Owned paths: new `asb tui` CLI module/dispatch/help, extension release discovery and bounded
acquisition in `asb-bundle` or a focused crate, extension XDG state, bootstrap integration, schemas,
fixtures, tests and install documentation.
Branch: `feature/asb-tui-lifecycle-router`.
Worktree: `agent-systems-benchmark-asb-tui-lifecycle-router`.

Do not add an ASB source/path dependency to asb-tui, execute unverified bytes, silently install a
TUI from the base bootstrapper, own frontend rendering, or let a frontend own benchmark processes.

## Work sequence

1. Add typed commands: install, launch/default, status, upgrade, doctor and remove, with JSON output
   and stable error codes; add `--version`, `--offline`, `--dry-run` and `--launch` where appropriate.
2. Define a small signed stable-channel index whose authenticated entries point only to immutable,
   versioned manifests and bind release, manifest digest, target and ASB/protocol compatibility.
3. Embed the release trust root, validate the system clock and select exactly one compatible target.
4. Download through HTTPS with redirect/domain policy, byte/aggregate limits, bounded retries,
   verified resume and owner-private staging. Reject ambiguity, expiry, downgrade and substitution.
5. Verify manifest, signature, executable, source, license report, SPDX SBOM and provenance before
   any candidate execution. Store the highest accepted release/digest for rollback protection.
6. Execute the verified candidate from an inode-stable or anonymous descriptor, send the closed
   lifecycle request on stdin and require a bounded schema-valid response/exit code. The candidate
   must reverify before activation.
7. Make status, launch and remove network-free. Implement only AR-1060's ASB half: discover and
   authenticate the runner endpoint under ASB authority, then provision an already-connected fixed
   descriptor and private reconnect broker without putting endpoint paths in argv, environment or
   public diagnostics. The standalone frontend independently authenticates every received channel.
8. Use a rootless XDG extension root separate from ASB releases/config/runs; preserve atomic
   activation, rollback and non-destructive uninstall.
9. Remove the legacy bootstrap assumption that `asb-tui` is bundled under ASB's current release;
   advertise the explicit optional `asb tui install` follow-up instead.
10. After AR-1037 merges, rebase the clean signed c545c33 checkpoint once onto exact protected ASB
    main. Preserve the reviewed patch through range-diff, deliberately resolve shared protocol/Cargo
    changes, and regenerate Cargo.lock, license/dependency evidence, SPDX SBOM, source manifest and
    provenance from the rebased tree before review or publication.
11. Start delegated commands from `env_clear`. Retain owner-safe XDG/HOME path validation and pass
    only bounded ASCII `TERM`/`COLORTERM` values plus documented fixed presence sentinels for
    `NO_COLOR`, `TMUX`, `STY`, `SSH_CONNECTION` and `SSH_TTY`; never pass their raw
    socket/session/endpoint values or unrelated credential, proxy, provider or shell environment.
12. Arm an RAII child/process-group guard immediately after every candidate, transfer or signature
    verifier spawn. Every later error or panic closes pipes, terminates only identity-checked owned
    processes, joins bounded readers and reaps children; disarm only after confirmed exit and
    validated bounded output.
13. Enforce an explicit foreground no-daemon contract. Reject retained pipes, leader-exit
    descendants, new-session/new-group `setsid` escape and double-fork daemonization. Ownership
    ambiguity or persistent process-observation failure must fail closed without signaling an
    unrelated process or the authoritative benchmark runner.
14. Do not insert or publish a final asb-tui artifact pin until AR-1010 is durably done and the exact
    protected-main asb-tui revision has green Repository quality and Trusted main verification.
    Under explicit build authorization, bind and independently verify its commit, tree, target,
    size and digest; never pin an intermediate, PR-only, local-only or rejected recovery artifact.

## Acceptance criteria

- One command installs the latest compatible verified release without caller-provided URLs, digests,
  keys or timestamps.
- No byte executes before independent ASB verification; the candidate reverifies before activation.
- Automatic downgrade, mutable URL, redirect escape, wrong target/version and stale index fail closed.
- Interrupted/concurrent installation retains the previous verified active version.
- Status/launch/remove require no network and do not change or signal benchmark run state.
- Base ASB remains independently installable and usable without asb-tui.
- Terminal context is compatible across local TTY, SSH, tmux, GNU Screen, plain and NO_COLOR cells
  without disclosing raw session, socket or endpoint values.
- Every post-spawn failure path terminates and reaps only owned processes and leaves no descriptor,
  reader-thread, child or descendant leak; the previous active install remains intact.
- Same-group descendants are bounded and cleaned, while setsid/double-fork/no-daemon escapes and
  unprovable ownership fail closed without touching unrelated or benchmark processes.
- Lockfile, SBOM, source/license manifests and provenance name the exact post-AR-1037 rebased tree;
  the asb-tui pin names only an independently verified trusted-green protected-main artifact.
- ASB contains lifecycle routing, verification and process-control seams only. Ratatui, Crossterm,
  rendering, widgets, screens, application state, navigation, help and terminal event loops remain
  exclusively in `martin-beck/asb-tui`.
- The AR-1060 descriptor handoff is default-CLOEXEC, fixed, bounded and leak-free; ASB owns endpoint
  provisioning/reconnect authority while `asb-tui` owns transport consumption and re-authentication.

## Evidence

Run synthetic signed-channel tests; tamper, expiry, downgrade, redirect, truncation, resume, race,
symlink, low-disk, clock and permission negatives; offline install; repeated install/upgrade/remove;
runner continuity tests; full workspace and quality/formal/fault gates; reproducible fixtures;
privacy review; exact-head CI and exact-main post-merge verification.
Add exact environment allowlist and secret-marker tests; injected failures after each spawn seam;
short/blocked pipe, read, timeout, over-limit, wait, malformed-response and exit-disagreement tests;
and direct, same-group, retained-pipe, leader-exit, setsid, double-fork, PID-reuse, unrelated-child
and transient/persistent process-observation fixtures. Prove bounded completion, zero owned leaks,
unchanged active installation and zero benchmark/unrelated-process signals after every failure.
