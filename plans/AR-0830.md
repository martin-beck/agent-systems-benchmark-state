# AR-0830: Provision hardened development host ASB runner capacity

## Outcome

Create one or more explicitly labeled ASB GitHub Actions runners on development host, next to existing
runners but with separate directories, service identities, leases, caches, logs, and reset policy.

## Dependencies and ownership

Dependencies: AR-0002, AR-0003, AR-0103.
Owned paths: development host ASB runner installation/service configuration, runner labels and leases,
reset/cleanup scripts, sanitized inventory and operational documentation. Existing Relay runner
paths and services are read-only dependencies.
Branch: feature/development-host-runner-capacity. Worktree: agent-systems-benchmark-development-host-runner-capacity.

## Work sequence

1. Inventory architecture, distribution, kernel, CPU/memory/storage/network ceilings, existing
   runner services, ownership, and reachability without exposing hostnames, addresses, credentials,
   tokens, or private logs.
2. Install the pinned runner under a dedicated /srv/data/ci-runners/asb-* root and dedicated
   least-privilege service identity. Use labels that encode only reviewed capability facts
   (for example asb-development-host, architecture, and a versioned capability label).
3. Fence workspaces, caches, artifacts, processes, cgroups, containers, and network policy from
   existing Relay runners. Persist expiring leases and refuse concurrent or stale ownership.
4. Add idempotent setup, health, reset, orphan cleanup, and uninstall paths. Reset must remove
   untrusted checkout/build state while preserving only bounded operator diagnostics.
5. Keep registration tokens, SSH material, package credentials, and private infrastructure
   identity outside both repositories and all public artifacts.

## Acceptance criteria

- A clean development host ASB runner is independently addressable by exact labels and cannot consume a
  Relay job or an unlabeled job.
- The service starts after reboot, runs least-privileged, uses isolated roots and caches, and
  fails closed when its lease, label, architecture, disk, or health contract is invalid.
- Setup and reset are idempotent; interrupted setup, expired lease, process escape, full disk,
  network loss, service crash, and orphaned workspace tests leave no cross-runner residue.
- Existing Relay services remain unchanged and healthy before and after every ASB operation.
- No secret, credential, private path, hostname, address, prompt, response, or raw log enters
  source, public state, job output, or release artifacts.

## Evidence and completion

Record exact runner/tool hashes, service identity and permissions, sanitized platform inventory,
lease transitions, reboot/reconnect, reset/uninstall, isolation negatives, and independent review.
Completion requires exact-tree CI and post-install/post-reset verification.
