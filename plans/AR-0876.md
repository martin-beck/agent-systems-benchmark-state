# AR-0876: Wire provider-aware agent launches

## Outcome

Turn the validated AR-0869 multi-agent provider selection into an authoritative, provider-aware
launch contract. Every executed adapter must receive the exact selected provider/model/API mode and
an explicitly resolved credential descriptor; a conflicting or unbound executable must fail before
durable run creation or process spawn. Stored manifests and terminal artifacts must attest the same
launch identity without exposing credential material.

## Contract and implementation sequence

1. Define a closed `ProviderLaunchV1` input binding selection/catalog/profile digests, exact agent,
   adapter/API mode, provider/model/settings, verified runtime-bundle and executable identities,
   credential resolver kind plus non-secret reference identity, workload/run/attempt identity, and
   bounded runtime/process/artifact policies. Canonically digest the complete launch input.
2. Build the launch only from constructor-controlled AR-0313 selection and AR-0318/0319/0320
   resolver outputs. Pass secrets solely through the approved descriptor/helper boundary; never put
   values in argv, ordinary environment, manifests, artifacts, logs, or errors. Ambient credentials
   and adapter defaults are forbidden.
3. Add an adapter-specific projection for every agent advertised by the AR-0869 catalog. It must
   prove the exact provider route and model/settings were applied or return a typed unsupported
   result. No generic batch executable may claim a provider-aware launch without that projection.
4. Verify the AR-0316/0317 runtime bundle, executable digest and adapter identity immediately before
   spawn. Bind the same launch digest into the durable run manifest before execution and into
   terminal result/artifact metadata afterward; reject any mismatch during report or compare.
5. Route CLI `run` and `sweep --provider-selection` through this contract before result/work-root
   creation. Preserve selection identity across each sweep point; compare/report must expose only
   non-secret digests and treat launch-identity drift as non-comparable.
6. Keep selection-only `provider-plan` side-effect free. Document that AR-0869 manifests alone are
   provenance until this contract qualifies the corresponding executable path.

## Required negative, privacy, and recovery tests

- Supply a valid OpenAI selection with an agent wrapper preconfigured for Ollama, another OpenAI
  model, a different API mode, or a different profile/reference. Each must fail before run creation
  and process spawn, with no fallback to wrapper defaults.
- Tamper each catalog, selection, profile, runtime bundle, executable, adapter, resolver, launch,
  manifest, terminal-artifact, run, attempt, and sweep-point identity independently. Reject stale,
  missing, duplicate, unknown, cross-agent, and mixed-profile inputs atomically.
- Exercise environment, FD and helper resolver success plus missing/reused/closed descriptors,
  helper failure/timeout/oversize output, cancellation before and during resolution, process spawn
  failure, crash after durable intent, and restart reconciliation. Late effects cannot be recorded
  under a different launch identity.
- Seed secret-shaped values in resolver output, inherited environment, argv, wrapper configuration,
  stdout/stderr, artifact metadata and failures. Assert no value or private path reaches public JSON,
  manifests, journals, reports, logs, fixtures, or diagnostics.
- Prove bounded argv/environment/descriptor/artifact metadata and exact cleanup of helper, adapter
  and process trees. Network denial remains enforced for replay and any profile not explicitly live.

## Acceptance criteria

- A successful provider-selected run proves the actual spawned adapter used the exact selected
  provider, model, API mode, settings, runtime bundle, executable and approved credential resolver;
  metadata-only association is impossible.
- Every agent in a multi-agent selection has a qualified adapter projection or the complete launch
  fails atomically as unsupported. One plan cannot silently launch only a compatible subset.
- Run/sweep manifests, terminal artifacts, compare and report bind the same canonical launch digest;
  any conflict or tamper fails closed before execution or comparison.
- A conflicting-provider wrapper negative demonstrates that an executable cannot run while ASB
  records a provider identity it did not apply. No ambient credential or adapter default is usable.
- Focused agent/CLI contract and integration tests, process/cancellation/recovery negatives,
  privacy/Gitleaks, mutation/fuzz/formal checks, full workspace gates, immutable review, exact-head
  CI and post-merge verification pass. All shared Cargo/registration fences are released afterward.

## Evidence limits

Synthetic wrappers prove contract enforcement, not native third-party agent support or provider
service correctness. Each agent/provider/platform combination remains limited to its separately
pinned live or replay evidence. Do not claim that AR-0869 metadata alone configured an executed
agent, and do not claim credential confidentiality beyond the tested resolver/process boundary.
