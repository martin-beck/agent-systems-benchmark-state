# AR-1452: Runtime-owned orchestration service implementation

## Outcome

Implement the reviewed AR-1451 authority boundary as a new Rust
`asb-orchestrator` crate. It becomes the only component that can turn a
validated run request into a local mock, strict replay, or explicitly admitted
live-provider attempt.

## Dependencies and owned paths

Depends on AR-1451 and the completed runtime/control primitives. Own the new
`crates/asb-orchestrator/` crate, workspace wiring, protocol fixtures, and
focused integration tests. Do not modify asb-tui. Shared schema changes are
coordinator-owned integration points.

## Required implementation

1. Add closed request, plan, handle, event, outcome, and error types with
   canonical digests and strict unknown-field rejection.
2. Implement a service-owned admission and attempt state machine with bounded
   idempotency, causal attempt fencing, journal intent/outcome ordering, and
   crash recovery.
3. Internally acquire the resource lease, sandbox/backend, runtime-observed
   namespace, relay, launch token, credential handle, and mode-specific
   authority. No public constructor may accept those authority objects.
4. Provide deterministic local-mock and strict-replay backends first. Keep
   live-provider acquisition fail-closed until every attestation is present;
   use loopback/mock services for tests, never a real provider in CI.
5. Transfer process/relay/lease ownership into an attempt session and guarantee
   cancellation, timeout, child-tree teardown, credential non-disclosure, and
   direct/alternate-egress denial.
6. Support backend selection for native, container, and VM runners through a
   bounded capability contract; no specific native host is mandatory.

## Acceptance and evidence

- Positive and hostile unit/property tests cover every transition and each
  authority input, including stale/copy/mismatch/replay, cancellation races,
  crash recovery, and secret/privacy checks.
- Local mock end-to-end run and sweep execute through the new service with
  recorded bounded manifests/events and no external network.
- Focused workspace gates, full gates, exact-head CI, independent review, and
  post-merge verification all pass.
