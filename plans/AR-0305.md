# AR-0305: Implement Gemini CLI client adapter

## Outcome

Run a pinned Apache-2.0 Gemini CLI release through its noninteractive structured interface.

## Dependencies and ownership

Dependencies: AR-0101, AR-0102, AR-0103.
Owned paths: asb-agents Gemini module and its fixtures.
Branch: feature/agent-gemini. Worktree: agent-systems-benchmark-agent-gemini.
One worker owns this task; shared workspace/schema edits require coordinator integration.

## Work sequence

1. Inspect the exact official google-gemini/gemini-cli source, license, stable npm artifact, JSON and stream-JSON dialect, provider/base-URL controls, tool policy and current service-transition limits.
2. Pin source and package integrity, isolate all config/state, and implement the smallest bounded adapter without relying on consumer OAuth or undocumented behavior.
3. Exercise a credential-free loopback provider with real editing/tool/cancellation fixtures on each available native architecture; label unavailable package/platform combinations.
4. Run focused and full gates, publish a focused PR, reconcile exact-head CI and record limitations.

## Acceptance criteria

A real pinned CLI completes the common offline engineering fixture with structured lifecycle, tool, usage and terminal evidence; endpoint override, prompt isolation, ambient-config rejection, cancellation and child cleanup are verified. JSON/event sizes and action/turn budgets are bounded. Consumer-account routes, changing hosted service tiers and untested architectures are not claimed.

## Evidence and completion

Record exact source/tag/tree, license and package integrity, commands by digest, immutable commit, CI identifiers, native outcomes and unsupported combinations. No credentials, raw prompts, transcripts or private paths. Finish only after independent immutable-head review, exact-head checks, integration and post-merge verification.
