# AR-1102: Add the UserConfigV1 configuration contract

## Outcome

A versioned, non-secret user configuration contract that carries one default provider/model pair
and one optional override per agent, validates strictly, computes a canonical `config_sha256`, and
never transports a secret value (only redacted reference digests).

## Dependencies and ownership

Dependencies: AR-0310 and AR-1100. Repository: `martin-beck/agent-systems-benchmark` only. Owned
paths are the new `crates/asb-protocol/src/user_config.rs`, its re-export in
`crates/asb-protocol/src/lib.rs` and its tests. The contract intentionally depends only on
`asb-protocol` primitives (`CredentialSource`); agent identities are bounded strings validated by
the CLI layer against `AGENT_IDS`, keeping the protocol crate free of a dependency on `asb-agents`.
No network, credential value, provider or user interaction is required; all tests are in-memory.
Branch: `feature/user-config`. Worktree: `agent-systems-benchmark-user-config`.

## Work sequence

1. Define `UserConfigV1` with `schema_version` (const 1), a `defaults` table
   (`provider`, `model`, `credential_source`, optional `credential_reference_sha256`) and an
   `agents` map of bounded agent-id strings to one `AgentOverride` (`provider`, `model`,
   optional `credential_reference_sha256`). A single override per agent is the whole override
   scope: no per-setting override fields.
2. Implement strict validation: unknown fields rejected (`deny_unknown_fields`), bounded text
   (model/provider ≤ 1024 bytes, agent ids ≤ 128 bytes), digest fields must be lowercase SHA-256,
   a `credential_reference_sha256` requires `credential_source` not `none`, and an override
   omitting a field inherits the default rather than leaving a hole.
3. Compute a canonical `config_sha256` over all fields in deterministic order (sorted agent ids),
   following the existing `ProfileHash` domain-separation style in provider.rs but with its own
   domain prefix so config and profile identities never collide.
4. Provide serde (JSON) round-trip plus a `schemars::JsonSchema` contract; the TOML reader/writer
   lives in the CLI layer (asb-cli already depends on the toml crate) and is covered by AR-1103.
5. Test malformed, unknown-field, oversized, digest-shaped and inconsistent inputs fail closed;
   prove `config_sha256` is stable, order-independent for the agents map, and that an override
   without a field inherits the default resolution.

## Acceptance criteria

A config value either validates completely or is rejected without partial state; the digest is
canonical and stable; no secret value can be represented anywhere in the contract. The generated
JSON schema requires the defaults table and agents map.

## Evidence

Record schema fixtures, digest stability tests, fail-closed malformed-input tests, generated
schema output, privacy scan and exact-head CI.
