# AR-0895: Verify every coordination-content pull request

## Outcome

Close the observed GitHub Actions path-filter gap so any pull request changing authoritative task/plan content or its generated CURRENT/STATUS projections automatically runs strict Coordination verification and DCO against the exact pull-request head.

## Dependencies and ownership

Depends on AR-0002 and AR-0003. Own `.github/workflows/verify.yml`, a narrowly scoped workflow-trigger regression test or checker, and documentation of the enforced coordination-content paths. Do not change task schema semantics, coordinator vendor code, unrelated workflows, or existing task content. Branch `ci/verify-coordination-content`; worktree `agent-systems-benchmark-state-verify-coordination-content`.

## Work sequence

1. Record the reproducer: PR 16 changed `tasks/**`, `plans/**`, `CURRENT.md`, and `STATUS.md` but did not automatically create the Coordination verification run; a manual exact-head dispatch was required.
2. Extend pull-request path selection to cover at least `tasks/**`, `plans/**`, `CURRENT.md`, and `STATUS.md`. Evaluate whether other authoritative/generated coordination paths require the same closed set and document the decision.
3. Preserve the existing exact-head checkout and DCO revision range. Ensure pull-request DCO is never skipped for an in-scope coordination-content change while workflow-dispatch behavior remains explicitly non-PR.
4. Add a regression that evaluates workflow triggers for one representative change under every required path plus mixed/unrelated paths. Test deleted/renamed files, generated-only diffs, and workflow syntax.
5. Prove schema validation, `render-status --check`, clean-tree enforcement, vendor/header/lint/type/complexity, coverage and DCO run on the actual pull-request head. A skipped, cancelled, base-only, stale-head, or no-op job cannot satisfy the required check.
6. Keep permissions read-only, actions pinned, fork-safe, credential-free, bounded, and concurrency-correct. Update branch protection/check documentation separately if a stable required-check name changes.

## Acceptance criteria

Each required path automatically triggers Coordination verification on a pull request; DCO evaluates every commit in exact base-to-head range; generated CURRENT/STATUS drift fails; workflow-dispatch cannot be cited as PR DCO evidence; trigger regression tests fail when any required path is removed; unrelated documentation can retain its reviewed policy; and no secret or write permission is introduced.

## Evidence and completion

Record the failing-before and passing-after trigger matrix, exact workflow/run/head IDs, DCO positive and hostile unsigned/missing-trailer cases, generated-view drift failure, actionlint/security review, full state gates, immutable review, exact-head CI and post-merge main verification.
