# AR-1022: Harden the asb-tui release lifecycle contract

## Outcome

Make the standalone delegated lifecycle safe for the first verified public release while preserving
the source-only channel's fail-closed behavior.

## Dependencies and ownership

Dependencies: AR-1017, AR-1018, AR-1019, AR-1020 and AR-1021.
Repository: `martin-beck/asb-tui`.
Owned paths: lifecycle request/response schemas, `src/delegated.rs`, `src/lifecycle.rs`, release
classification/trust metadata, focused fixtures/tests and matching lifecycle documentation.
Branch: `feature/asb-tui-release-contract-hardening`.
Worktree: `agent-systems-benchmark-asb-tui-release-contract-hardening`.

Do not add rendering, ASB CLI routing, release artifacts or a Git/path dependency on the ASB source
tree. Preserve the existing authenticated bundle verifier and content-addressed lifecycle unless a
test demonstrates a concrete repair is required.

## Work sequence

1. Decide and document whether the unreleased lifecycle schema can be corrected as v1 or needs a
   clean v2; provide explicit rejection behavior for the superseded shape.
2. Remove caller-selected `allowed_signers` from the production request. Embed the exact permitted
   signer identity in the release binary and make key rotation a separately versioned policy.
3. Remove caller-selected `now_unix` from production. Read a bounded system clock internally;
   retain injected time only behind library test seams.
4. Represent `source_only_unverified` and `verified_extension` honestly. Never return verified or
   activate an installation unless the authenticated manifest identifies a promoted release.
5. Bind ASB version/protocol range, target, release, source commit/tree and executable digest across
   the request, manifest, installed state, self-test and status response.
6. Re-audit path/inode/symlink handling, lifecycle locking, concurrent requests, interrupted stage,
   downgrade, expiry, clock skew, appended-key and signer-substitution cases.
7. Regenerate schemas and fixtures, update release-channel validation and document the exact stable
   JSON/exit-code contract that the ASB router may consume.

## Acceptance criteria

- No production field lets a caller choose the signer or verification time.
- Only the embedded allowed signer and correct SSH namespace authenticate a release.
- Unverified/source fixtures cannot be installed, activated or reported as verified.
- Verified state is bound to exact immutable release and executable identities.
- Unsupported lifecycle versions fail before filesystem mutation.
- Install, status, upgrade, launch and remove preserve atomicity and benchmark-process isolation.
- Existing tamper, cache, retry, interruption and permissions guarantees remain covered.

## Evidence

Run focused hostile lifecycle tests, full locked tests/doctests, rustfmt, Clippy with warnings denied,
rustdoc, release build, schema/publication checks, coverage, dependency/license/audit checks,
workflow analyzers, Gitleaks, ASB isolation, clean-tree verification, independent exact-diff review,
protected exact-head CI and exact-main post-merge CI. Record any intentionally incompatible
pre-release schema change and its migration/rejection behavior.
