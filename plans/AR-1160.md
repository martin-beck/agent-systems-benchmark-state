# AR-1160: Expose configuration and recording through control API

## Outcome

Add negotiated catalogs and idempotent configuration, provider and recording operations for independent frontends.

## Dependencies and ownership

Dependencies: AR-1060 and AR-1151; AR-0844 is an integration input and AR-1100 through AR-1120 are transitive. Repository: `martin-beck/agent-systems-benchmark`. Owned paths: control schemas/capabilities, safe catalogs, configuration drafts/mutations, campaign operations, events and tests.
Branch: `feature/ar-1160`. Worktree: `agent-systems-benchmark-ar-1160`.

## Work sequence

1. Publish bounded agent, provider, auth-status, model, workload, recording and effective-configuration catalogs with disabled reasons.
2. Validate drafts without effects, then apply global/selected-agent/provider mutations with revision and idempotency fencing.
3. Expose campaign estimate, acknowledgement, launch, progress, cancel, coverage and offline-default operations.
4. Keep credential enrollment values outside the ordinary public control protocol and captured content outside every response.
5. Test old/future/malformed versions, stale revisions, retries, disconnect/reconnect, recovery, oversized frames and privacy.

## Acceptance criteria

An independent frontend can perform the complete wizard from runner truth without owning configuration or credentials, and retries cannot duplicate configuration or paid recording effects.

## Evidence and completion

Record bounded public fixtures, exact schema and repository identities, focused/full gates, privacy scans, independent immutable-head review, exact-head CI and post-merge verification. Never publish credentials, prompts, responses, private paths, host identities or raw logs.
